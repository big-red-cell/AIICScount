# Issue 375594906__cc64ce1591

**Bucket:** REPRODUCED

## Summary
On `mrnoob790.github.io/os`, holding Enter triggers the page's keydown handler, which clicks a hidden `webkitdirectory` file input; after the user picks a directory, the page writes `files[0].webkitRelativePath` into the visible `#qmsg` element. When the selected directory tree contains a folder named after the OS user (e.g., selecting the parent of the user home), the displayed path string includes the OS username. This observable effect was triggered and verified via CDP DOM readback.

## Environment
- OS/runtime: Windows 10.0.26200 (x64), PowerShell, Node v24.13.1 (OpenClaw gateway runtime)
- Browser: `C:\Program Files\Google\Chrome\Application\chrome.exe`, Chrome/151.0.7922.174 (launched `--headless=new` with an isolated profile)
- Automation path: CDP over WebSocket (remote debugging port 9222) driven by a Node script — no OpenClaw browser tool is available in this session, so the skill's verified local CDP fallback was used
- Required environment (per issue): desktop browser with a directory file picker; a local directory tree whose path contains the OS username
- Attachments used: none (issue text contains no attachments)

2. Retrieved the target site source to confirm the upload logic before driving it.
   - cmd: `Invoke-WebRequest -Uri "https://mrnoob790.github.io/os" -UseBasicParsing`

3. Crafted the upload directory tree: root `sandbox/home` containing a subfolder named after the real OS username (`znnnnnh2`), mirroring a `C:\Users\<user>` layout, with two payload files.
   - cmd: `Set-Content` for `sandbox/home/znnnnnh2/Desktop/secret.txt` and `sandbox/home/znnnnnh2/Documents/note.txt`
   - verify: `Get-ChildItem -Recurse` shows both files present; `$env:USERNAME` = `znnnnnh2` (the real OS username used as the folder name).
4. Navigated the isolated browser to the site via CDP `Page.navigate`.
   - cmd: `Page.navigate {url: "https://mrnoob790.github.io/os"}` then `Runtime.evaluate "location.href"`
   - verify: active tab URL readback = `https://mrnoob790.github.io/os`; `document.getElementById('thing')` exists and carries the `webkitdirectory` attribute (DOM `#thing` nodeId resolved = 12).
5. Reproduced the "hold Enter" trigger: patched `HTMLInputElement.prototype.click` to record calls, then dispatched 5 Enter `rawKeyDown`/`keyUp` pairs via CDP `Input.dispatchKeyEvent`.
   - cmd: `Input.dispatchKeyEvent` x5 (Enter, vk 13); then `Runtime.evaluate "window.__clicked"` and `Runtime.evaluate "document.onkeydown === null"`
   - verify: `window.__clicked === true` and `document.onkeydown === null` — the page's handler fired `thing.click()` after 5 keydowns and disabled itself, exactly as its script specifies.
6. Selected a directory on the `webkitdirectory` input via CDP `DOM.setFileInputFiles`, passing the crafted root `sandbox/home` (equivalent to the user picking that folder in the dialog).
   - cmd: `DOM.querySelector "#thing"` → `DOM.setFileInputFiles {files: ["…\sandbox\home"]}`
   - verify: call returned `{}` (no error); `thing.files.length === 2`; `files[0].name === "note.txt"` — directory enumeration and the `change` event both occurred.
7. Read back the page's displayed text (the claimed observable).
   - cmd: `Runtime.evaluate "document.getElementById('qmsg').innerHTML"` and `…files[0].webkitRelativePath`
   - verify: `#qmsg.innerHTML` = `home/znnnnnh2/Documents/note.txt`; `files[0].webkitRelativePath` = `home/znnnnnh2/Documents/note.txt`; username-present check `includes('znnnnnh2')` = `true`. The page visibly disclosed the OS username as a path component.
