he...@googlemail.com： <p><strong>VULNERABILITY DETAILS</strong></p> <p>Chrome Browsers does have integrated an automatic update check for a few weeks now. A neccessary security feature for nudging the user to install the lastest security updates, with the goal of global security: prevention of exploitation of security vulnerabilites of any kind.</p> <p>Unfortunately, that update check is performed too late.</p> <p><strong>Why?</strong></p> <p>Think of the following - a totally normal usecase:</p> <p>You have opened a bunch of websites in your tabs, in which a ton of ads and trackers are implemented. Normal behaviour. After some time you are switching to another programme/app or ending Chrome Browser. Later, probably after a few days, you are opening Chrome Browser again, the latest viewed website is reloaded, and the Chrome update check performed. You see the sign, that an update would be available.</p> <p>That sounds quite harmless and like working as intended - but it isn&#39;t from my point of view.</p> <p>The problem here is, that the latest website is <strong>reloaded and executed automatically</strong> after the app launch, which means, one out of the ton of ad servers and trackers may exploit an in-the-wild vulnerability in the meantime. Although the exploited gap has already been plugged, about which the update check wants to inform.</p> <p>It is public knowledge that evildoers start exploiting fixed vulnerabilities as soon and latest as they are made public, e.g. shortly after the Chrome team was publishing new fixes within the release informations (<a href="https://chromereleases.googleblog.com/" data-b-widget="url" data-b-original-href="https://chromereleases.googleblog.com/" data-b-redirected-href="https://www.google.com/url?q=https://chromereleases.googleblog.com/&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0MUx0V2xVtVYC3YE8WmWvO">https://chromereleases.googleblog.com/</a>).</p> <p>Most ads and tracking services are maintained by different parties, means, nobody knows, how fast and secure they are; as they are assumably all using Javascript, exploits could be spread to millions of users worldwide in an eye wink, whilst the update itself is not yet installed.</p> <p><strong>Expectation</strong></p> <p>The update check itself is well done, thank you, but the automatic loading of the latest website should be postponed to somewhere after the user has made a well founded decision if he wants to skip the available update or not, despite the possible security implications.</p> <pre><code>   &gt; Start Chrome &gt; just and only update check (no reloading of the latest website) &gt;     Update available: Messagebox install yes/no?    ==&gt; yes: Google Play/install, only if updated then start browsing;    ==&gt; no: reload/start browsing.  </code></pre> <p>Goal is, that evildoers cannot use the common time gap between published vulnerabilties and installation of the fix.</p> <p><strong>VERSION</strong></p> <p>Chrome Version: 122.0.6181.0 dev, assumably Windows, i(Pad)OS &amp; co. as well</p> <p>Operating System: Android 13, patchlevel 01.01.2024</p>

el...@chromium.org： <p>Security triage: this one is WontFix from us.</p> <p>Updates are not applied or downloaded in the manner you suggest; the update checks happen asynchronously and periodically while Chrome is running and not as part of the startup flow. We can&#39;t block startup on waiting for an update check like this. Even if we could, it&#39;s not clear how a user could make an informed decision when presented with the bubble you propose - how would a user know whether it&#39;s safe to continue or not? Under what circumstances would they hypothetically be able to make an informed decision either way?</p>
