bu...@google.com： <hr> <h3>Report description</h3> <p>Chrome&#39;s TouchID-protected password autofill on MacOS fills password in wrong input field if cursor is moved post-auth prompt. Risks data exposure.</p> <hr> <h3>Bug location</h3> <h4>Which product or website have you found a vulnerability in?</h4> <p>Google Chrome</p> <hr> <h3>The problem</h3> <h4>Please describe the technical details of the vulnerability</h4> <p>I have discovered a bug in Google Chrome related to the password autofill feature protected by TouchID. When the TouchID prompt appears for password autofill verification, switching the cursor to a different input field before authenticating causes Chrome to autofill the password in the newly focused input field instead of the original password field. This behavior deviates from the expected functionality, where the password should only be auto-filled in the designated password field, regardless of the cursor position post-TouchID prompt.</p> <p>Steps to Reproduce: Enable password autofill protected by TouchID in Google Chrome on MacOS. Navigate to a website with a login form that includes a password field and at least one other input field (e.g., a &quot;Verify Password&quot; field). Enter your username and focus on the password field to trigger the password autofill suggestion. When the TouchID prompt appears for autofill verification, do not authenticate immediately. Instead, move the cursor to another input field on the form. Authenticate via TouchID without moving the cursor back to the password field. Observe the password being autofilled in the new input field where the cursor is present, instead of the intended password field. Expected Behavior: The password should only be autofilled in the designated password field, irrespective of cursor movement or focus change after the TouchID prompt is displayed.</p> <p>Actual Behavior: The password is autofilled in whichever input field the cursor is focused on after TouchID authentication, even if it is not the intended password field.</p> <h4>Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4> <p>This bug could have several security implications:</p> <p>Accidental Exposure: Users might accidentally expose their passwords in fields visible to others nearby or through screen sharing. Data Leakage: In web forms where multiple input fields are present (e.g., registration forms), users might inadvertently save their passwords in plaintext in unintended fields, which could be submitted and stored, leading to potential data leakage. Misuse in Malicious Web Pages: An adversary could craft a webpage that tricks users into autofilling their password into a visible text field after authenticating via TouchID, potentially exposing the password to the attacker or through network traffic if the form is submitted.</p> <hr> <h3>The cause</h3> <h4>What version of Chrome have you found the security issue in?</h4> <p>123.0.6312.59 (Official Build) (arm64)</p> <h4>Is the security issue related to a crash?</h4> <p>No</p> <h4>Choose the type of vulnerability</h4> <p>Sensitive data exposure</p> <h4>How would you like to be publicly acknowledged for your report?</h4> <p>Please acknowledge my contribution as Swapnil Mukherjee, a Computer Science graduate student at Clemson University. I appreciate the opportunity to contribute and would like this acknowledgment to reflect my personal commitment to enhancing cybersecurity.</p>
