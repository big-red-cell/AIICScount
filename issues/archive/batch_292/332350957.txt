wt...@google.com： In Chrome. the libyuv functions I444ToI420() and I422ToI420() are unlikely to receive a null src_v pointer in conjunction with legal src_y and src_u pointers. That can only happen if the calling code makes a mistake when setting up the src_y, src_u, and src_v pointers for the I444ToI420() and I422ToI420() functions. Given the symmetric nature of src_u and src_v, it seems unlikely to mess up one of them but not the other.<br><br>A more likely scenario is to change<br><br>    When src_y and src_u are legal pointers but src_v is a null pointer, ...<br><br>to<br><br>    When src_y is a legal pointer but src_u and src_v are null pointers, ...<br><br>This can happen if the calling code makes a mistake when setting up the src_y, src_u, and src_v pointers for the I444ToI420() and I422ToI420() functions (messing up both src_u and src_v), or if the calling code incorrectly passes a monochrome (grayscale) image to the I444ToI420() and I422ToI420() functions. This also seems unlikely.
