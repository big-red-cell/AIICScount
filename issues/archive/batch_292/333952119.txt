ja...@gmail.com： VULNERABILITY DETAILS<br>Since the transition from Manifest V2 (MV2) to Manifest V3 (MV3) of Chrome Extension, there is a strict control in the response header that the Chrome Extension does not allow to remove the response header. When the response header sets the X-Frame-Options to DENY, or SAMEORIGIN, the Chrome Extension cannot remove this option to perform the iframe injection. However, due to the legacy issue, the Chrome Extension can set the ALLOW-FROM origin and render the page. With this directive, chrome browsers encountering response headers will ignore the header completely. Therefore, the DENY or SAMEORIGIN setting of X-Frame-Options will be ignored, and the Chrome Extension can perform the frame injection. If the malicious Chrome Extension could leverage this vulnerability to set the iFrame to perform a malicious action, such as the clickjacking attack. This is the legacy issue that allows the Chrome Extension in MV3 to still could be able to manipulate the HTTP response header.<br><br>VERSION<br>Chrome Version: 123.0.6312.122 (Official Build) (64-bit) (cohort: M123 Rollout) <br>Operating System: Windows 10 Version 22H2 (Build 19045.4291)<br><br>REPRODUCTION CASE<br>demo_iframe.pptx<br><br><br>CREDIT INFORMATION<br>Externally reported security bugs may appear in Chrome release notes.
