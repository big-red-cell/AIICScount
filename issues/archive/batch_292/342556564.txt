ed...@gmail.com： <p>I have done some additional research regarding this issue. The &quot;data&quot; URL scheme, defined in <a href="https://tools.ietf.org/html/rfc2397" data-b-widget="url" data-b-original-href="https://tools.ietf.org/html/rfc2397" data-b-redirected-href="https://www.google.com/url?q=https://tools.ietf.org/html/rfc2397&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw24hON_hUXLHCCIJcZgugd9">RFC 2397</a>, is intended to embed small data items directly within the URL. Placing a URL between semicolons after a valid MIME type but before the base64 declaration in a data URI creates a misleading representation in the browser&#39;s address bar, obscuring the true nature of the content and violating the intended use of data URLs.</p> <p><strong>Relevant RFC Citations:</strong></p> <ol> <li> <p>RFC 2397 - The &quot;data&quot; URL scheme: Section 1: The scheme provides a way to include small data items as &quot;immediate&quot; data.</p> </li> <li> <p>RFC 3986 - Uniform Resource Identifier (URI): Generic Syntax: Section 1.1: URIs should clearly classify as locators, names, or both. Section 3.1: The scheme component dictates the interpretation of the remaining components.</p> </li> </ol> <p>Specification Suggestion:</p> <p>The data URI should be crafted as follows, without including misleading URLs between the MIME type and base64 declaration:</p> <pre><code>data:[&lt;media type&gt;][;base64],&lt;data&gt; </code></pre> <p>For example, a correctly crafted data URI should look like this:</p> <pre><code>data:text/html;base64,PGh0bWw+PGhlYWQ+PHRpdGxlPkxlZ2l0PC90aXRsZT48L2hlYWQ+PGJvZHk+PGI+Tm90IExlZ2l0PC9iPjwvYm9keT48L2h0bWw+ </code></pre> <p>When entering the following data URI in a browser&#39;s address bar, the browser displays a misleading representation:</p> <pre><code>data:text/html;https://www.irs.gov;base64,PGh0bWw+PGhlYWQ+PHRpdGxlPkxlZ2l0PC90aXRsZT48L2hlYWQ+PGJvZHk+PGI+Tm90IExlZ2l0PC9iPjwvYm9keT48L2h0bWw+ </code></pre>
