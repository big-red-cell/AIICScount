This aligns with XSSI, where the inclusion and execution context is distinct from the main application&#39;s origin.</li> </ul> </li> </ol> <p>3.Note on Data URIs: Data URIs are typically not clickable or directly accessible by users. However, in this PoC, the data URI is forcefully inserted into the omnibar via an intent from a malicious app. This bypasses typical user interaction requirements, making the exploit seamless and more dangerous.</p> <p>Conclusion:</p> <p>While the data URI&#39;s unique origin context and execution model differ slightly from traditional XSSI, the principles of script inclusion, execution in a distinct origin context, and leveraging user trust align closely with XSSI attacks. Therefore, this vulnerability can be reasonably classified under XSSI, highlighting the need to restrict data URI execution and validate script sources to protect users from such exploits.</p>
