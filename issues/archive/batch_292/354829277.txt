an...@chromium.org： <p>If I understand correctly, two issues are being pointed out here.</p> <hr> <p>(A) (From <a href="https://issues.chromium.org/issues/354829277#comment10" data-b-widget="issue-reference" data-b-issue-id="354829277" data-b-comment-number="10">comment#10</a> and before). An <code>&lt;embed&gt;</code> element of type <code>application/pdf</code> displays a placeholder with an Open button on Android, while on desktop the embeds displays the &quot;blocked by CSP&quot; placeholder.</p> <p>I guess this might be a bit unexpected, however I would say that there is no security issue here. Downloads and navigations are not protected by CSP, so it is already possible to include a link to a PDF document without having it blocked by CSP. The CSP directive <code>child-src</code> is meant to restrict embedding of child frames, and there is no child frame being embedded on Android here (since the Open button just opens a PDF viewer). As such, I would say there is no issue here. I guess we could discuss whether it would be more consistent with the behavior on desktop to just display a &quot;blocked by CSP&quot; placeholder though.</p> <hr> <p>(B) (From <a href="https://issues.chromium.org/issues/354829277#comment11" data-b-widget="issue-reference" data-b-issue-id="354829277" data-b-comment-number="11">comment#11</a> and <a href="https://issues.chromium.org/issues/354829277#comment12" data-b-widget="issue-reference" data-b-issue-id="354829277" data-b-comment-number="12">comment#12</a>). An <code>&lt;embed&gt;</code> element embedding an img is not blocked by <code>child-src</code>.</p> <p><code>&lt;embed&gt;</code> is a bit of a strange html element, since it can both result in a frame or in other content being embedded. In fact, there have been attempts to remove it from the HTML spec. Anyway, wrt CSP, <code>object-src</code> should govern the <code>&lt;embed&gt;</code> element, and specifying <code>object-src &#39;none&#39;</code> does block embedding the image. For being consistent and safe, however, when <code>&lt;embed&gt;</code> results in framing a child frame, we respect CSP <code>frame-src</code>.</p> <hr> <p>I think there is no security vulnerability in both cases, and probably no bug at all, so I would just close this as WAI.</p>
