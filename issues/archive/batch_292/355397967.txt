ma...@chromium.org： <p>[security shepherd]</p> <p>My understanding of this report is that an <code>&lt;iframe sandbox=&quot;allow-popups&quot;&gt;</code> should not be able to open a window that runs scripts. <code>sandbox=&quot;allow-popups-to-escape-sandbox&quot;</code> should be necessary to permit that. In this case, the iframe contains a link to an <code>intent://</code> URL. Clicking that link results in a new tab being created that is able to run scripts, despite it being &quot;created&quot; from a sandboxed iframe. The iframe content isn&#39;t explicitly requesting a new window. Presumably that&#39;s a result of how Chrome handles the intent URL.</p> <p>Assigning to arthursonzogni@ based on their prior involvement with iframe sandboxing issues. Please feel free to reassign if there&#39;s someone more appropriate to handle the issue.</p>

ar...@chromium.org： <p>Hello 👋</p> <p>See the <a href="https://html.spec.whatwg.org/#attr-iframe-sandbox-allow-top-navigation-to-custom-protocols" data-b-widget="url" data-b-original-href="https://html.spec.whatwg.org/#attr-iframe-sandbox-allow-top-navigation-to-custom-protocols" data-b-redirected-href="https://www.google.com/url?q=https://html.spec.whatwg.org/%23attr-iframe-sandbox-allow-top-navigation-to-custom-protocols&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1gn6K5-HLDBWM7eXPa6jCz">HTML specification</a> about navigating to external applications:</p> <blockquote> <p>The sandboxed custom protocols navigation browsing context flag, unless tokens contains either the allow-top-navigation-to-custom-protocols keyword, the allow-popups keyword, or the allow-top-navigation keyword.</p> </blockquote> <p>In your example, the iframe.sandbox contains <code>&quot;allow-popups</code>, so we don&#39;t have <code>&quot;sandboxed custom protocols navigation&quot;</code>. So this is <strong>working as intended</strong>.</p> <p>This is the result of the <a href="https://chromestatus.com/feature/5680742077038592" data-b-widget="url" data-b-original-href="https://chromestatus.com/feature/5680742077038592" data-b-redirected-href="https://www.google.com/url?q=https://chromestatus.com/feature/5680742077038592&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3IhUBeRuL2tdhM83tXUpGJ">latest spec change</a>, by <a href="mailto:arthursonzogni@chromium.org" data-b-widget="url" data-b-original-href="mailto:arthursonzogni@chromium.org" data-b-redirected-href="mailto:arthursonzogni@chromium.org">arthursonzogni@chromium.org</a>. Previously external application were not blocked no matter the sandbox.</p> <p>If you want to suggest change to the specification, you can contribute on <a href="https://github.com/whatwg/html" data-b-widget="url" data-b-original-href="https://github.com/whatwg/html" data-b-redirected-href="https://www.google.com/url?q=https://github.com/whatwg/html&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0mh8JLNgNqFSL6DvH_5MYP">https://github.com/whatwg/html</a>.</p>
