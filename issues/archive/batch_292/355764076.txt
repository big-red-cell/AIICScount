ti...@chromium.org： <p>[Security shepherd] This is not a vulnerability in Chrome.</p> <p><code>upgrade-insecure-requests</code> does not apply here for two big reasons:</p> <ol> <li>top-level navigations to third-party origins are explicitly out of scope for now [1]: <blockquote> <p>Performing upgrades for top-level navigations to third-party resources brings a significantly higher potential for breakage, so we’re avoiding it for the moment.</p> </blockquote> </li> <li>it would never upgrade requests to <code>http://localhost</code> and <code>http://127.0.0.1</code> <ul> <li>potentially-trustworthy URLs are (or will be, see #1 above) excluded [1]: <blockquote> <p>If request is a navigation request, append a header named Upgrade-Insecure-Requests with a value of 1 to request’s header list if any of the following criteria are met:</p> <ul> <li>request’s URL is not a potentially trustworthy URL</li> </ul> </blockquote> </li> <li>and any URL on localhost is considered potentially-trustworthy [2] [3]</li> </ul> </li> </ol> <p>This is working as intended</p> <p>[1] <a href="https://w3c.github.io/webappsec-upgrade-insecure-requests/#upgrade-request"
