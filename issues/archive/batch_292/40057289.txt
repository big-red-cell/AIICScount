en...@chromium.org： <p>Apologies for the super delayed response here, this fell through the cracks.</p> <p>You are seeing the effect of <a href="https://chromestatus.com/feature/5670617353289728" data-b-widget="url" data-b-original-href="https://chromestatus.com/feature/5670617353289728" data-b-redirected-href="https://www.google.com/url?q=https://chromestatus.com/feature/5670617353289728&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw16EiQzdGQCtA47aQK-nEHZ">Permission Delegation</a> here. In short, UX research showed that making permission decisions for cross-origin iframes and managing previous decisions was complicated and confusing to users. To address this problem, in Chrome 71 we made a change so that we only ask users to make decisions about the top level origin. It is then up to the top level website to delegate permission to the various iframes which it embeds, if it chooses, using <a href="https://developer.mozilla.org/en-US/docs/Web/HTTP/Permissions_Policy" data-b-widget="url" data-b-original-href="https://developer.mozilla.org/en-US/docs/Web/HTTP/Permissions_Policy" data-b-redirected-href="https://www.google.com/url?q=https://developer.mozilla.org/en-US/docs/Web/HTTP/Permissions_Policy&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw12a4C_sUktuxxxXEhv9Ks4">Permission Policy</a>.</p> <p>In your first example in <a href="https://issues.chromium.org/issues/40057289#comment1" data-b-widget="issue-reference" data-b-issue-id="40057289" data-b-comment-number="1">comment #1</a>, because the embedded frame is same-origin with the top-level document, it inherits the top level document&#39;s permissions state by default. For most intents and purposes, there is no meaningful difference between code running in the top-level frame vs. nested frame.</p> <p>In your second example in <a href="https://issues.chromium.org/issues/40057289#comment5" data-b-widget="issue-reference" data-b-issue-id="40057289" data-b-comment-number="5">comment #5</a>, in the cross-origin embedding scenario, the top-level document needs to provide the <code>allow=&quot;geolocation&quot;</code> attribute on the <code>&lt;iframe&gt;</code> to enable the nested, cross-origin frame to:</p> <ol> <li>trigger a permission prompt (on behalf of the top-level frame),</li> <li>use the top-level frames permission state.</li> </ol> <p>In this world, it is the responsibility of the top-level site to only specific the <code>allow</code> attribute for embedded documents it trusts. There are some capabilities that can be inherited by default, see the list <a href="https://source.chromium.org/chromium/chromium/src/+/main:third_party/blink/renderer/core/permissions_policy/permissions_policy_features.json5;drc=58b37f770216cc031d4e592b035134b37fe643f8" data-b-widget="url" data-b-original-href="https://source.chromium.org/chromium/chromium/src/+/main:third_party/blink/renderer/core/permissions_policy/permissions_policy_features.json5;drc=58b37f770216cc031d4e592b035134b37fe643f8" data-b-redirected-href="https://www.google.com/url?q=https://source.chromium.org/chromium/chromium/src/%2B/main:third_party/blink/renderer/core/permissions_policy/permissions_policy_features.json5;drc%3D58b37f770216cc031d4e592b035134b37fe643f8&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2NWMd165GSzPp3pHSpxpw4">here</a>.</p> <p>Feel free to reopen if you observe behavior inconsistent with the above!</p>
