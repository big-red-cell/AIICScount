jo...@deadbytes.net： <p>Excuse me if I misunderstand the expected security boundaries around cross origin protections but this didn&#39;t seem correct.</p> <p><strong>VULNERABILITY DETAILS</strong><br> An attacker identifying XSS on a vulnerable website where they are able to inject arbitrary JavaScript can send cookies cross origin despite <code>Access-Control-Allow-Origin</code> not being set. The presence of <code>Access-Control-Allow-Credentials</code> allows the cookie to be sent even though the request fails. This requires an attacker to have a publicly available web server that can respond with the necessary headers and bypasses protection of blocking <code>Access-Control-Allow-Origin</code> from using <code>\*</code> when <code>Access-Control-Allow-Credentials</code> is set to <code>true</code>.</p> <p><strong>VERSION</strong><br> Chrome Version: 99.0.4844.74 stable<br> Operating System: MacOS Monterey 12.2.1</p> <p><strong>REPRODUCTION CASE</strong><br> Create directories attacker and vuln and place index-attacher.php and index-vuln.php into each respectively, renaming them to index.php. The README.md provides specific reproduction information.</p> <p><strong>CREDIT INFORMATION</strong><br> <strong>Externally reported security bugs may appear in Chrome release notes.
