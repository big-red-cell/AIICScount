Vulnerability description
nobody@google.com： <p><strong>VULNERABILITY DETAILS</strong><br> I discovered a vulnerability which allows an attacker to create and send malicious CRX files via a direct URL link. Once these CRX files are installed by the target of an attack, Google Chrome does not display the usual dialogue box asking the user to confirm the permissions requested by the malicious Chrome Extension.</p> <p>Please see attached PDF for a POC with photos.</p> <p><strong>VERSION</strong><br> Chrome Version: Latest Version of Chrome<br> Operating System: All Operating Systems</p> <p><strong>REPRODUCTION CASE</strong><br> Background:<br> Normally when a user tries to download a CRX file from a direct URL link, Google Chrome will scan the file and check to verify that it’s a valid Chrome Extension from the Chrome Web Store. If it fails this verification, then the file is deleted from the user’s computer.</p> <p>In addition, when a user manually drags and drops a CRX file to install it in developer mode, a dialogue box appears which lists the extensions requested permissions and asks the user to accept the installation. Both of these protections can be bypassed by packing a malicious extension for Google Chrome, then changing the file extension from CRX to ZIP.</p> <p>POC:</p> <ol> <li> <p>Create and package a malicious CRX file (Example: Cursed Chrome)</p> </li> <li> <p>Change the file extension of this file from CRX to ZIP</p> </li> <li> <p>Now host this file on a web server so that the target of your attack can download it. Google Chrome will not delete the malicious zip file after download.</p> </li> <li> <p>In the extensions settings page, turn on developer mode, then drag and drop the zip file to install it. No warning or dialogue box will appear and the user will not be asked to confirm the installation. The malicious extension will is now installed.</p> </li> </ol> <p><strong>CREDIT INFORMATION</strong><br> <strong>Externally reported security bugs may appear in Chrome release notes. If</strong><br> <strong>this bug is included, how would you like to be credited?</strong><br> Reporter credit: Andrew Steinberg</p>
