The effects of an exploit would<br>be widespread and highly impactful, as the attacker could just forge a response targeting the source<br>port of vulnerable resolver without the need to guess the correct TXID.<br><br>Vulnerability Details<br>After analyzing the source code of all DNS software, we locate a response preprocessing part that<br>receives incoming packets and parses them before processing valid DNS data.<br>We find that there is a huge implementation difference between different DNS software on the<br>preprocessing operation. If the source port is matched, these software will accept these packets.<br><br>Regarding this sort of processing, we propose a DoS attack to cause vulnerable resolvers to ignore<br>any valid response and terminate current resolution process. We name it BadDNS attack.<br><br>General attack steps:<br> 1. The target resolver sends a query for current resolution.<br><br> 2. The attacker forges malformed packets and returns them to the target resolver earlier to legal<br>    response.<br> 3. To hitting the correct source port, the attacker could just brute-force the 65,535 port numbers. By<br>    doing so, all queries using any port of these 65,535 ports would fail.<br><br> 4. After receiving malformed packets, the target resolver just decides that there is something wrong<br>    with the remote server and ignores any follow-up responses.<br><br> 5.
