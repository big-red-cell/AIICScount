Fine attached &quot;permissionsoverlay.html&quot; and host it.<br>2. Browse and click on permission button.<br>3. en...@chromium.org： Apologies for the delay here and thank you for the report.<br><br>The overlap here is indeed awkward, at the same time, windowing systems on desktop have been around for decades, and we must to be able to believe that by now, users will have some understanding for, and are able to deal with, windows that are very clearly just stacked on one another.<br><br>I also think that there are some security invariants that are meaningful and useful to maintain here. For example: the keyboard focus should be on the top-most window (here, the MIDI prompt), and the chip that is shown should match the top-most window (again, the MIDI prompt), and there should be no confusion about the security origin requesting these permissions (here, all UI surfaces are same-origin).<br><br>If you have a variant of the POC that undermines these invariants, I am curious to look into that. However, as long as these invariants are all met, then the situation you depict above is indeed awkward, but I am not sure I can see how it can lead to user confusion.<br><br>(Adding elklm@ and tungnh@ as FYI, let me know if you disagree with my mental model above.)
