al...@google.com： <p>Update some findings.</p> <p>On Android, content:// scheme is used when browser load a local html file to the browser. When a blob document url is created, it inherits the origin from the environment creating it. This seems to match what <a href="https://w3c.github.io/FileAPI/#originOfBlobURL" data-b-widget="url" data-b-original-href="https://w3c.github.io/FileAPI/#originOfBlobURL" data-b-redirected-href="https://www.google.com/url?q=https://w3c.github.io/FileAPI/%23originOfBlobURL&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw202CZ_IcwRhY87AqtkKYAo">https://w3c.github.io/FileAPI/#originOfBlobURL</a> said. A content:// scheme origin is considered secured and the embedded iframe has &quot;usb&quot; in allow attribute, which enables the feature policy of WebUSB in the embedded permissions.site. Things look expected.</p> <p>On Windows, file:// scheme is used for local files, but interestingly, when a blob document url is created, it generates opaque origin instead of inheriting from the origin of file://. That doesn&#39;t match what blob spec describes. Also that is actually the reason why you don&#39;t see a permission prompt while clicking on &quot;usb&quot; button, because the feature is not enabled (so as many other features on the page).</p> <p>Also interestingly, the origin of a file:// scheme seems not well defined in <a href="https://url.spec.whatwg.org/#origin" data-b-widget="url" data-b-original-href="https://url.spec.whatwg.org/#origin" data-b-redirected-href="https://www.google.com/url?q=https://url.spec.whatwg.org/%23origin&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2-0GLlOnQv9KmrZgCqdny3">https://url.spec.whatwg.org/#origin</a>, that means browser decide what to do on its own. I guess on Chromium it decides to just create an opaque origin when a blob document url is created from file://, but I am not entirely sure though.</p>
al...@chromium.org： Since this is not defined in spec and leave the browser to decide the behavior, I assume what we see here is expected and will mark this issue as Won&#39;t Fix.
