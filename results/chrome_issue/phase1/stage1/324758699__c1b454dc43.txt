<p>VULNERABILITY DETAILS</p>
<p>I discovered a vulnerability in the implementation of the CSP frame-src directive. Despite setting &#39;frame-src&#39; to a specific source, like &quot;frame-src <a href="https://another-domain.com/" data-b-widget="url" data-b-original-href="https://another-domain.com/" data-b-redirected-href="https://www.google.com/url?q=https://another-domain.com/&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0SP8Vf2WDXDGOm7PlGsxdG">https://another-domain.com/</a>&quot;, it still permits the use of the javascript protocol. Ideally, when &#39;frame-src&#39; is configured for a specific source, only that particular source should be permitted, and other domains or protocols should be disallowed.</p>

<p>Here, we create an iframe. An iframe always contain a document. We always start from the &quot;about:blank&quot; document. Then we execute the javascript URL on the document. This works, because both document are from the same-origin. Executing the javascript URL is not a navigation.</p>
<p>CSP <code>frame-src</code> is only about navigation, so this is working as intended.</p>
<p>The proposed POC is similar to creating an empty iframe, and running script from the parent.</p>
<pre><code>  const iframe = document.createElement(&quot;iframe&quot;);
  document.body.appendChild(iframe);
  iframe.contentWindow.eval(`alert(document.domain)`)
</code></pre>
<p>Both the parent and the child are sharing the same origin and share the same CSP. In both documents, we can&#39;t inject iframe and make them navigate outside of what their CSP: frame-src enforce. This is working as expected.</p>
