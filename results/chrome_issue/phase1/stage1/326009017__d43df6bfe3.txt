<hr>
<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<ol>
<li>open web that victim want, here <a href="https://ansuh.000webhostapp.com/image.html" data-b-widget="url" data-b-original-href="https://ansuh.000webhostapp.com/image.html" data-b-redirected-href="https://www.google.com/url?q=https://ansuh.000webhostapp.com/image.html&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1x8dfZh-FnI5vR0bFOKqtK">https://ansuh.000webhostapp.com/image.html</a></li>
<li>open image in new tab (this image is SVG image encoded base64)</li>
<li>alert showed from SVG image, and the subject alert is main website (ansuh.000webhostapp.com), What should be displayed is &#39;this page&#39;</li>
</ol>
<h4>Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>This bug is simple, but it will affect the victim, because the victim will believe that the alert that appears comes from the website he visited.
When the attacker successfully stores the XSS in the form of a base64 image SVG file to some site(like facebook), This bug helps attackers to trick victims into entering their website passwords when they want to see the intended image. attacker will inform victim to open the image in new tab, So when opening in the new tab, a prompt will appear to fill in the password. Because the subject still points to the main website, the victim will believe and will input the password. Then the password can be sent to the attacker site.</p>
