<p>I agree with Ted, and I think it may be a good idea to pass this to our security team - just to get an authoritative answer.</p>
<p>this example essentially presents that typing <code>javascript:alert(location.href)</code> prints current page URL, while the bug argues it should print <code>javascript:</code> or something the lines of, essentially initiating a navigation.</p>
<p>At the origin of this bug lies a dual nature of what a URL does (&quot;some urls are navigable and some are not&quot;). The more complicated piece is that some URLs are non-navigable by design, and are used by &quot;bookmarklets&quot;, e.g. a bookmark:</p>
<pre><code>javascript:window.open(&#39;http://chart.apis.google.com/chart?cht=qr&amp;chs=300x250&amp;chl=%27+encodeURIComponent(location.href), %27_blank%27)
</code></pre>
<p>presents current page URL as a QR code, but if these URLs were navigable, all bookmarklets would essentially cease to function (so sites like instapaper, or spritz would effectively break).</p>
<p>that said, an interesting scenario is:</p>
<ul>
<li>if <code>javascript:</code> URLs don&#39;t initiate navigation, and</li>
<li><code>javascript:</code> URLs can be bookmarked, then</li>
<li><code>javascript:</code> URLs can be invoked from the Omnibox</li>
</ul>
<p>but in that specific scenario a navigation is made, taking user to a defunct <code>javascript:</code> page, where this problem does not exist. In other words: the user has to type this url in the Omnibox while visiting some website (and if an unauthorized app is manipulating bookmarks, then the user is probably already in deeper trouble)</p>
<p>Lens will not allow this to happen.</p>

Author: From the video, this is scanning a QR code via a shortcut on the keyboard itself, right? This is not hitting the Google Lens icon in the omnibox itself.

Essentially, this appears to a keyboard app converting the text of a QR code into text -- and the keyboard "types" that into the underlying app (and potentially hits enter/submit).

I think the QR code / keyboard interaction is a "red herring" here. The question is whether a user typing that text into the omnibox should perform that action shown in the video. If the answer is yes, then I think we close this as working as intended. I don't think it's reasonable for us to police what a keyboard does for accelerating text entry (nor do I believe we have a way to detect it).
