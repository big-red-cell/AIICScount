<h1>Problem Description</h1>
<p>These are just benign examples of these issues. The problem arises when on my websites (pwa-demo.github.io/no), I can set the manifest &quot;start_url&quot; values to &quot;?redirect=example.com&quot;. Then, during installation, instead of showing me the main page of pwa-demo.github.io, it will show me example.com, which violates the SOP policy.</p>
<p>This isn&#39;t an issue on Desktop Chrome, but it is problematic on Android devices, as it could potentially be exploited by malicious attackers.</p>
<h1>Additional Comments</h1>
<p>My manifest looks like this &quot;start_url&quot;: &quot;/no/?redirect=app.starbucks.com&quot;</p>
<h1>Summary</h1>
<p>PWA installation bypasses the SOP policy by taking advantage of the start_url field in the manifest.</p>

Author: ja...@tamu.edu
I agree that a malicious attacker can always do worse things than this. The issue here is that the start_url should not be a path that attackers can exploit. For example, it performed well on your Desktop version; however, if attackers craft the start_url, they will bypass it. On an Android device, attackers can execute actions as described earlier. <br><br>The &quot;start_url&quot; should be within the &quot;scope,&quot; as defined by W3C, another field in the manifest file. However, crafting the value of &quot;start_url&quot; can cause it to fall outside of the scope, which is the crux of the problem here.<br><br>I believe it&#39;s not solely about what attackers can do; it&#39;s also about the violation of the least privilege principle. User privacy could be compromised if the Desktop and Android versions behave differently.<br>
