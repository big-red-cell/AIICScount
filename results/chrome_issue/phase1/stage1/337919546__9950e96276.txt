Author: # Steps to reproduce the problem
1. Host the below page with basic auth - 
```
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
  </head>
  <body>
    <button id="b">
      Click Here
    </button>
    <script>
      b.addEventListener('click', async (e)  => {   
      const data = {
      url: document.URL,
      };
      navigator.share(data);  

    });
    </script>
  </body>
</html>

```
2. User can either authenticate using HTTP Auth Pop Up (Creds won't be in URL) or through URL itself like http://user:pass@example.com
3.  Website want's to share URL only(without creds in url) as part of functionality, but when user is authenticated with username & password in URL, Victim's credentials are also getting shared.

# Problem Description
Website wants to share only URL using Navigator.share() API, whose url field is set from document.URL 
When user authenticates using HTTP Auth credentials present in URL, Navigator.share includes user credentials also which is not intended by the website.

Discussions:
> "Do note that window.location.href returns url without username & password, while the old document.URL return url with credentials"
Should the document.URL also return url without credentials like window.location.href which is more secure ?

Note: This report is similar to https://issues.chromium.org/issues/337673270#comment4 , I have added a better scenario with document.URL and Navigator.share() API.
