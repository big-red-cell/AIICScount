fa...@gmail.com： Security Bug<br>-------------------------<br><br>VULNERABILITY DETAILS<br>The `chrome.declarativeNetRequest` API is used to block or modify network requests by specifying declarative rules. This allows extensions to modify network requests without intercepting and viewing their content, which includes modifications of scripts, CSS, embedded pages, images, etc. However, using the same permission, `declarativeNetRequest`, a malicious extension can also modify the resources of other extensions.<br><br>VERSION<br>Chrome Version: 126.0.6452.3 (Official Build) dev (64-bit) (cohort: Dev) <br>Operating System: Windows 11<br><br>REPRODUCTION CASE<br>1. Download the attached proof of concept files. Load the &quot;Attacker Extension&quot; by enabling developer mode at chrome://extensions/.<br>2. Similarly, load the &quot;Victim Extension&quot; as well.<br>3. After loading, notice that the victim extension&#39;s page has been compromised. rd...@chromium.org： <p>Yep, this is working as intended.  Extensions may not access or modify resources from a chrome-extension origin (that is, an extension can&#39;t access or modify main.html in the &quot;Victim Extension&quot; here directly), but they can operate on web origins, including web origins in iframes embedded in extension frames.  This is true for declarativeNetRequest and for other APIs, such as content scripts.</p> <p>Closing this out as WAI.</p>
