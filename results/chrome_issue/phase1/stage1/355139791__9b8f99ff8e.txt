<p>The attached proof of concept expects that <code>frame-src &#39;none&#39;</code> will prevent an <code>&lt;iframe src=&quot;javascript:…&quot;&gt;</code> from evaluating the JavaScript.</p>
<p>The HTML specification defines how navigating to a <code>javascript:</code> URLs interacts with CSP in <a href="https://html.spec.whatwg.org/multipage/browsing-the-web.html#the-javascript:-url-special-case" data-b-widget="url" data-b-original-href="https://html.spec.whatwg.org/multipage/browsing-the-web.html#the-javascript:-url-special-case" data-b-redirected-href="https://www.google.com/url?q=https://html.spec.whatwg.org/multipage/browsing-the-web.html%23the-javascript:-url-special-case&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3lKQGAC-X3muza72vVFxQb">7.4.2.3.2 The javascript: URL special case</a>. This refers to CSP <a href="https://w3c.github.io/webappsec-csp/#should-block-navigation-request" data-b-widget="url" data-b-original-href="https://w3c.github.io/webappsec-csp/#should-block-navigation-request" data-b-redirected-href="https://www.google.com/url?q=https://w3c.github.io/webappsec-csp/%23should-block-navigation-request&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3UExf6CTUfiN1aFBBTJ4yV">4.2.4. Should navigation request of type be blocked by Content Security Policy?</a>. This says that an inline check for directive <code>script-src-elem</code> should be used for <code>javascript:</code> URLs (type is <code>navigation</code> in this context, per the HTML spec).</p>
<p>If you update your HTML to specify a policy of <code>script-src-elem &#39;none&#39;</code> you&#39;ll see that the JavaScript is blocked as expected.</p>
<p>For some extra background, <a href="https://github.com/w3c/webappsec-csp/issues/127" data-b-widget="url" data-b-original-href="https://github.com/w3c/webappsec-csp/issues/127" data-b-redirected-href="https://www.google.com/url?q=https://github.com/w3c/webappsec-csp/issues/127&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2AYHha7r9ZKlJWiJJ5hiOC">https://github.com/w3c/webappsec-csp/issues/127</a> has some history of why this behavior is specified as it is. <a href="https://github.com/web-platform-tests/wpt/blob/master/content-security-policy/navigation/to-javascript-url-frame-src.html" data-b-widget="url" data-b-original-href="https://github.com/web-platform-tests/wpt/blob/master/content-security-policy/navigation/to-javascript-url-frame-src.html" data-b-redirected-href="https://www.google.com/url?q=https://github.com/web-platform-tests/wpt/blob/master/content-security-policy/navigation/to-javascript-url-frame-src.html&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2mZhiAaP7mRFZ3aQZdNz8j">to-javascript-url-frame-src.</a> is a web platform test asserting that <code>frame-src &#39;none&#39;</code> does not block <code>javascript:</code> URLs in iframes. <a href="https://github.com/web-platform-tests/wpt/blob/master/content-security-policy/navigation/to-javascript-url-script-src.html" data-b-widget="url" data-b-original-href="https://github.com/web-platform-tests/wpt/blob/master/content-security-policy/navigation/to-javascript-url-script-src.html" data-b-redirected-href="https://www.google.com/url?q=https://github.com/web-platform-tests/wpt/blob/master/content-security-policy/navigation/to-javascript-url-script-src.html&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw19wDmMTVGYVlX5-EVCJO3k">to-javascript-url-script-src</a> covers <code>script-src-elem</code> and <code>javascript:</code> URLs.</p>

<p>Wow, this one was difficult to refute! It took me some time.</p>
<p>Thanks for opening this report.</p>
<pre><code>&lt;<span class="stx-keyword">meta</span> http-equiv=<span class="stx-string">&quot;Content-Security-Policy&quot;</span> content=<span class="stx-string">&quot;frame-src &#39;none&#39;&quot;</span>&gt;
&lt;<span class="stx-keyword">body</span>&gt;
  &lt;<span class="stx-keyword">iframe</span> src=<span class="stx-string">&quot;javascript:</span>
<span class="stx-string">    let iframe=document.createElement(&#39;iframe&#39;);</span>
<span class="stx-string">    iframe.srcdoc=&#39;&lt;a href=http://example.com target=_blank&gt;a&lt;/&gt;&#39; //</span>
<span class="stx-string">    document.body.appendChild(iframe)</span>
<span class="stx-string">  &quot;</span>&gt;&lt;/<span class="stx-keyword">iframe</span>&gt;
</code></pre>
<p>--</p>
<ol>
<li>CSP <code>frame-src</code> is only about navigation. As such, the initial empty document can always &quot;load&quot;. This is essential, because a &quot;frame&quot; can&#39;t be empty.</li>
<li>Using <code>iframe.src = &quot;javascript:&quot;</code> does not create a navigation. Instead it execute script in the current document (e.g. <code>about:blank</code>)</li>
<li>The script doesn&#39;t create an iframe. There is a comment <code>//</code> hidden causing the last instruction not to execute.</li>
<li>When a javascript URL &quot;evaluate&quot; to a string, the string is inserted. Here, the real &quot;last&quot; instruction is <code>iframe.srcdoc</code>, which evaluates to a string. The value is inserted into the DOM of <code>about:blank</code>.</li>
</ol>
<p>That&#39;s why we see a <code>&lt;a&gt;</code> embedded inside the initial empty document.</p>
<p>This is working as expected. There are no navigation, so it is normal CSP:frame-src doesn&#39;t block anything.</p>
