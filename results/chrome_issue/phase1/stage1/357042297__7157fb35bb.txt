Author: Perhaps my comparison to EXE was inapt. Sorry about that, since it seems to be distracting from the real issue. (For example, this is a MacOS bug, so Mark of the Web is irrelevant)

From the Safe Browsing side, we're not willing to mark all file types that might execute code as dangerous. fileloc is one example, but we have plenty of potentially dangerous file types for MacOS listed [here](https://source.chromium.org/chromium/chromium/src/+/main:components/safe_browsing/content/resources/download_file_types.asciipb;drc=ae18bb965a72f3ab44bafcd7586d39571d16ee8b;l=3043). Whatever action we take for this bug should be applied to all of those. These downloads are evaluated by Safe Browsing, so we have confidence that we'd have visibility into large-scale abuse and the means to combat it (a Safe Browsing warning would mark the download as dangerous).

It sounds to me like this is an intentional part of the extensions platform. Many extension APIs pose security risks to users, and we rely on our review process, anti-abuse mechanisms, and user trust in extension developers to mitigate them.
