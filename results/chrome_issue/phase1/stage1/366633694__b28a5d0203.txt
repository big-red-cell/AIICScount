<p>Any domain that expires and is not renewed after 90 days can be registered by someone else. So, what’s interesting about this? Whoever re-registers the domain does not need to ask for permission again from those who had previously granted permissions to the domain.</p>
<p>Is this a problem? Absolutely. In this case, I tested it with a domain of a large Indonesian company, called Indomie.</p>
<p>The domain <em>indomieido.com</em> was once used by Indomie for their Ramadan advertising campaign. I participated in the campaign and granted permission for the domain to activate the camera on my device.</p>
<p>Some time after, the domain expired and wasn’t renewed. I re-registered it and wrote a simple code to trigger the camera, and it worked.</p>
<p>What shouldn’t happen here?
Browsers should reset all permissions for domains that have expired because when a domain is re-registered by an attacker, they can access certain features previously granted by users without needing to ask for permission again. This is because the permissions were granted to the original domain owner before the attacker re-registered and took control of the domain.</p>
<p>Can this issue be resolved?
Certainly. Every domain has a unique Registry Domain ID. For instance, <em>google.com</em> has the Registry Domain ID <em>2138514_DOMAIN_COM-VRSN</em>, and as long as the domain is renewed, the ID remains unchanged. However, when the domain expires and is re-registered, the domain will have a new Registry Domain ID.</p>
<p>Therefore, you can address this issue by always identifying the Registry Domain ID of every domain that has been granted permission in the user’s browser. If at any point the domain <em>example.com</em> with Registry Domain ID <em>test123</em> suddenly changes to <em>test456</em>, reset all permissions granted to that domain. A change in the Registry Domain ID indicates a change in ownership, and there is a high likelihood the domain has been re-registered by an attacker.</p>

<p>Although it is true that domains frequently change ownership, this is not the same as user security. When a domain changes hands, it is not merely a “trivial ownership transfer,” but rather a potential security threat. The security and privacy of users must always be a priority, not treated as a side effect that is ignored during transfers.</p>
<p>I fully understand that users have the option to select &quot;Allow while visiting the site&quot; meaning they grant indefinite consent. However, this does not mean that the permission should remain valid when domain ownership changes. The solution I propose is to separate permissions based on domain ownership, not just the domain itself. Users grant permission to the entity managing the domain at that time, not to whoever might acquire the domain in the future. Therefore, when domain ownership changes, the trust relationship between the user and the new owner should also be reset.</p>
<p><strong>Domain Ownership Identity Validation Solution</strong>
The browser can validate domain ownership changes without forcing users to re-grant permissions during every visit. As previously mentioned, the Domain Registry ID remains a strong indicator of domain ownership changes, as it is a fundamental part of domain management. While it is not always publicly accessible, Chrome can internally store and monitor the Domain Registry ID of domains that users have granted permissions to. When the ID changes, Chrome could automatically trigger a re-validation of permissions for that domain. This protects users from the misuse of permissions by the new owner.</p>
<p>If the Domain Registry ID is not fully accessible, an alternative is to use updated SSL certificates. Every time an SSL certificate expires and is renewed by a new owner, the browser can verify that the domain may have changed hands, thus triggering a permission reset.</p>
<p><strong>&quot;Transparency and Notification to Users.&quot;</strong> When a domain ownership change is detected, instead of immediately revoking permissions, Chrome could display a notification to the user, explaining that the domain they previously allowed may now be owned by a different entity. Users can choose to review the permissions they have granted, with the understanding that they are no longer dealing with the same domain owner. This allows full transparency without burdening the user with repeated popups.</p>
<p><strong>Another Option: More Specific User Controls</strong>
To address the issue of &quot;Allow while visiting the site&quot; Chrome could offer more advanced permission options. Users could be given the <strong>option to grant permissions based on time or entity validation</strong>, where they can provide permissions only as long as the domain is owned by the same entity, or limit the duration of permissions based on their preferences. This gives users greater control over their privacy while still maintaining a seamless user experience.</p>

<p>The core issue here is not the duration of permissions, but the inherent trust between users and the entities they grant permissions to. When a user chooses &quot;Allow while visiting the site,&quot; they are not only granting permission to the domain name but also to the owner of that domain. The user trusts that the domain owner will manage those permissions responsibly. However, when a domain changes hands, there is a shift in the entity trusted by the user, which can significantly impact their privacy and security.</p>
<p><strong>User trust</strong> is at the heart of browser security. If expired and re-registered domains can exploit old permissions without re-requesting them, then <strong>user privacy</strong> is at risk, especially if the new owner has malicious intent.</p>
<h3><strong>The Right Solution:</strong></h3>
<ol>
<li>
<p><strong>Reset Permissions When Domain Ownership Changes:</strong> Utilize <strong>SSL certificate updates</strong> or <strong>entity validation changes</strong> to trigger permission resets. This protects users without relying on external data that may not always be accessible.</p>
</li>
<li>
<p><strong>User Notifications:</strong> Inform users if a domain they previously granted permissions to changes ownership, allowing them to re-verify their permissions.</p>
</li>
</ol>
<h3><strong>Why This Matters:</strong></h3>
<p>Maintaining <strong>user trust</strong> and <strong>permission integrity</strong> is a priority. Ensuring permissions are not misused by new owners is a crucial step in protecting user privacy and maintaining browser reputation.</p>
<p>I believe that with the implementation of these solutions, Chrome can continue to lead in <strong>security and transparency</strong>, effectively and innovatively maintaining user trust.</p>
