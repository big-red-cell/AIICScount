<p>If I read this correctly, this emulates a <code>fetch()</code> and will then assign the fetch result to <code>.innerHTML</code>. This will indeed execute script. My understanding of the fetch &amp; HTML specs is that fetch isn&#39;t meant to sanitize the data; and <code>.innerHTML</code> isn&#39;t meant to block script execution. In other words, forcing sanitization in either the <code>fetch()</code> or the <code>.innerHTML</code> steps would violate specs and would be web-incompatible.</p>
<p>IMHO, this is working as intended. I don&#39;t think this should count as a vulnerability and/or security issue.</p>
<p>Some additional comments:</p>
<ul>
<li>Arguably, this is a feature request for either Fetch or HTML specs. I suspect they&#39;ll be skeptical of changing existing behaviour, though.</li>
<li><a href="https://issues.chromium.org/issues/371768645#comment3" data-b-widget="issue-reference" data-b-issue-id="371768645" data-b-comment-number="3">#comment3</a>: The referenced Sanitizer work should indeed give developers an easy way to avoid this problem. We&#39;re still working on it.</li>
<li><em>&quot;allowing for the injection of harmful payloads directly into HTML elements.&quot;</em> I&#39;d usually understand injecting to mean something attacker controlled. But using <code>fetch()</code> requires very explicit code to actually include the result into a page unmodified; implemented here by assigning to <code>.innerHTML</code>.</li>
</ul>
