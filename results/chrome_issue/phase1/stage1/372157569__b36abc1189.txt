Author: cl...@google.com
Sorry I had missed this. For me, this is working as intended. The download is a decision triggered by the non-sandboxed frame in response to a postMessage. PostMessage is allowed from the sandboxed frame to the non-sandboxed frame because the sandboxed frame has allow-scripts. So this is working according to spec. Unfortunately, there is no sandbox flag that prevent postMessage from sandboxed to non-sanboxed content, so as long as the sandboxed frame has allow-script, it can postMessage to any context, including non-sandboxed ones. Then the non-sandboxed contexts are free to respond to the postMessage in whatever manner they want, including by opening popups or downloading files. This is just following the specs. The alternative you are asking about would require to block all downloads and popup opening for all browsing contexts in the browsing context group (the page and all pages it can communicate with) as long as there is one sandboxed iframes in any of these pages. This is clearly breaking web compatibility and seems problematic. I will mark this bug as won&#39;t fix.
