Sorry, I’m not quite sure you fully understood what I explained. I agree that any website can redirect users to any page at any time. However, the issue isn’t about pages being able to redirect users, but rather that the back button or the history.back() function should navigate users back to the pages they previously visited, not to some other page that the users didn’t access. That’s not a &quot;back,&quot; but a &quot;redirect.&quot;<br>Let’s take a look. The crucial function in the POC of this vulnerability is:<br><br>setTimeout(function() {<br>    window.location.reload();<br>}, 1000);<br><br>Without this additional function, Chrome browser has actually mitigated attempts to alter the history by still showing the original/visited page. Even if the URL in the history has changed, when the back button on the browser is pressed or the history.back() function is executed, the browser continues to display the page that the user genuinely accessed. I’ve attached a new video to show the difference.
