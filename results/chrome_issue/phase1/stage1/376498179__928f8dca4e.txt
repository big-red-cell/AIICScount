Security Bug<br>-------------------------<br><br>VULNERABILITY DETAILS<br>Private Network Access can be bypassed by instantiating a WebSocket object which sends an HTTP request for the WebSocket handshake. For example, loading a remote site that runs JavaScript &#39;fetch(&quot;<a href="https://www.google.com/url?q=http://localhost/req?foo%3Dbar&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0s_4aa35nr7Wu4Q1daNmlD" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="http://localhost/req?foo=bar" data-b-redirected-href="https://www.google.com/url?q=http://localhost/req?foo%3Dbar&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0s_4aa35nr7Wu4Q1daNmlD">http://localhost/req?foo=bar</a>&quot;)&#39; will fail in the browser with the following error &quot;has been blocked by CORS policy: The request client is not a secure context and the resource is in more-private address space `local`.&quot;. Loading a remote site that runs the JavaScript &#39;const socket = new WebSocket(&#39;ws://localhost/req?foo=bar&#39;);&#39; will send an HTTP GET request via the browser bypassing Private Network Access. <br><br>VERSION<br>Chrome Version: Version 130.0.6723.71 (Official Build) (arm64) + stable<br>Operating System: MacOS Sonoma 14.6.1<br><br>REPRODUCTION CASE<br>File is attached.<br><br>CREDIT INFORMATION<br>Externally reported security bugs may appear in Chrome release notes.
