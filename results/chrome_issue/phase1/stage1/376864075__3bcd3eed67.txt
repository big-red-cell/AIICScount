<h1>Problem Description</h1>
<p>This report examines two main vulnerabilities identified in the developed browser extension:</p>
<p>Unrestricted Access to Local Files
Unauthorized Access to Authorized Websites (e.g., Google.com)
through the use of a .URL file
Description: background.js establishes a connection with popup.html through ports. Upon receiving a message of type START_READ_FILE, the extension loads the content of the p.url file, extracts the URL, and opens it in a new inactive tab.
In this case, we specified the path for reading file://C:/Windows/System32/hosts.
When clicking the &quot;Open .url File&quot; button, popup.js sends a message to background.js to start reading the p.url file. After receiving a response, the content of the file is displayed in the fileContent element.</p>
<p>The extension enables loading and displaying content from authorized websites, such as <a href="https://www.google.com" data-b-widget="url" data-b-original-href="https://www.google.com" data-b-redirected-href="https://www.google.com/url?q=https://www.google.com&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0xHc4PnJ-5PnGXiIvS00h7">https://www.google.com</a>, within the popup.html window. This could lead to unauthorized access to user data and sensitive information, especially if the user is logged into these sites.
In the .URL file, we specified the site google.com. The extension loads the specified URL’s content and directly inserts it into the fileContent element inside popup.html using innerHTML.
We can pass the obtained values to the server.
I could not execute XSS code on the page within the popup or extract cookie values to send them to the server.</p>
<h1>Summary</h1>
<p>The extension can display an authorized Google profile in its own window and read local files.</p>
