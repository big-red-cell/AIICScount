<p>Based on the provided report and videos, I cannot determine the network topology and configuration between the victim device and the attacker device.</p>
<p>I assume you did something like <a href="https://portswigger.net/burp/documentation/desktop/mobile/config-android-device" data-b-widget="url" data-b-original-href="https://portswigger.net/burp/documentation/desktop/mobile/config-android-device" data-b-redirected-href="https://www.google.com/url?q=https://portswigger.net/burp/documentation/desktop/mobile/config-android-device&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2Yc_UzoyDfyu5dykT8rSRW">https://portswigger.net/burp/documentation/desktop/mobile/config-android-device</a> as part of your configuration. The only reason this data is leaked to the proxy is because the proxy is using a certificate that the android device was configured to trust. That is not a security issue.</p>
<p>If you still think there&#39;s an issue here, please carefully describe the network setup between the two devices and all configuration settings made to the victim device to make this attack work. In particular, start with a factory-reset victim device. For this to be a security issue, you need to demonstrate that Chrome is failing to validate the certificate for clients4.google.com.</p>
