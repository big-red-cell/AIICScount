Author: # Steps to reproduce the problem
1. Create a remote server hosting a webpage with the following contents: 
```html
<script>window.opener = null; location.replace("https:\/\/google.com\/")</script>
```
2. Navigate to that server's webpage 
3. Examine the browser history and the history will show that the webpage is Google even though the domain is not google.com
4. Change the webpage to the following: 
```html
<script>window.opener = null; location.replace("https:\/\/chromium.org\/")</script>
```
5. As a separate user who has not visited the website before, navigate to the server's webpage. That user will be redirected to chromium.org.
6. As the first user who visited the webpage, without clearing the browser cache, navigate back to the website. This user will be redirected to google.com, even though the current webpage is now redirecting users to chromium.org

# Problem Description
The user's browser history shows the icon and name of the website redirected to while still pointing to the original URL visited. For example, if the webpage is hosted on example.com but is redirected to google.com, the browser history icon will show Google and the Google icon, but still go directly to example.com. 

In addition, depending on when the user visits the webpage, whatever redirect it was set to, will stay that way for that specific user even if it changes later on within the webpage itself. 

# Summary
An attacker can poison the browser cache to redirect to an arbitrary website indefinitely
