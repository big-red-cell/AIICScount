<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>JavaScript embedded in PDF files is an intended functionality designed to enhance interactivity. However, when PDFs are rendered in Chromium-based browsers (e.g., Chrome, Edge, Brave), the current implementation poses a significant spoofing risk due to how JavaScript alerts are displayed. Specifically, alerts triggered by JavaScript in PDFs display the domain name of the host website in the alert box, rather than indicating that the alert originates from the embedded PDF viewer.</p>
<p>This behavior is exploitable to carry out large-scale spoofing attacks, as malicious actors can upload crafted PDFs with embedded JavaScript to legitimate domains, misleading users into believing the alert originates from the trusted domain itself. In contrast, browsers like Firefox clearly label the alert as originating from the PDF viewer (e.g., &quot;pdf.js&quot;), which mitigates the risk of confusion.</p>
<p>Current Behavior in Chromium-Based Browsers:
When JavaScript embedded in a PDF executes an alert in a Chromium-based browser, the alert box prominently displays the host domain name.</p>
<p>For example:</p>
<p>A malicious PDF hosted at example.com/malicious.pdf displays the alert as:</p>
<p>&quot;example.com</p>
<p>XSS in the PDF&quot;</p>
<p>Behavior in Firefox (PDF.js):
Firefox uses its PDF.js renderer and clearly distinguishes that the alert originates from the PDF viewer.</p>
<p>For example:</p>
<p>&quot;pdf.js</p>
<p>XSS in the PDF&quot;</p>
<h4>Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>The inclusion of the domain name in Chromium-based browsers creates an avenue for spoofing attacks.</p>
