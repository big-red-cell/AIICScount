Author: ch...@chromium.org
<p>I think this is a quirk of the google.com redirector. If this were a normal, HTTP 302 redirect, then the existing logic for determining multiple download permission based on the request initiator would be fine (because the initiator does not change across redirects). But because the google.com redirector uses a javascript redirect, the ultimate download request is in fact initiated by google.com, so with respect to the download request limiter logic, it is correct to treat this as a google.com-initiated download.</p>
<p>I&#39;m inclined to close this as WAI.</p>
