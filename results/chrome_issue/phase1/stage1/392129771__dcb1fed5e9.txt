<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>Chrome browser on macOS lacks proper sandboxing implementation for sensitive browser data (history and cookies), allowing unauthorized access by other applications.</p>
<p>Technical Details:</p>
<ul>
<li>Location: ~/Library/Application Support/Google/Chrome/Default/</li>
<li>Affected files:
<ul>
<li>History (SQLite database)</li>
<li>Cookies (SQLite database)</li>
</ul>
</li>
<li>No sandbox protection or access controls</li>
</ul>
<p>Impact:
Any application with basic file system permissions can:</p>
<ol>
<li>Read complete browsing history</li>
<li>Access stored cookies</li>
<li>Extract visit timestamps and patterns</li>
<li>Monitor user behavior without detection</li>
</ol>
<p>PoC code attached demonstrates:</p>
<ul>
<li>Direct access to Chrome&#39;s databases</li>
<li>Extraction of browsing data</li>
<li>No special permissions required</li>
<li>No user authorization needed</li>
</ul>
<p>Environment:</p>
<ul>
<li>macOS Sonoma 14.3</li>
<li>Chrome Version: 132.0.6834.111</li>
<li>Reproducible on all recent Chrome versions</li>
</ul>
<h4>Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>Any application running on the user&#39;s macOS system with basic file system permissions can exploit this vulnerability. The attacker gains:</p>
<ol>
<li>Complete access to user&#39;s browsing history</li>
<li>Access to stored cookies which could lead to session hijacking</li>
<li>Ability to track user&#39;s browsing patterns and behavior</li>
<li>Potential for credential theft through stored login data</li>
</ol>
<p>This violates Chrome&#39;s security model where sensitive browser data should be protected through proper sandboxing, similar to Safari&#39;s implementation on macOS.</p>
