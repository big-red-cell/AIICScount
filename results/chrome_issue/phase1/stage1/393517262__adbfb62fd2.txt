URL Authentication Parsing Can Be Used for Social Engineering Attacks

Author: ri...@gmail.com
public_non_google

Author: VULNERABILITY DETAILS
Chromium browsers allow URLs containing '@' symbol, this feature can be abused for social engineering, phishing, and browser exploitation attacks. Attackers can create deceptive links that appear to be from trusted domains (e.g., google.com) before the @ symbol, tricking users into clicking malicious links.

VERSION
Chrome Version: [132.0.6834.160]
Operating System: windows 11 version 23H2 (OS build 22631.4751)


REPRODUCTION CASE
1. Open the Chrome browser
2. Enter the following URL in the address bar: https://google.com@evil.com
3. The browser loads evil.com, but an unsuspecting user may believe they are visiting google.com.


REAL WORLD EXPLOITATION SCENARIOS 
1.PHISHING ATTACKS: 
The attacker can send a link to the victim like : https://instagram.com@phishingsite.com
Victims think they are visiting Instagram login page but actually enter credentials on a phishing page.

2.  BeEF HOOKING AND BROWSER EXPLOITATION:
The attacker hosts a BeEF payload on evil.com. As soon as the victim lands on evil.com, the browser is hooked, allowing full control. This can be used to steal cookies, capture keystrokes, and execute malicious scripts.

3. CLIENT-SIDE JAVASCRIPT EXECUTION:
Malicious JavaScript can be injected into the page hosted on evil.com. This script could execute in the victim's browser when they land on evil.com, which can be used to steal session cookies, inject forms, or perform other malicious actions.

4. BYPASSING SECURITY AWARENESS
Even if a user notices the real domain after redirection, the damage is already done if scripts have already executed. Many users only check the first part of the URL before clicking.


SUGGESTED FIXES:
1. Modify Chromium’s URL parsing to ignore @ unless part of valid authentication credentials.
2. Display a security warning before redirecting users.
3. Block navigation to URLs where @ is misused.
