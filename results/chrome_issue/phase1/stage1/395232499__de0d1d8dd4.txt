<h1>Steps to reproduce the problem</h1>
<ol>
<li>Open poc.html</li>
<li>Press the &quot;Click me&quot; button</li>
<li>You will see that the page is opening <a href="http://evil.com" data-b-widget="url" data-b-original-href="http://evil.com" data-b-redirected-href="https://www.google.com/url?q=http://evil.com&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3reQLcKtrIIiGg1kHgnNKP">http://evil.com</a> but the address bar is still show 127.0.0.1</li>
</ol>
<h1>Problem Description</h1>
<p>First of all, I know that this is how iframes work, but the problem here is that the address bar in PiP still shows the URL. If an attacker injects an iframe inside the PiP window, it could make the iframe’s content appear as if it comes from the PiP address bar. The scenario I created in the HTML file is designed to open a webpage inside a PiP iframe, which could confuse the user about the URL and lead to spoofing.</p>
<p>The best way to prevent this spoofing issue is by removing the URL from the PiP window when it contains an iframe, just like Arc Browser did. I’ve attached an image showing how Arc Browser handles this issue to prevent URL confusion, which could lead to spoofing.</p>
<h1>Summary</h1>
<p>Address Bar Spoofing via Opening an Iframe inside a PiP Window</p>
