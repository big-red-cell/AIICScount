<p>VULNERABILITY DETAILS</p>
<p>A heap buffer overflow vulnerability exists in the locale handling code when processing invalid UTF-8 sequences using the strxfrm_l function. The vulnerability occurs when the function writes beyond the allocated buffer size, potentially allowing attackers to execute arbitrary code or crash the application.</p>
<p><a href="https://github.com/chromium/chromium/blob/main/third_party/libxslt/src/libxslt/xsltlocale.c" data-b-widget="url" data-b-original-href="https://github.com/chromium/chromium/blob/main/third_party/libxslt/src/libxslt/xsltlocale.c" data-b-redirected-href="https://www.google.com/url?q=https://github.com/chromium/chromium/blob/main/third_party/libxslt/src/libxslt/xsltlocale.c&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1zr2BFAqw54UAwu6xWcswW">https://github.com/chromium/chromium/blob/main/third_party/libxslt/src/libxslt/xsltlocale.c</a></p>
<p>This code handles locale creation and string transformation for XSLT processing in libxslt, used in applications like Chrome for XML transformations. The key vulnerabilities are:</p>
<p><strong>1. Heap Buffer Overflow in POSIX <code>xsltStrxfrm</code> Function:</strong></p>
<ul>
<li><strong>Cause:</strong> When <code>strxfrm_l</code> (used to compute the transformed string length) returns <code>(size_t)-1</code> (indicating an error), <code>xstrlen</code> becomes <code>0</code>. Subsequent allocation (<code>xmlMalloc(0)</code>) may return a small buffer, and <code>strxfrm_l</code> writes beyond it.</li>
<li><strong>Trigger:</strong> Supply an invalid locale or malformed input string, causing <code>strxfrm_l</code> to fail. This leads to a zero-byte allocation and heap overflow during transformation.</li>
</ul>

<p>I don&#39;t think this is an issue in libxslt or libxml.</p>
<ol>
<li>
<p>The test program calls <code>strxfrm_l</code>. The documentation for <code>strxfrm_l</code> gives the prototype:</p>
<pre><code>size_t strxfrm(char *restrict s1, const char *restrict s2, size_t n);
</code></pre>
<p>And also says:</p>
<blockquote>
<p>If this value is n or more, the contents of s1 are indeterminate.</p>
</blockquote>
<p>It does <em>not</em> say that it&#39;s legal to freely index into <code>s1</code> as long as the index is less than the return value.</p>
</li>
<li>
<p><code>libxslt</code> has this:</p>
<pre><code>    r = strxfrm_l((char *)xstr, (const char *)string, xstrlen, vlocale);

 if (r &gt;= xstrlen) {
 xsltTransformError(NULL, NULL, NULL, &quot;xsltStrxfrm : strxfrm failed\n&quot;);
     xmlFree(xstr);
     return(NULL);
 }
</code></pre>
<p>So they are clearly checking the return value, and it doesn&#39;t seem like they would be affected either.</p>
</li>
</ol>
