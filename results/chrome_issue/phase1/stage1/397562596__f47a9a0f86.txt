<p><strong>Description</strong></p>
<p>This vulnerability allows bypassing the markup sanitization mechanism using a combination of the Clipboard API and Mutation Observer. The fix in <a href="https://chromium-review.googlesource.com/c/chromium/src/+/3611826/4/third_party/blink/renderer/core/editing/serializers/serialization.cc#906" data-b-widget="url" data-b-original-href="https://chromium-review.googlesource.com/c/chromium/src/+/3611826/4/third_party/blink/renderer/core/editing/serializers/serialization.cc#906" data-b-redirected-href="https://www.google.com/url?q=https://chromium-review.googlesource.com/c/chromium/src/%2B/3611826/4/third_party/blink/renderer/core/editing/serializers/serialization.cc%23906&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2hSJWIhuAagjdwfVWNdAX9">https://chromium-review.googlesource.com/c/chromium/src/+/3611826/4/third_party/blink/renderer/core/editing/serializers/serialization.cc#906</a> only performs sanitization during the initial parsing stage but does not protect elements once they are inserted into the DOM, making exploitation possible through runtime manipulation.</p>
<p>Version: 133.0.6943.127 (Official Build) (64-bit)</p>
<p>OS: window</p>
<p><strong>Vulnerability Details</strong></p>
<p>I read the fix code of the vulnerability that was fixed <a href="https://issues.chromium.org/40059358" data-b-widget="issue-reference" data-b-issue-id="40059358">https://issues.chromium.org/40059358</a></p>
<p>In this code <a href="https://chromium-review.googlesource.com/c/chromium/src/+/3611826/4/third_party/blink/renderer/core/editing/serializers/serialization.cc#906" data-b-widget="url" data-b-original-href="https://chromium-review.googlesource.com/c/chromium/src/+/3611826/4/third_party/blink/renderer/core/editing/serializers/serialization.cc#906" data-b-redirected-href="https://www.google.com/url?q=https://chromium-review.googlesource.com/c/chromium/src/%2B/3611826/4/third_party/blink/renderer/core/editing/serializers/serialization.cc%23906&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2hSJWIhuAagjdwfVWNdAX9">https://chromium-review.googlesource.com/c/chromium/src/+/3611826/4/third_party/blink/renderer/core/editing/serializers/serialization.cc#906</a>, sanitization is performed only during the initial stage but does not monitor or lock elements after they are inserted into the DOM. The <code>body-&gt;appendChild(fragment)</code> function allows subsequent markup modifications. A Mutation Observer can inject a payload after sanitization is complete, enabling Cross-Site Scripting (XSS).</p>
<p>Only the payload <code>&lt;img src=x onerror=alert(1)&gt;</code> is successfully injected and executed.</p>
<p>The payloads <code>&lt;svg onload=alert()&gt;</code> and <code>&lt;script&gt;alert()&lt;/script&gt;</code> will not execute in Chrome.</p>
<p>This vulnerability only affects Chromium-based browsers. In Firefox, the exploit does not execute at all.</p>

<p><strong>Recommended Fixes</strong></p>
<ul>
<li>Disable MutationObserver on sanitized elements.</li>
<li>Use Trusted Types to restrict innerHTML.</li>
<li>Re-sanitize elements whenever they are modified in the DOM</li>
</ul>
<p><strong>NOTE</strong>
This only occurs in Chromium-based browsers and does not work in Firefox.</p>
