VULNERABILITY DETAILS<br><br>Chrome has previously gated some JavaScript APIs (submitForm, e.g.) in PDFium behind user gestures. The remaining APIs allow a different kind of attack, though. <br><br>It is possible to create a believable malicious PDF document that<br><br>1. changes its displayed content with time (while the file stays the same)<br>2. displays different content to different people<br><br>In the first scenario, an attacker can get the victim to agree to something, while later misrepresenting what the victim agreed to. In the second scenario, an attacker can leverage a &quot;confused deputy&quot; to defraud a third party.<br><br>To be clear, this is not a &quot;bug&quot; in PDFium, i.e., this is not a problem that Google created. It is a problem with the PDF spec. At the same time, Google could take measures to protect the user against this kind of attack. A possibility would be to notify the user that a PDF document executes JavaScript upon opening. <br><br>Would you like to treat this as a security issue?<br><br><br>VERSION<br>Chrome Version: 133.0.6943.99 (Official Build) (64-bit)<br>Operating System: does not matter<br><br>REPRODUCTION CASE<br><br>Attached.<br><br>CREDIT INFORMATION<br>Externally reported security bugs may appear in Chrome release notes.
