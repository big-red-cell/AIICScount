<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<hr>
<h3><strong>Summary</strong></h3>
<p><strong>Title:</strong> Forced Automatic Download via  &amp;  Click Event Manipulation in Chrome</p>
<p><strong>Bug Type:</strong> Forced Download / Drive-by Download / UI Spoofing</p>
<p>A vulnerability in Google Chrome allows an attacker to force a file download without explicit user consent by abusing the <code>&lt;details&gt;</code> and <code>&lt;summary&gt;</code> HTML elements along with JavaScript event manipulation. This issue can be exploited for drive-by downloads, leading to potential malware infections, phishing attacks, and unauthorized file execution.</p>
<hr>
<hr>
<h3><strong>Tested Environments</strong></h3>
<ul>
<li><strong>Chrome Version:</strong> [Version 128.0.6613.86 (Official Build) (64-bit)]</li>
<li><strong>Operating System:</strong> [Windows 10 Pro (64-bit)]</li>
<li><strong>Incognito Mode:</strong> [No]</li>
</ul>
<hr>

<ol>
<li>In the PoC video, focus on <strong>Enhanced Protection</strong> and <strong>Privacy and Security</strong> settings.</li>
<li>Create an HTML file with the following code:</li>
</ol>

        &lt;<span class="stx-keyword">video</span> width=<span class="stx-string">&quot;640&quot;</span> height=<span class="stx-string">&quot;360&quot;</span> controls autoplay muted loop&gt;

<hr>
<h3><strong>Expected Behavior</strong></h3>
<p>Chrome should require explicit user interaction (e.g., a direct click on a download link with a known file extension like <code>.exe</code>) before initiating any file downloads.</p>
<hr>
<h3><strong>Actual Behavior</strong></h3>
<p>By embedding a file download link inside <code>&lt;details&gt;</code> and <code>&lt;summary&gt;</code>, combined with <code>onclick=&quot;this.click()&quot;</code>, an attacker can force a download when the user interacts with the page. The <code>&lt;video&gt;</code> tag might also contribute to unintended behavior by executing scripts or autoplaying content without user consent.</p>

<h4>Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<hr>
<h3><strong>Impact</strong></h3>
<ul>
<li><strong>Drive-by Download Attack</strong> – Users unknowingly download and execute malicious files.</li>
<li><strong>Phishing Attack</strong> – Attackers can host fake Google-like domains to trick users into executing malware.</li>
<li><strong>Security Bypass</strong> – Chrome&#39;s built-in protection mechanisms against forced downloads are circumvented.</li>
<li><strong>Possible Sandbox Escape</strong> – If the behavior allows execution without security warnings, it may indicate a deeper flaw in Chrome’s security model.</li>
</ul>
<p>This issue demonstrates a <strong>critical security bypass vulnerability</strong> in Google Chrome’s <strong>Enhanced Protection</strong> and <strong>Privacy and Security</strong> settings. Despite these safeguards being explicitly designed to <strong>block malicious downloads and pop-ups</strong>, attackers can still:</p>
<ul>
<li><strong>Bypass Security Mechanisms</strong> – The browser fails to enforce its own security policies, allowing unauthorized downloads.</li>
<li><strong>Trigger Forced Malware Downloads</strong> – Users may unknowingly install malware, ransomware, or keyloggers without any manual action.</li>
<li><strong>Exploit Social Engineering</strong> – The unexpected pop-up can trick users into interacting with it, increasing the risk of compromise.</li>
<li><strong>Enable Remote Code Execution (RCE) Vectors</strong> – If the <code>.exe</code> file is executed, attackers could gain complete control over the system.</li>
<li><strong>Reduce Trust in Browser Security</strong> – Users relying on Chrome’s security features may assume they are protected, when in reality, they remain vulnerable.</li>
</ul>

<p>I think this is working as intended. exe files are allowed to be silently downloaded with a user gesture [1], unlike other file types such as dll which are treated as dangerous because it can be injected into an executable in the same directory [2]. cc drubery to correct me if I&#39;m wrong, please.</p>
<p>Safe Browsing Enhanced Protection enables additional checks/scans of downloads, but doesn&#39;t change the default behavior of allowing exe downloads without a prompt.</p>
<p>I&#39;m not sure I understand the claims about bypassing popups and Javascript execution settings, since for example popups appear blocked in the video -- but it&#39;d be best to file a separate bug about bypassing settings for popups or Javascript execution, in any case.</p>
