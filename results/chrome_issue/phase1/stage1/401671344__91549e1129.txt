<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>📌 The Problem: Chrome Sandbox Escape via /proc/<span>&lt;PID&gt;</span>/root/bin/sudo Execution
🔍 Technical Details of the Vulnerability
A sandbox escape vulnerability was discovered in Google Chrome 134.0.6998.35 on Kali Linux.</p>
<p>🛠 Steps to Reproduce:</p>
<ol>
<li>
<p>Start Chrome without sandboxing (for testing purposes):
bash
google-chrome --no-sandbox --disable-gpu-sandbox --disable-dev-shm-usage --disable-popup-blocking &amp;</p>
</li>
<li>
<p>Find Chrome’s Process ID (PID):
bash
ps aux | grep chrome</p>
</li>
<li>
<p>List Chrome’s root filesystem:
bash
ls -lah /proc/29000/root/bin/</p>
</li>
<li>
<p>Execute a system command inside Chrome’s environment:
bash
/proc/29000/root/bin/ls -lah /proc/29000/root/</p>
</li>
<li>
<p>Privilege Escalation to Root (Sandbox Escape):
bash
sudo /proc/29000/root/bin/sudo id</p>
</li>
</ol>
<p>This confirms full privilege escalation to root (uid=0(root)) from inside Chrome’s process.</p>
<p>1️⃣ Chrome&#39;s PID (ps aux | grep chrome)
2️⃣ Listing /proc/<span>&lt;PID&gt;</span>/root/bin/ (ls -lah /proc/29000/root/bin/)
3️⃣ Executing commands inside Chrome’s root (/proc/29000/root/bin/ls -lah /proc/29000/root/)
4️⃣ Privilege escalation to root (sudo /proc/29000/root/bin/sudo id)</p>
<h4>Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>Any local user on the system who can execute Chrome can potentially gain root privileges.
If combined with a remote code execution (RCE) exploit, this could allow an attacker to fully compromise a system.</p>
<p>✅ Full Root Access → Chrome’s sandbox fails, allowing privilege escalation.
✅ System Compromise → Attackers can modify system files &amp; execute arbitrary commands.
✅ Persistence → The attacker can install rootkits, backdoors, or malware.</p>
