<h1>Problem Description</h1>
<p>A <strong>permission bypass</strong> vulnerability has been found in <strong>Google Chrome</strong>, allowing the <strong>automatic download of executable (.exe) files containing malware</strong> without user consent or notification. This vulnerability occurs when users visit a test page specifically designed to simulate the download of a <strong>malware</strong> file.</p>
<p>The test page used to demonstrate the issue is:<br>
<a href="https://alayershunters.github.io/alayershuntbugbounty/Malware-Web-Download.html" data-b-widget="url" data-b-original-href="https://alayershunters.github.io/alayershuntbugbounty/Malware-Web-Download.html" data-b-redirected-href="https://www.google.com/url?q=https://alayershunters.github.io/alayershuntbugbounty/Malware-Web-Download.html&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw34eKt6mk9bxWD87WQZ5ca1">https://alayershunters.github.io/alayershuntbugbounty/Malware-Web-Download.html</a></p>
<p>On a <strong>fresh installation of Google Chrome</strong> on a <strong>new device</strong> or inside a <strong>Windows Sandbox</strong> (simulating a new device), once the page is loaded, an <strong>.exe</strong> file containing malware starts downloading automatically without any warning or user confirmation. The user is not given an option to stop or assess the potential harm of the file being downloaded. This is highly dangerous, as <strong>.exe files</strong> can contain malware that can steal personal data, damage the device, or provide unauthorized access to the system.</p>
<p>However, when tested in <strong>Incognito mode</strong>, <strong>Chrome</strong> requests <strong>user confirmation</strong> before proceeding with the download of the executable file, showing a difference in behavior between normal and incognito modes.</p>
<p>In comparison, other browsers such as <strong>Opera</strong>, <strong>Brave</strong>, and <strong>Microsoft Edge</strong> have stricter protections in place. These browsers do not allow the automatic download of executable (.exe) files, whether in normal or incognito mode. They request user confirmation or display a warning when attempting to download executable files, providing better protection against potentially harmful files.</p>
<p><strong>Expected Behavior:</strong></p>
<ul>
<li><strong>Google Chrome</strong> should prompt the <strong>user for confirmation</strong> or display a <strong>clear warning</strong> before downloading executable (.exe) files, especially on <strong>new devices</strong> or in <strong>Windows Sandbox</strong>, where users without prior settings could easily fall into automatic downloads without understanding the potential risks.</li>
<li><strong>User consent</strong> should always be obtained for potentially harmful files that could damage the device or steal data. Without this confirmation, users are at a high risk of unknowingly downloading malware or malicious software.</li>
<li>There should be <strong>visual indicators</strong> about the type of file being downloaded, so users can easily recognize that it is an <strong>executable</strong> that could be potentially <strong>harmful</strong>.</li>
<li>Chrome should <strong>validate</strong> and request user confirmation in both <strong>normal and incognito modes</strong>, ensuring consistent protection in both browsing modes and preventing users from downloading malicious files without knowledge or consent.</li>
</ul>
<p>This vulnerability is highly dangerous as it could allow <strong>malware</strong> to be downloaded onto a device without the user&#39;s knowledge, potentially leading to data theft, device damage, or unauthorized access to sensitive information. It is a serious threat to user security and privacy.</p>
<h1>Additional Comments</h1>
<ol>
<li>
<p>It’s important that Chrome improves its handling of executable downloads by adding confirmation steps, especially for users with new installations or in environments like Windows Sandbox.</p>
</li>
<li>
<p>A visual warning should be displayed to inform users that the file being downloaded is an executable and might pose a risk to the system.</p>
</li>
</ol>
