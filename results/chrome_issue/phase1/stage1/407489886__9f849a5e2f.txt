<h3>Report description</h3>
<p>Able To Install Service Workers from Network Overrides, Persist Without DevTools Open</p>
<hr>
<h3>Bug location</h3>
<h4>Where do you want to report your vulnerability?</h4>
<p>Chrome VRP – Report security issues affecting the Chrome browser. <a href="https://bughunters.google.com/about/rules/5745167867576320/chrome-vulnerability-reward-program-rules" data-b-widget="url" data-b-original-href="https://bughunters.google.com/about/rules/5745167867576320/chrome-vulnerability-reward-program-rules" data-b-redirected-href="https://www.google.com/url?q=https://bughunters.google.com/about/rules/5745167867576320/chrome-vulnerability-reward-program-rules&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw31QXnMd5mgu42yXMeOAv3K">See program rules</a></p>
<hr>
<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>Attackers can install local <strong>Service Workers (SW)</strong> on any site using <strong>Chrome DevTools Network Overrides</strong>.</p>
<p>If blocked by <strong>Content Security Policy (CSP)</strong>, such as in the case of <a href="https://accounts.google.com/o/oauth2/v2/auth" data-b-widget="url" data-b-original-href="https://accounts.google.com/o/oauth2/v2/auth" data-b-redirected-href="https://www.google.com/url?q=https://accounts.google.com/o/oauth2/v2/auth&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw239wqPCWh_2lRYsBTHW-uC">https://accounts.google.com/o/oauth2/v2/auth</a> (oauth sign-in), this can be easily bypassed by overriding the CSP headers first, reloading the page, then installing the service worker overrides.</p>
<p>After a successful installation, the content overrides can be disabled, and the SW will continue to function normally without DevTools open. It persists between sessions unless the browser profile is reset or site settings and cookies are cleared every time.</p>
<h3>Attack Scenario</h3>
<ol>
<li>Attacker uses a public/shared PC.</li>
<li>Attacker downloads, copies, or creates necessary attack files.</li>
<li>Attacker installs local service workers on target domains.</li>
<li>Attacker caches prepared local HTML files or scripts.</li>
<li>Attacker disables content overrides and deletes evidence files to remove traces.</li>
<li>Victim uses the public PC.</li>
<li>Victim accesses online services that have been forged by the attacker.</li>
<li>Data is sent to the attacker from a malicious script.</li>
</ol>

<h3>Fix Recommendation</h3>
<p>Block SW registration via DevTools&#39; Content Overrides.</p>

<p>One of the most vulnerable targets is shared PC users (e.g. in schools or public libraries), where an attacker only needs access once to set up their pre-made SW and cache files.</p>
<p>By injecting malicious scripts or forging pages, they can steal private information, hijack account sessions, phishing, and spy on user activities (just a few that I can think of) on any online or HTTPS site.</p>

<p>Hi, thanks for reporting. We appreciate the detailed report!</p>
<p>However, this reported issue, while allowing for local manipulation of website behavior through Service Workers, relies on the intentional use of Chrome Developer Tools&#39; Network Overrides feature. DevTools are designed for local debugging it has the ability to alter network requests, inject scripts, and modify local storage. As this requires direct access to the user&#39;s machine and active use of developer tools, it&#39;s considered a misuse of development features rather than a security vulnerability in the Service Worker implementation itself. Hence, I am closing this bug as WAI, please feel free to reopen if you disagree. And thanks again for the detailed report!</p>
