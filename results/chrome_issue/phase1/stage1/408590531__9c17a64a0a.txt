<h1>🐞 Bug Bounty Report: Chromium — Cache Poisoning via Service Worker Overwrite (No User Interaction)</h1>
<hr>
<h2>📌 Title:</h2>
<p><strong>Chromium: Service Worker Hijack Enables Local Cache Poisoning of Same-Origin Resources</strong></p>
<hr>
<h2>🎯 Summary:</h2>
<p>An attacker can <strong>overwrite cached content</strong> of a same-origin resource by:</p>
<ol>
<li>Forcing the browser to cache a benign version of the file.</li>
<li>Registering a malicious <strong>Service Worker</strong> on the same origin.</li>
<li>Hijacking future requests and returning <strong>forged content</strong>, making it seem <strong>authentic and trusted</strong>.</li>
</ol>
<p>This is a form of <strong>persistent cache poisoning</strong> that doesn&#39;t trigger any browser warnings. A user who visits <code>victim.html</code> afterward gets <strong>malicious content</strong> from cache without visiting any malicious site.</p>
<hr>
<h2>🧪 Affected Product:</h2>
<ul>
<li><strong>Browser</strong>: Google Chrome (Chromium)</li>
</ul>

<h2>🛠️ Recommended Fix:</h2>
<ul>
<li>Chromium should prevent <strong>Service Workers from intercepting requests</strong> to cached content that was fetched before the worker was registered.</li>
<li>Add <strong>cache partitioning</strong> or validation based on worker state.</li>
<li>Consider sandboxing access to files not registered within scope.</li>
</ul>

Author: # Bug Bounty Report: Chromium — Service Worker Origin Validation Bypass Leading to Cross-Origin Data Theft

Title
Chromium: Service Worker Origin Validation Bypass Enables Cross-Origin Data Theft

Severity
Critical
Affected Versions
Chrome 134.0.0.0 and all Chromium-based browsers using the same service worker implementation.

Description
A critical vulnerability exists in Chromium's service worker implementation that allows an attacker to bypass origin validation and steal sensitive data from a victim's origin. The vulnerability enables a service worker registered on the attacker's origin to intercept requests to the victim's origin, access sensitive data (cookies, localStorage, sessionStorage, and page content), and exfiltrate this data back to the attacker's origin.
This represents a fundamental security flaw in how service workers handle cross-origin requests, effectively bypassing the same-origin policy, which is a critical security boundary in web browsers.

Impact
This vulnerability has severe security implications:
1. Authentication Bypass:
 - Attackers can steal session cookies and authentication tokens
 - This allows them to impersonate users on the victim's site

2. Sensitive Data Exposure:
 - Personal information, financial data, and other sensitive content can be stolen
 - This could lead to identity theft or financial fraud

3. Security Control Bypass:
 - The same-origin policy, a fundamental security boundary, is completely bypassed
 - CSRF protections can be circumvented

4. Persistent Surveillance:
 - Service workers persist across browser sessions
 - This allows for long-term monitoring of user activity

5. Wide Impact:
 - Affects all Chromium-based browsers (Chrome, Edge, Opera, etc.)
 - Any website could be vulnerable if a user has visited an attacker's site

Root Cause
The vulnerability exists in Chromium's service worker implementation, specifically in how it validates origins and handles cross-origin requests. The key issues are:

1 . Origin Validation Failure:
 - The service worker's origin validation doesn't properly check if the service worker has permission to intercept requests to other origins
 - This allows a service worker from one origin to intercept requests to another origin

2. Cross-Origin Communication:
 - The service worker can send intercepted data back to the attacker's origin
 - This bypasses CORS restrictions that would normally prevent cross-origin data access

3. Storage Access:

 - The service worker can access sensitive data from the victim's origin
 - This includes cookies, localStorage, and sessionStorage data

Proof of Concept
The proof of concept demonstrates that a service worker registered on the attacker's origin (http://localhost:8000) can intercept requests to the victim's origin (http://localhost:8001), access sensitive data, and exfiltrate this data back to the attacker's origin.

When the victim visits their own site after the attacker has set up the service worker, the service worker intercepts the request, captures the response (which includes sensitive data), and sends it to the attacker's server.

The attacker can then view the stolen data by visiting http://localhost:8000/stolen.

Recommended Fix
To fix this vulnerability, Chromium should:

1. Strengthen Origin Validation:
 - Ensure that service workers can only intercept requests to their own origin
 - Implement strict checks to prevent cross-origin interception

2. Restrict Cross-Origin Communication:
 - Prevent service workers from sending data to origins other than their own
 - Enforce CORS restrictions for service worker communication

3. Enhance Data Access Controls:
 - Implement stricter controls on how service workers access sensitive data
 - Ensure that same-origin policy is enforced for all data access

4. Add Security Headers:
 - Implement headers to prevent service worker scope manipulation
 - Consider adding a Service-Worker-Allowed header to limit service worker scope

Additional Notes
This vulnerability represents a fundamental security flaw in Chromium's service worker implementation. The impact is severe, and the exploitation is relatively straightforward. 

The vulnerability affects all Chromium-based browsers and could lead to the theft of sensitive data from any website.
This is a 0-day vulnerability that should be addressed immediately to protect users from potential data theft and privacy violations.

class RequestHandler(BaseHTTPRequestHandler):
    def _set_cors_headers(self):
        self.send_header('Access-Control-Allow-Origin', '*')
        self.send_header('Access-Control-Allow-Methods', 'GET, POST, OPTIONS')
        self.send_header('Access-Control-Allow-Headers', 'Content-Type')
        self.send_header('Access-Control-Allow-Credentials', 'true')

    def do_OPTIONS(self):
        self.send_response(200)
        self._set_cors_headers()
        self.end_headers()

    def do_GET(self):
        if self.path == '/':
            self.send_response(200)
            self.send_header('Content-Type', 'text/html')
            self.end_headers()
            with open('index.html', 'rb') as file:
                self.wfile.write(file.read())
        elif self.path == '/sw.js':
            self.send_response(200)
            self.send_header('Content-Type', 'application/javascript')
            self.end_headers()
            with open('sw.js', 'rb') as file:
                self.wfile.write(file.read())
        elif self.path == '/stolen':
            self.send_response(200)
            self.send_header('Content-Type', 'text/html')

from http.server import HTTPServer, BaseHTTPRequestHandler
import json

class RequestHandler(BaseHTTPRequestHandler):
    def _set_cors_headers(self):
        self.send_header('Access-Control-Allow-Origin', '*')
        self.send_header('Access-Control-Allow-Methods', 'GET, POST, OPTIONS')
        self.send_header('Access-Control-Allow-Headers', 'Content-Type')
        self.send_header('Access-Control-Allow-Credentials', 'true')
        self.send_header('Service-Worker-Allowed', '/')
    
    def do_OPTIONS(self):
        self.send_response(200)
        self._set_cors_headers()
        self.end_headers()
    
    def do_GET(self):
        if self.path == '/':
            self.send_response(200)
            self.send_header('Content-type', 'text/html')
            self.end_headers()
            with open('index.html', 'rb') as f:
                self.wfile.write(f.read())
        elif self.path == '/sw.js':
            self.send_response(200)
            self.send_header('Content-type', 'application/javascript')
            self._set_cors_headers()
            self.end_headers()
            with open('sw.js', 'rb') as f:
                self.wfile.write(f.read())
        else:
            self.send_response(404)
            self.end_headers()

def run_server():
    server_address = ('', 8001)
    httpd = HTTPServer(server_address, RequestHandler)
    print('Victim server running on http://localhost:8001')
    httpd.serve_forever()

if __name__ == '__main__':
    run_server()
