are normally made public once a fix has been widely deployed.<br><br>-------------------------<br><br>VULNERABILITY DETAILS<br>I discovered a security issue in Google Chrome related to the handling of stored login credentials. Specifically, the Login Data SQLite file in the user profile directory (C:\Users\[Username]\AppData\Local\Google\Chrome\User Data\Default) contains all saved usernames and passwords in encrypted form, but they can be decrypted without requiring user interaction or elevated privileges using Windows DPAPI.<br><br>I developed a C# class that demonstrates this behavior by:<br><br>Accessing the Login Data file.<br><br>Reading the encrypted credentials.<br><br>Decrypting them using the current user’s context (via CryptUnprotectData).<br><br>Displaying the results in plain text, including both usernames and passwords.<br><br>This poses a risk if malware or a malicious actor has local access to the user session, as they can extract and decrypt Chrome-stored credentials without any prompt, making this a potential local privilege misuse or sensitive data exposure issue.<br><br>VERSION<br>Chrome Version: 123.0.6312.106 (Stable)<br>Operating System: Windows 10 Pro (Build 19045.4170)<br><br>REPRODUCTION CASE<br>You can reproduce this issue by:<br><br>Navigating to:<br>C:\Users\[Username]\AppData\Local\Google\Chrome\User Data\Default\Login Data<br><br>Using a C# class to:<br>-Open the SQLite database.<br>-Query the logins table for origin_url, username_value, and password_value.<br>-Decrypt password_value using the CryptUnprotectData Windows API.<br>-Display results.<br>I can provide the C# source code as a demonstration file upon request. Please let me know if you would like the script included directly or shared through another channel.<br><br>CREDIT INFORMATION<br>Externally reported security bugs may appear in Chrome release notes.
