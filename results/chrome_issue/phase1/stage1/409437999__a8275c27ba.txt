The Content-Security-Policy header applies to the individual page served by the index.php. The directives limit where this page may load resources from. As far as I understand, those directives do not apply to the SW installed by that page, so the fetch() inside the SW succeeds.<br><br><a href="https://www.google.com/url?q=https://mango-automatic-monitor.glitch.me/&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3T_n6bbkIs4Qfg4XhMxg1I" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="https://mango-automatic-monitor.glitch.me/" data-b-redirected-href="https://www.google.com/url?q=https://mango-automatic-monitor.glitch.me/&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3T_n6bbkIs4Qfg4XhMxg1I">https://mango-automatic-monitor.glitch.me/</a> has a live version that approximates the CSP. As far as I can tell, both Firefox and Chrome install the service worker from that site, and in both the cross-origin fetch() succeeds and logs an opaque response.<br><br>So as far as I can tell, there isn&#39;t any CSP bypass happening. <br>
