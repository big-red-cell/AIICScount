<h1>Steps to reproduce the problem</h1>
<p>Quick Repro Steps (Chrome)
Create Victim Server (port 8000)</p>
<p>Set cookie in /protected.html: SameSite=Strict</p>
<p>Add /relay.html that listens for postMessage and redirects to /protected.html.</p>
<p>Create Attacker Server (port 8001)</p>
<p>Serve /attacker.html that:</p>
<p>Opens <a href="http://localhost:8000/relay.html" data-b-widget="url" data-b-original-href="http://localhost:8000/relay.html" data-b-redirected-href="https://www.google.com/url?q=http://localhost:8000/relay.html&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw09F19WBZr9a0WKaLYgClGI">http://localhost:8000/relay.html</a> in a new tab</p>

<p>bash
Copy
Edit
cd victim &amp;&amp; python3 server.py
cd attacker &amp;&amp; python3 server.py
Open Exploit:
Visit <a href="http://localhost:8001/attacker.html" data-b-widget="url" data-b-original-href="http://localhost:8001/attacker.html" data-b-redirected-href="https://www.google.com/url?q=http://localhost:8001/attacker.html&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw233VGyP0MOcDEj7Xht-Ugz">http://localhost:8001/attacker.html</a> in Chrome.</p>
<h1>Problem Description</h1>
<p>In Google Chrome (latest builds), it is possible to bypass the SameSite=Strict cookie policy when using a combination of:
window.open() (cross-origin tab)</p>
<p>postMessage() communication
Redirect inside the opened tab
This results in the SameSite=Strict cookie being sent in what is effectively a cross-site request, violating the core intent of the SameSite attribute.</p>
<h1>Summary</h1>
<p>Bypass of SameSite=Strict via window.opener and postMessage-based redirect</p>
