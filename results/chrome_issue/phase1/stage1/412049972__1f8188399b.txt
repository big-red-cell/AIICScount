<h1>Problem Description</h1>
<p>The Linux version of Google Chrome appears to bypass the normal redirect flow for Facebook’s linkshim mechanism (l.php?u=), immediately redirecting to the untrusted destination without waiting for the interstitial page load or server response.
This behavior introduces a browser-specific open redirect bypass, where server-side checks (like Facebook&#39;s linkshim system which blocks malicious links or shows warnings) are skipped entirely.
Expected behavior:
Chrome should wait for the redirect response from Facebook servers, showing the interstitial warning page before redirecting to external links.
Actual behavior on Linux Chrome:
Chrome automatically preloads or directly navigates to the destination (evil.com) without rendering Facebook’s intermediate page, making it easier for attackers to exploit linkshim URLs in phishing/social engineering.
This issue appears only in Linux, as the Windows version of Chrome behaves correctly and renders the warning as expected.</p>
<h1>Additional Comments</h1>
<p>This issue affects how Chrome (Linux) handles Facebook&#39;s redirection system l.php?u=.... Instead of waiting for Facebook to render the intermediate warning page, Chrome jumps straight to the target destination (e.g., evil.com). This breaks intended user protections and introduces phishing/open redirect vectors specific to Chrome on Linux.
Other platforms like Chrome on Windows behave correctly, waiting for the interstitial. This makes it clear the issue is platform-dependent, not site-based.</p>
