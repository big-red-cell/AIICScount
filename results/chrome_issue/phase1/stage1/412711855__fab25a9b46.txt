<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>I discovered a behavior in Chrome where the browser unexpectedly allows execution of javascript: URIs from the address bar under specific conditions. Normally, Chrome blocks execution of javascript: when typed directly into the address bar as a security measure. However, this restriction appears to be bypassed after a user performs a search. To reproduce: open a new Chrome tab, type any search term (e.g., &quot;test&quot;) in the address bar, and press Enter. Once the search results are displayed, manually replace the URL in the address bar with javascript:alert(0) and press Enter. Instead of being blocked, the browser immediately executes the alert, indicating that the usual restrictions are not being enforced in this flow. This behavior may allow social engineering or phishing-style attacks where users are tricked into entering JavaScript payloads, assuming the browser will block them. It also suggests a potential inconsistency in Chrome’s security model related to user activation and script execution. I believe this could be considered a security concern and warrants further investigation.</p>
<h4>Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>Any user can unintentionally trigger JavaScript execution from the address bar after a search, which violates Chrome’s expected URI restrictions. An attacker could exploit this by socially engineering a victim into typing  a javascript: payload into the address bar, assuming Chrome will block it. Once executed, it could lead to user confusion, browser UI spoofing, or chaining with other vulnerabilities for more severe attacks. This behavior undermines user trust in Chrome&#39;s security model and could serve as a primitive in larger exploit chains.</p>
