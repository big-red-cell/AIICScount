<p>Vulnerability Analysis</p>
<ol>
<li>Leaking heap address</li>
</ol>
<p>let real_obj = {hidden: 0x1337}; // The heap object you really want to leak
let proxy = new Proxy(float_arr, {
get: function(target, prop, receiver) {
if (prop === &#39;0&#39;) {
// Return the real object
return real_obj;
}
return target[prop];
}
});</p>
<p>• The code successfully leaks the reference of the heap object real_obj from the float_arr array through Proxy and type confusion techniques.
• This method uses the proxy mechanism to make the first element of the array accessed, and the returned element is not the original array element, but another heap object, so that the attacker can indirectly obtain the memory address of the object.
2. Address leakage</p>
<p>let leaked = float_arr[0]; // Directly access the first element of the proxy object
let leaked_addr = f2i(leaked); // Get the memory address of the heap object</p>
<p>• Using Proxy, the attacker leaked the memory address leaked_addr of the heap object by accessing the first element of the array.
• After converting the object to a memory address through f2i, the attacker can obtain the location of the object in memory.
3. Arbitrary address read and write primitives</p>
<p>let arb_ab = new ArrayBuffer(0x100); // Used for read and write tests
let arb_ta = new Float64Array(arb_ab);</p>
<p>• The attacker constructed an ArrayBuffer and a Float64Array as tools for reading and writing arbitrary addresses.
• By manipulating the address and data in memory, the attacker can read data at any address and even modify the value in any memory.</p>
<ol start="4">
<li>Read the value of an arbitrary address</li>
</ol>
<p>let leak_val = arb_read(leaked_addr);
console.log(&quot;[+] Leaked value from arbitrary address: &quot; + hex(leak_val));</p>
<p>Through the constructed arb_read function, the attacker reads the value of the previously leaked heap address (leaked_addr). This shows that the attacker can obtain the value of any location by reading memory.
5. Write to an arbitrary address</p>
<p>arb_write(test_addr, 0x4141414141414141n);
console.log(&quot;[+] Wrote 0x4141414141414141 to address: &quot; + hex(test_addr));</p>
<p>• Through the constructed arb_write function, the attacker successfully writes a specific value (0x4141414141414141) to the arbitrary memory address test_addr.
• This write operation is usually used to overwrite the contents in memory, such as overwriting function pointers, modifying control flow, or destroying data structures.</p>
<p>Vulnerability Category</p>
<ol>
<li>Type Confusion Vulnerability</li>
</ol>
<p>By confusing Proxy and different data types, attackers can manipulate objects in memory and then obtain and manipulate heap memory addresses. This type of vulnerability is usually a type confusion vulnerability of the V8 engine, which is a common problem in browser memory management.</p>
<ol start="2">
<li>Arbitrary Address Read and Write Vulnerability</li>
</ol>
<p>This vulnerability allows attackers to read and write arbitrary memory addresses. By leaking heap memory addresses and using ArrayBuffer, memory can be read and written at any location. This vulnerability allows attackers to directly manipulate the program&#39;s memory, which may lead to remote code execution (RCE), information leakage, sandbox escape and other serious consequences.</p>
<ol start="3">
<li>Memory Management Vulnerability</li>
</ol>
<p>This vulnerability also involves the management of heap memory. By leaking heap object references, attackers can obtain memory addresses in the heap and further manipulate the contents of the memory. This type of vulnerability may cause program crashes, memory corruption, privilege escalation and other problems.
Hazards of the vulnerability
• Remote code execution (RCE): By modifying function pointers in memory, overwriting control flow, etc., attackers can execute malicious code.
• Privilege escalation: By modifying heap objects, attackers may bypass sandboxes or other permission control mechanisms and obtain higher permissions.
• Information leakage: Attackers can read sensitive memory contents and leak confidential data in memory.
• Sandbox escape: If the vulnerability occurs in a sandbox environment, attackers can break through the isolation of the sandbox through arbitrary memory write operations and access and modify resources that should not be accessed.
Summary
This vulnerability is a type confusion vulnerability of the V8 engine, which allows attackers to leak heap addresses through memory access primitives (arbitrary address read and write) and perform malicious operations by manipulating memory contents. This is a serious memory management vulnerability that can lead to security issues such as remote code execution, information leakage, sandbox bypass and privilege escalation.</p>
