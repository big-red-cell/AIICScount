<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>The vulnerability is a Cross-Site Scripting (XSS) issue that allows an attacker to inject and execute arbitrary JavaScript code in the context of the page. Specifically, the vulnerability arises from improper handling of user input, where the eval() function is used without sanitizing inputs. This enables an attacker to run JavaScript directly from the browser&#39;s developer console, allowing them to alter the page content, steal sensitive data, or perform other malicious actions.</p>
<p>The script I ran is, javascript:eval(&#39;document.body.innerHTML=&quot;&lt;div style=&#39;position: fixed; top: 0; left: 0; width: 100%; height: 100%; background-color: rgba(0,0,0,0.7); color: white; font-size: 50px; display: flex; justify-content: center; align-items: center;&#39;&gt;Hacked! Your page has been compromised.<span>&lt;/div&gt;</span>&quot;&#39;);</p>
<p>This code, when executed via the browser console, injects an overlay message onto the page, simulating a &quot;hack&quot; scenario. This shows that an attacker can inject arbitrary content and execute malicious code.</p>
<h4>Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>Who Can Exploit the Vulnerability?</p>
<p>Attackers with access to the browser&#39;s developer console. This could be any user on the website (even a non-privileged user) who knows how to open the browser&#39;s console.
Malicious Actors could exploit this vulnerability to deliver an attack to other users visiting the website, especially if the site is not properly secured or if it lacks protections like Content Security Policies (CSP).
What Do They Gain by Exploiting This Vulnerability?</p>
<p>Arbitrary Code Execution: The attacker can execute JavaScript in the context of the website, meaning they can alter the content of the page, steal cookies, session tokens, or manipulate the site for malicious purposes.
Alter User Experience: The attacker can change the appearance of the website, display misleading content (e.g., fake error messages, &quot;Hacked&quot; warnings), or create confusion among users.
Steal Sensitive Information: By injecting JavaScript, the attacker could steal session cookies, authentication tokens, or other sensitive information if the page is not properly protected (e.g., through HTTPS or CSP).
Perform Phishing Attacks: The attacker can display fake login forms or redirect users to a malicious site to steal credentials.
Potential for Further Exploitation: This vulnerability can be leveraged as part of a broader attack, leading to a larger compromise (e.g., phishing, redirecting to malicious sites, data theft).
Example Scenario: If a user is logged into the website, an attacker could steal session cookies, potentially allowing them to hijack the user&#39;s session and perform actions as if they were the victim.</p>
