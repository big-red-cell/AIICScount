Summary<br>An extension with debugger, tabs, and scripting permissions (no cookies) can execute arbitrary JavaScript using chrome.debugger.sendCommand in Runtime.evaluate, and read document.cookie from a high-value domain like <a href="https://www.google.com" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="https://www.google.com" data-b-redirected-href="https://www.google.com">https://www.google.com</a>.<br>This PoC demonstrates a sandbox escape via debugger, resulting in UXSS and cookie theft, without injecting any content script or requesting explicit host permissions.<br><br>Steps to Reproduce<br>1. Install the attached extension (see manifest.json and background.js).<br>2. Click the extension icon.<br>3. A tab will open to <a href="https://www.google.com" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="https://www.google.com" data-b-redirected-href="https://www.google.com">https://www.google.com</a>.<br>4. The extension attaches a debugger, executes document.cookie, and logs the result.<br><br>Version<br>Google Chrome : 138.0.7183.3 (Official Build) canary (x86_64) <br>OS : MacOS Monterey<br><br>Expected Result<br>Extension should not be able to access cookies from <a href="http://google.com" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="http://google.com" data-b-redirected-href="http://google.com">google.com</a> unless it has explicit permissions.<br><br>Actual Result<br>It retrieves sensitive session cookies like SAPISID, SID, __Secure-1PAPISID, etc.<br><br>Impact<br>This can lead to full account compromise by abusing the retrieved cookies, bypassing user interaction or content script restrictions.
