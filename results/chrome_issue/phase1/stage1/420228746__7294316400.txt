<h1>Problem Description</h1>
<p>Product: Chrome Beta for Android
Version: 137.0.7151.44
Platform: Android
Severity: High (User Consent Bypass + Stealth Download Risk)</p>
<p>Summary of the Issue:</p>
<p>During testing on Chrome Beta version 137.0.7151.44 for Android, I identified a pair of related security flaws that can be exploited together:</p>
<ol>
<li>An APK file can be downloaded automatically without any visible user confirmation or interaction.</li>
<li>The download proceeds in the background while the legitimate Chrome download notification is visually hidden using overlay elements embedded in the webpage.</li>
</ol>
<p>This behavior enables a malicious webpage to simulate normal interactions (e.g., claiming a prize) while silently initiating and hiding a file download process from the user.</p>
<p>Impact:</p>
<ul>
<li>APK files can be delivered to the device without user awareness or consent.</li>
<li>The browser’s built-in download protections requiring a user gesture are bypassed.</li>
<li>Chrome’s actual system notification for the download is still triggered, but intentionally concealed through in-page UI manipulation.</li>
<li>This creates a path for silent file distribution, potentially leading to social engineering or malicious installation.</li>
<li>The behavior could degrade trust in Chrome’s download safety and notification system.</li>
</ul>
<p>Severity Justification:</p>
<p>This vulnerability warrants a High severity rating because it circumvents Chrome Android’s user gesture enforcement for downloads — a fundamental security mechanism designed to prevent unsolicited file transfers.</p>
<p>Additionally, by covering up the Chrome download notification using in-page HTML elements, the exploit reduces the chance of user detection. The combined effect enables a stealthy method to deliver files that users may install unknowingly.</p>
<h1>Summary</h1>
<p>APK auto-download without consent  notification spoofing in Chrome Beta Android 137.0.7151.44</p>
