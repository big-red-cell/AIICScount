I have identified a bypass of Chrome browser SOP policies. An attacker cannot change the location.hash via cross-site because of your SOP policy: `Uncaught SecurityError: Failed to set a named property &#39;hash&#39; on &#39;Location&#39;: Blocked a frame with origin &quot;<a href="https://www.google.com/url?q=https://example.com&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw32_WZYagLX5XuNCw35Xw40" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="https://example.com" data-b-redirected-href="https://www.google.com/url?q=https://example.com&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw32_WZYagLX5XuNCw35Xw40">https://example.com</a>&quot; from accessing a cross-origin frame`.<br><br>The bug is that if an attacker has control over the location of a window if he creates the reference with window.open, he can change the location completely but not access its attributes by SOP policies. For example an attacker from <a href="https://www.google.com/url?q=http://example.com&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2vKt98IJgycdV1jQk_Xbaj" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="http://example.com" data-b-redirected-href="https://www.google.com/url?q=http://example.com&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2vKt98IJgycdV1jQk_Xbaj">example.com</a> could do: `var x = window.open(&quot;<a href="https://www.google.com/url?q=http://localhost:5050/test.html%23test&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1C5oeC06t0RwT_24aC6kwq" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="http://localhost:5050/test.html#test" data-b-redirected-href="https://www.google.com/url?q=http://localhost:5050/test.html%23test&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1C5oeC06t0RwT_24aC6kwq">http://localhost:5050/test.html#test</a>&quot;); setTimeout(()=&gt;{x.location = &quot;<a href="https://www.google.com/url?q=http://evil.com&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3reQLcKtrIIiGg1kHgnNKP" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="http://evil.com" data-b-redirected-href="https://www.google.com/url?q=http://evil.com&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3reQLcKtrIIiGg1kHgnNKP">http://evil.com</a>&quot;},2000)`<br><br>The problem is that changing the location.hash does not reload the page as opposed to for example changing the location.search. This allows an attacker to modify the page to the same page he opened but modifying the hash and thus modifying location.hash cross-site by bypassing the browser&#39;s SOP policies.<br><br>This can lead to numerous Cross-Site-Scripting attacks in which the location.hash is evaluated in DOM and then used, assuming that it cannot be cross-site modified.<br><br>To reproduce the bug I am going to prepare a PoC that evaluates the location.hash value in DOM to prevent XSS attacks and then uses it after certain conditions. Although it depends on the loading time of the browser an attacker could program a simple script in JS to open and close the window and change the hash every x time until it exploits the XSS.<br><br>VERSION<br>Chrome Version: 137.0.7151.41 | all versions<br>Operating System: Mac OS (arm64)<br><br>REPRODUCTION CASE<br>1. Host the file `poc.html` and open a python server on port `5050`.<br>2. open a cross-site domain (for example `<a href="https://www.google.com/url?q=http://example.com&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2vKt98IJgycdV1jQk_Xbaj" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="http://example.com" data-b-redirected-href="https://www.google.com/url?q=http://example.com&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2vKt98IJgycdV1jQk_Xbaj">example.com</a>`) and execute `var x = window.open(&quot;<a href="https://www.google.com/url?q=http://localhost:5050/poc.html%23test&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1WtcGGLIiBB2OZt1oeVxe8" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="http://localhost:5050/poc.html#test" data-b-redirected-href="https://www.google.com/url?q=http://localhost:5050/poc.html%23test&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1WtcGGLIiBB2OZt1oeVxe8">http://localhost:5050/poc.html#test</a>&quot;); setTimeout(()=&gt;{x.location = &quot;<a href="https://www.google.com/url?q=http://localhost:5050/poc.html%23alert(1)&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0YuruZxsw0xlxaCaZk4HvD" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="http://localhost:5050/poc.html#alert(1)" data-b-redirected-href="https://www.google.com/url?q=http://localhost:5050/poc.html%23alert(1)&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0YuruZxsw0xlxaCaZk4HvD">http://localhost:5050/poc.html#alert(1)</a>&quot;},2000)`<br>3.
