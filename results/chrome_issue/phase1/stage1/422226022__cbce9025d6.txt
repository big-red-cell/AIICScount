<h1>Steps to reproduce the problem</h1>
<p>Open the PoC page in Chrome: <a href="https://precious-concha-73cd14.netlify.app/sandboxbypass.html" data-b-widget="url" data-b-original-href="https://precious-concha-73cd14.netlify.app/sandboxbypass.html" data-b-redirected-href="https://www.google.com/url?q=https://precious-concha-73cd14.netlify.app/sandboxbypass.html&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1CmEpDw8LYVqIwC5EtDbDi">https://precious-concha-73cd14.netlify.app/sandboxbypass.html</a></p>
<p>Observe an alert popup showing:
&quot;Iframe sent message: script executed&quot;</p>
<p>This indicates the script inside the sandboxed iframe ran successfully despite the sandbox restrictions.</p>
<p>The attack chain relies on iframe navigation combined with history.back() to reuse the srcdoc content allowing script execution.</p>
<h1>Problem Description</h1>
<p>An iframe is created with the attribute sandbox=&quot;allow-scripts&quot;.</p>
<p>The iframe&#39;s srcdoc attribute is set to HTML content that includes an inline <span>&lt;script&gt;</span> which communicates with the parent page via postMessage.</p>
<p>After the iframe loads the srcdoc content, the iframe is navigated to about:blank via location.replace.</p>
<p>Immediately after, history.back() is called, which restores the iframe to the previous srcdoc history entry.</p>
<p>Due to Chrome&#39;s handling of history and policy container reuse, the inline script inside the srcdoc is executed despite the sandbox restrictions.</p>
<p>This results in JavaScript running inside a sandboxed iframe that should have disallowed such execution.</p>

<p>Expected Behavior:
The sandbox=&quot;allow-scripts&quot; attribute should prevent any inline script execution or script injection inside the iframe.</p>
<p>Navigations and history operations should not restore iframe content in a way that allows script execution bypassing sandbox restrictions.</p>
<p>Additional Notes:
This vulnerability can lead to CSP bypass in complex scenarios where policies rely on sandbox attribute restrictions.</p>
<p>This also represents a broader class of iframe navigation and history manipulation vulnerabilities that undermine browser security policies.</p>
<p>The issue is specific to Chrome&#39;s handling of iframe history entries and srcdoc content.</p>
