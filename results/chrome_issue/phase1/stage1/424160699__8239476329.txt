### Report description


Google Chrome bypasses two-factor authentication (2FA) for Gmail when users previously logged in on different devices


---

### Bug location


#### Where do you want to report your vulnerability?

Chrome VRP – Report security issues affecting the Chrome browser. [See program rules](https://bughunters.google.com/about/rules/5745167867576320/chrome-vulnerability-reward-program-rules)


---

### The problem


#### Please describe the technical details of the vulnerability


Technical Details:
- Authentication Flow Bypass: Chrome saves login information that stays active longer than it should
- Session Persistence: Previous Chrome logins skip 2FA checks on next access
- Security Code Fallback: System accepts simple security codes instead of requiring full 2FA process
- Multi-Device Risk: Problem happens across multiple devices with Chrome sync enabled

Reproduction Steps:
1. Login to Gmail with 2FA enabled on Chrome browser
2. Complete full 2FA authentication (password + 2FA method)
3. Close browser/restart system
4. Try to access Gmail again
5. Expected: Full 2FA authentication required
6. Actual: Only security code needed, 2FA skipped


#### Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so

Primary Impact:
- 2FA Security Model Compromised: Makes two-factor authentication useless
- Unauthorized Account Access: Attackers can access accounts without proper verification
- Multi-Device Exposure: Risk increases across all synced Chrome browsers

Affected Users:
- Gmail users with 2FA enabled using Chrome browser
- Business Google Workspace accounts
- Users accessing Gmail from multiple devices

Potential Attack Scenarios:
1. Physical Device Compromise: Unauthorized access to unlocked devices
2. Shared Computer Risk: Public computers keeping login access
3. Device Theft: Stolen devices providing direct Gmail access
4. Enterprise Security: Company devices bypassing security policies

Business Impact:
- Personal data exposure (emails, contacts, documents)
- Company data breach potential
- Legal compliance violations
- Identity theft and privacy violations

Severity Assessment: HIGH
- Affects basic security control (2FA)
- Impacts many users
- Easy to exploit
- Can be automated by attackers

Hi <br>Thank you for the follow-up. Here are the specific technical details that make this a Chrome bug:<br><br>Detailed Issue Description:<br>This vulnerability occurs specifically when:<br>1. User logs inGmail via Chrome on multiple devices (Device A, B, C)<br>2. User logs out from one device (Device A) while remaining logged in on others (Device B, C)<br>3. When attempting to re-login on Device A, the normal flow should require password + SMS 2FA<br>4. However, Chrome allows bypassing SMS 2FA by using security codes generated from other logged-in devices<br><br>Chrome-Specific Problems:<br><br>1. Cross-Device Session Sharing: Chrome sync is inappropriately sharing authentication state between devices, allowing Device B/C to generate security codes that authenticate Device A, bypassing per-device 2FA verification.<br><br>2. Device Trust Inheritance: Chrome treats security codes from other synced devices as equivalent to SMS 2FA for the current device, which violates Google&#39;s per-device authentication policy.<br><br>3. Session State Confusion: Chrome maintains some authentication context even after logout, allowing other synced devices to &quot;vouch&quot; for the logged-out device&#39;s authentication.<br><br>Why This is Chrome&#39;s Bug:<br>- Google&#39;s authentication system expects each device to complete its own 2FA verification<br>- Chrome&#39;s sync mechanism is overriding this security boundary<br>- Other browsers don&#39;t exhibit this cross-device authentication bypass behavior<br>- The issue is in Chrome&#39;s interpretation and handling of multi-device authentication state<br><br>This represents a fundamental flaw in how Chrome handles device-specific authentication requirements in a multi-device sync environment.
