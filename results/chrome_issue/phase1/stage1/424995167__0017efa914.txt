<h1>Problem Description</h1>
<p>📋 Summary:</p>
<p>A vulnerability in Android WebView arises when setSupportMultipleWindows(false) is used, and WebChromeClient.onCreateWindow is not properly implemented. Under these conditions, a malicious website can open a new page using window.open() or a link with target=&quot;_blank&quot;, which loads in the same WebView.</p>
<p>If the original WebView already has access to camera/microphone, the new page inherits the permission context and can immediately access those resources using getUserMedia(), without user interaction or re-prompt.</p>
<p>This creates a permission boundary bypass, violating user expectations and WebView security guarantees</p>
<p>🎯 Expected Behavior:
Opening a new window via window.open() or target=&quot;_blank&quot; should:</p>
<p>Open in a new WebView or context without inherited permissions.</p>
<p>Prompt for new access to sensitive resources (camera/microphone).</p>
<p>❌ Actual Behavior:
New content loads in the same WebView (because setSupportMultipleWindows(false)).</p>
<p>The malicious page inherits camera/mic permissions from the previous context.</p>
<p>No new permission dialog is shown to the user.</p>
<p>🔐 Security Impact:
Permission Bypass: WebView does not enforce origin isolation for sensitive APIs like camera/mic.</p>
<p>User Deception: Users are tricked into giving access to one site, but another malicious one receives it.</p>
<p>💻 Environment Details:</p>
<p>Android version: [Android 10]</p>
<p>Chrome version: [ 137.0.7151.89]</p>
<p>✅ Suggested Fix:
Enforce permission re-prompt or isolation when loading new content via window.open(), regardless of setSupportMultipleWindows setting.</p>
<p>Improve documentation warning about inherited permission context when setSupportMultipleWindows(false) is used.</p>
<h1>Additional Comments</h1>
<p>This issue affects Android apps using WebView with:</p>
<p>setSupportMultipleWindows(false)</p>
<p>JavaScript enabled</p>
<p>No override of WebChromeClient.onCreateWindow()
In this configuration, a malicious site can load new content in the same WebView using window.open() or target=&quot;_blank&quot; and bypass user re-consent for sensitive resources (camera/microphone), resulting in a permission boundary violation.</p>

Author: ea...@gmail.com
Hi Team,<br><br>Thank you for your follow-up.<br><br>To directly answer your question: Yes, when a WebView performs a normal page navigation (e.g., via webView.loadUrl() in Java), permissions granted to Origin 1 (such as camera or microphone access) are automatically inherited by Origin 2 (the new site) without requiring user re-consent.<br><br>Key Points :<br><br>* Permissions are granted per WebView instance, not per origin. Once Origin 1 has access to sensitive resources (e.g., camera), Origin 2, loaded in the same WebView, can access those resources without a new prompt.<br><br>* SetSupportMultipleWindows(false) forces all content to load in the same WebView, allowing permissions granted to one origin to be inherited by another when navigating between websites, which violates origin isolation.<br><br>* This behavior allows a malicious website to inherit permissions granted to a trusted website in the same WebView instance, without any additional user consent.<br><br>Best regards,<br>KGowtham<br>
