<p>4.Actual Result:
The browser crashes with error code STATUS_BREAKPOINT or shows the &quot;Aw, Snap!&quot; page. In some builds, this leads to heap corruption and invalid memory access due to integer overflow in internal text diffing logic.</p>
<p>5.Crash Context:
The crash is triggered due to an unsigned integer overflow in the calculation:
TextDiffRange::Insert(this-&gt;data().length(), data.length());
When offset + new_size exceeds UINT32_MAX, it wraps around silently because CheckValid() is compiled out in release builds (guarded by EXPENSIVE_DCHECKS_ARE_ON()).
The corrupted range is later used during layout or mutation processing, eventually causing out-of-bounds access and crash.</p>
<h1>Problem Description</h1>
<p>Problem Description:
An unsigned integer overflow vulnerability exists in Chromium&#39;s implementation of CharacterData::appendData() in the Blink engine. This flaw allows a crafted webpage to cause heap corruption and crash the browser, potentially leading to further security consequences such as out-of-bounds memory access.</p>
<p>The root cause lies in the handling of large text nodes when appending data. Specifically, when the total size of the text after appending approaches or exceeds 2^32 (i.e., UINT32_MAX), calculations used in internal diffing and layout routines silently wrap due to the lack of bounds checking in release builds.</p>
<p>In particular, the following internal call is unsafe:
SetDataAndUpdate(new_str, TextDiffRange::Insert(this-&gt;data().length(), data.length()), kUpdateFromNonParser);</p>
<p>Here, both this-&gt;data().length() and data.length() are unsigned int values. If their sum overflows 32-bit bounds, the resulting TextDiffRange&#39;s offset + new_size will wrap around, causing an incorrect or invalid memory region to be referenced.</p>
<p>Although there is a function TextDiffRange::CheckValid(...) meant to validate the integrity of the diff ranges, this check is compiled out unless EXPENSIVE_DCHECKS_ARE_ON() is defined. Thus, in production builds, this logic does not catch the overflow, and corrupted state proceeds downstream.</p>
<p>The impact can range from rendering failures to browser crashes, with console output such as:
Aw, Snap! Something went wrong while displaying this webpage.
Error code: STATUS_BREAKPOINT</p>
<p>Or a JS exception like:
Uncaught RangeError: Invalid string length</p>

<p>Integer overflow in CharacterData::appendData leads to heap corruption and browser crash</p>
