This report is a different way to bypass URLBlocklist policy, and download any files we want. The doc for URLBlocklist (<a href="https://www.google.com/url?q=https://chromeenterprise.google/policies/%23URLBlocklist&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2sR459f3A6ktCHG_1vhewR" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="https://chromeenterprise.google/policies/#URLBlocklist" data-b-redirected-href="https://www.google.com/url?q=https://chromeenterprise.google/policies/%23URLBlocklist&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2sR459f3A6ktCHG_1vhewR">https://chromeenterprise.google/policies/#URLBlocklist</a>) says that &quot;this policy does not apply to in-page JavaScript URLs with dynamically loaded data.&quot; The idea is that we use JavaScript to fetch the blocked URLs in DevTools, and then go to the Networks tab to save the response to file.<br><br>Note that you can&#39;t just enter `fetch(&quot;<a href="https://www.google.com/url?q=https://www.attack.com/&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0wMmdprm2B9Yms7ab1MdKD" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="https://www.attack.com/" data-b-redirected-href="https://www.google.com/url?q=https://www.attack.com/&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0wMmdprm2B9Yms7ab1MdKD">https://www.attack.com/</a>&quot;)` in F12 Console, because DevTools Console initiated network requests are not allowed to save. Instead, we can inject a script tag to any webpages that are allowed by our Enterprise policies, and set this tag&#39;s src to the URL that we want to download.<br><br>The impact of this bug is the same as CVE-2023-4904. Namely, this can be abused by users to bypass restrictions on kiosk and download malwares despite the organizations&#39; policies.<br><br>VERSION<br>Chrome Version: 138.0.7204.97 (Official Build) (64-bit) stable<br>Operating System: Windows 11 x64 Build 27881.1000<br><br>REPRODUCTION CASE<br>1. Add https://* to URLBlocklist, and add <a href="https://www.google.com/url?q=https://www.example.org&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1nXmZj-BsxvMcLiYgdAUJx" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="https://www.example.org" data-b-redirected-href="https://www.google.com/url?q=https://www.example.org&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1nXmZj-BsxvMcLiYgdAUJx">https://www.example.org</a> to URLAllowlist<br>2. Navigate to <a href="https://www.google.com/url?q=https://www.example.org&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1nXmZj-BsxvMcLiYgdAUJx" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="https://www.example.org" data-b-redirected-href="https://www.google.com/url?q=https://www.example.org&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1nXmZj-BsxvMcLiYgdAUJx">https://www.example.org</a>. Execute the following: let a = document.createElement(&quot;script&quot;); document.head.append(a); a.src = &quot;<a href="https://www.google.com/url?q=https://ajax.aspnetcdn.com/ajax/jQuery/jquery-3.7.1.min.js&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0Mktff_0zGk47VFUoNH0ep" target="_blank" rel="noopener noreferrer nofollow ugc" data-b-widget="url" data-b-original-href="https://ajax.aspnetcdn.com/ajax/jQuery/jquery-3.7.1.min.js" data-b-redirected-href="https://www.google.com/url?q=https://ajax.aspnetcdn.com/ajax/jQuery/jquery-3.7.1.min.js&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0Mktff_0zGk47VFUoNH0ep">https://ajax.aspnetcdn.com/ajax/jQuery/jquery-3.7.1.min.js</a>&quot;;<br>4. Author: zm...@chromium.org
<p>It&#39;s a similar concept.</p>
<p>The reason you can download jQuery is that you run the JavaScript via DevTool first. In other words, the network request is made by running the Javascript but not click the Save button.</p>
<p>And network requests that are made by Javascript are not covered by the URLBlocklist policy.</p>
<p>Note that URLBlocklist is a navigation control policy but not a network control policy. It means even when it&#39;s set to *, Chrome will still be allowed to make various network requests in many different reasons.</p>
