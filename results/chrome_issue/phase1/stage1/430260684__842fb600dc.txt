<h1>Problem Description</h1>
<p>Summary:
Modern browsers are expected to block automatic top-level redirects initiated from sandboxed iframes (especially cross-origin) unless explicitly triggered by user interaction. However, I have discovered a vulnerability where sandbox=&quot;allow-scripts allow-top-navigation&quot; combined with a data: URI allows window.top.location to be set from within the iframe, triggering a top-level redirect without user gesture.</p>
<p>This bypasses browser-enforced redirect protection and is being actively abused in real-world malvertising campaigns (e.g. by the &quot;Yosec&quot; group) to force user redirection to scam or malware pages.</p>

<p>Sandbox Navigation Policy Bypass via data: iframe</p>

<p>I think you are misreading <a href="https://crbug.com/40053780" target="_blank">crbug.com/40053780</a>#comment18. The bug there was that a cross-origin iframe could <em>itself</em> embed an iframe and set <code>allow-top-navigation</code> on <em>that</em> sub-sub-frame, and then still navigate the top level navigable. Your POC here just has the top level frame directly embed the cross-origin frame and set <code>allow-top-navigation</code> on it. Specifically, the fix CL (<a href="https://crrev.com/c/2688360" data-b-widget="url" data-b-original-href="https://crrev.com/c/2688360" data-b-redirected-href="https://www.google.com/url?q=https://crrev.com/c/2688360&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2h2x1JX0BDc7N1WHmhrtqh">https://crrev.com/c/2688360</a>) states:</p>
<p><code>This CL ensures that sandboxed iframes with &quot;allow-top-navigation&quot; can&#39;t navigate the top frame if their embedder can&#39;t.</code></p>
<p>In your POC/repro steps, the embedder <em>can</em> (as it is the top-level frame). You removed the indirection of a <em>separate</em> cross-origin frame running that script from the original report in <a href="https://issues.chromium.org/issues/40053780" data-b-widget="issue-reference" data-b-issue-id="40053780">Issue 40053780</a>.</p>
