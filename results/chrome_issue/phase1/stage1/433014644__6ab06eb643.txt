<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>The File System Access API’s showSaveFilePicker() method in Google Chrome allows web pages to prompt users to save files with arbitrary file extensions, including executable file types such as .bat, .cmd, or .lnk.</p>
<p>By specifying a double extension (e.g., .txt.bat), an attacker can trick the API into accepting a dangerous executable extension under the guise of a benign file type. When this PoC is run locally (via file://), Chrome does not display any warning or block the save operation, allowing the attacker to silently save executable files on the user’s system.</p>
<p>Double-clicking the saved file on Windows executes the payload (e.g., launching calc.exe), demonstrating that the browser allowed saving a fully executable script without any user alert or safeguard.</p>
<p>When hosted online (via https://), Chrome correctly triggers a security warning to inform the user about potentially dangerous file types. However, this protection is not enforced for local files, creating an inconsistent security posture and a vector for attacks such as ZIP-based phishing, USB-based malware droppers, and social engineering attacks involving local HTML files.</p>
<p>The vulnerability arises because Chrome’s file save dialog and Safe Browsing protections do not apply uniformly to local content, enabling exploitation through trusted local file contexts.</p>
<h4>Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>An attacker who can convince a user to open a malicious HTML file locally (for example, via a phishing email attachment, a ZIP archive, or a USB drive) can exploit this vulnerability to silently save executable files (like .bat scripts) onto the user’s system without any warning from Chrome.</p>
<p>Once saved, these executable files can be run by the user (often unknowingly), allowing the attacker to execute arbitrary code on the victim’s machine. This can lead to malware installation, system compromise, or further attacks.</p>
<p>Because Chrome does not warn or block these saves when run from local files, attackers can leverage trusted local file contexts to bypass typical browser security protections, increasing the risk of successful social engineering, malware delivery, and local privilege escalation attacks.</p>
