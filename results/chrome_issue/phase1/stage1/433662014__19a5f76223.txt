<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>The Picture-in-Picture (PiP) API in Chrome is designed to allow users to watch videos in a floating overlay window while interacting with other content. To protect user privacy and prevent unwanted behavior, browsers provide permission controls that allow users to block or disable PiP on a per-site or global basis.</p>
<p>In Chrome desktop version 138.0.7204.158, there is a flaw in how PiP permissions are enforced:</p>
<p>Although the user has explicitly blocked or disabled Picture-in-Picture permissions for the website or globally, the browser does not properly enforce this restriction at the API level.</p>
<p>The HTMLVideoElement.requestPictureInPicture() method can still be called successfully via JavaScript, and the browser will enter Picture-in-Picture mode regardless of the permission status.</p>
<p>This allows a webpage to programmatically trigger PiP without explicit user consent or interaction beyond an initial gesture, bypassing the permission model.</p>
<p>The issue occurs specifically on desktop Chrome; mobile Chrome versions respect the permission and block the API call as expected.</p>
<p>The vulnerability stems from a gap between the permission management system and the enforcement of the <strong>requestPictureInPicture()</strong> API call in the browser’s implementation.</p>
<p>Potentially, the browser fails to check or respect the permission flag before activating PiP, which contradicts the expected security and privacy model.</p>
<h4>Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p><strong>Impact Analysis</strong>
Who can exploit this vulnerability:
Any website or attacker who can run JavaScript code in a user’s browser (e.g., through a malicious or compromised website, advertising network, or injected scripts).</p>
<p><strong>What they gain:</strong></p>
<p>Ability to forcefully open a Picture-in-Picture (PiP) video window even when the user has blocked or disabled PiP permissions.</p>
<p>This leads to unwanted, intrusive UI elements that can distract or confuse users.</p>
<p>Attackers could use this to create deceptive overlays or trick users into interacting with malicious content disguised within the PiP window.</p>
<p>It undermines user consent and privacy controls, reducing trust in the browser’s permission model.</p>
<p><strong>Additional considerations:</strong></p>
<p>While this vulnerability does not directly lead to data leakage or remote code execution, the forced PiP window could be used in social engineering or UI spoofing attacks.</p>
<p>The persistent or repeated triggering of PiP may degrade user experience or be used in harassment scenarios.</p>
