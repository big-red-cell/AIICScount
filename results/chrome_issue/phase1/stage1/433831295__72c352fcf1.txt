### The problem


#### Please describe the technical details of the vulnerability

1. Issue Summary
The PDFium engine in Chrome executes the deprecated JavaScript API app.mailMsg() embedded within PDF files, which:

Automatically launches the system's default email client (Outlook, Gmail desktop, Thunderbird, etc.) without user interaction

Pre-fills attacker-controlled fields (To, Subject, Body, CC)

Bypasses Chrome's PDF sandbox restrictions by enabling PDF-originated cross-application interactions

This contradicts:

Chromium's security model for PDFs (no documented support for email-related JS APIs)

Google's general principle of requiring user consent for external app interactions

2. Proof of Concept
Malicious PDF Code Snippet:

javascript
app.mailMsg({
  bUI: false, // Silent execution (no UI prompts)
  cTo: "attacker@example.com",
  cSubject: "Urgent: Action Required",
  cMsg: "Click here: http://malicious.link/steal-creds",
  cCc: "exfil@example.com" 
});
Steps to Reproduce:

Open the attached PDF in Chrome with JavaScript enabled (default)

Observe the default email client launches automatically with prefilled phishing content

No user interaction required beyond opening the PDF

3. Expected vs Actual Behavior
Expected	Actual
Chrome should block unsupported/deprecated JS APIs like app.mailMsg()	Chrome executes the API without warnings
PDF JS should be sandboxed without external app access	Email client is launched cross-process
High-risk actions should require user consent	Executes silently when bUI: false


#### Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so

4. Impact
Phishing Acceleration: Attackers can craft PDFs that auto-generate credible-looking emails from the victim's account

Security Boundary Violation: Breaches the PDF sandbox by interacting with mail clients

User Trust Exploitation: Email appears legitimate since it originates from the victim's actual client

Attack Scenario:

Victim opens a booby-trapped PDF (e.g., fake invoice)

Chrome silently opens Outlook/Gmail with:

Prefilled recipient (attacker's email)

Credible subject ("Payment Approved - See Attachment")

Malicious link in body

Victim may click "Send" unintentionally

5. Technical Analysis
Root Cause: PDFium maintains legacy Adobe Acrobat JS compatibility but lacks proper restrictions on high-risk APIs

Sandbox Escape: The API bridges Chrome's renderer process to external applications

No Documentation: Chromium's PDFium docs don't list app.mailMsg() as supported

6. Remediation Suggestions
Immediately disable app.mailMsg() in PDFium

Add user consent dialogs for PDF-triggered external app launches

Audit other legacy JS APIs (e.g., app.launchURL, app.execDialog)
