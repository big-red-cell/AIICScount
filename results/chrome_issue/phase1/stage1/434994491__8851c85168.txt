<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>UI Spoofing in PDFium&#39;s app.response() API allows for Credential Theft Phishing</p>
<p>Observed Result:
Immediately upon opening the document, a dialog box appears. The title of the dialog is &quot;Authentication Required&quot; and the prompt is &quot;This document is protected. Please enter your system password to continue.&quot;. The text input field is a password field (input is masked with dots/asterisks). This dialog appears to be a trusted, native system or browser prompt, with no indication that it is generated by the untrusted PDF content.</p>
<p>Expected (Secure) Result:
The dialog should not be presented as a trusted system prompt. It should be clearly attributed to the PDF document. For example, the title could be &quot;report.pdf says:&quot; or include a clear warning that the request is from an untrusted source. The ability for an untrusted source to create a password-masked input field should be blocked or require explicit user consent.</p>
<h2>Steps to Reproduce:</h2>
<pre><code>Create a PDF document.

Add a JavaScript action to the &quot;Document Will Open&quot; event.

Insert the following JavaScript code into the action:
</code></pre>
<pre><code>app.response({
  cQuestion: &quot;This document is protected. Please enter your system password to continue.&quot;,
  cTitle: &quot;Authentication Required&quot;,
  bPassword: true
});
</code></pre>
<p>Save the PDF file. (A Proof-of-Concept PDF is attached to this report).</p>
<p>Open the PDF file in Google Chrome.</p>
<h4>Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>Impact:
This vulnerability enables a high-fidelity phishing attack for credential theft. A malicious actor can craft a PDF that spoofs a trusted system UI (e.g., Windows Security, Google login, macOS password prompt) to trick a user into entering their password.</p>
<p>Because the bPassword flag makes the input field behave like a real password field, the user is given a strong, false sense of security. The captured password can then be silently exfiltrated using other PDF JavaScript APIs like submitForm(). This constitutes a logical bypass of the browser&#39;s security model by abusing the user&#39;s trust in the native UI.</p>
