<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>🛡️ Technical Details of the Vulnerability (Security Design Concern)
In Google Chrome&#39;s built-in password manager (chrome://settings/passwords), when a user chooses to export all saved passwords, the browser only requires authentication via the operating system (OS) user password (e.g., Windows or macOS password).</p>
<p>Once this OS-level authentication is passed, Chrome allows downloading a CSV file containing all saved credentials in plain text, including:</p>
<p>Domain (URL)</p>
<p>Username</p>
<p>Password</p>
<p>This process poses a real-world security risk, especially in environments where:</p>
<p>Devices are shared (common in India and other regions)</p>
<p>OS passwords are weak, reused, or known to others</p>
<p>Users keep devices unlocked or have auto-login enabled</p>
<p>⚠️ Impact and Security Concern
While this behavior is intended by design, it creates a local attack surface with serious consequences:</p>
<p>Anyone with knowledge of the OS password (e.g., friend, roommate, family member) can access and export a user&#39;s entire password vault.</p>
<p>The CSV file is unencrypted, making it easy to exfiltrate.</p>
<p>OS authentication is not a strong enough gate for such a sensitive action, especially compared to how Google handles sensitive account changes (e.g., requiring Gmail password re-auth or 2FA).</p>
<p>✅ Expected Improvement
To mitigate the risk of local abuse, Google Chrome should:</p>
<p>Require Google account re-authentication (i.e., password or 2FA) in addition to OS authentication before allowing password export.</p>
<p>Optionally, encrypt the exported file with a user-defined passphrase.</p>
<p>Warn the user more strongly about the risks of keeping the CSV file after export.</p>
<h4>Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>🎯 Impact Analysis
Who can exploit it:
Anyone with access to the user’s device who knows or guesses the OS login password (e.g., friends, roommates, family members, or low-privilege insiders), even without knowing the Google account password or 2FA.</p>
<p>What they gain:
They can export all saved passwords in plain text via chrome://settings/passwords, including:</p>
<p>Website URLs (domains)</p>
<p>Usernames</p>
<p>Cleartext passwords</p>
<p>This exposes banking credentials, social media accounts, email logins, and more, all at once — creating serious risks of:</p>
<p>Account takeovers</p>
<p>Identity theft</p>
<p>Financial fraud</p>
<p>Further phishing attacks using harvested data</p>
<p>Since the CSV file is unencrypted, it can be silently copied or exfiltrated without leaving any trace after the OS authentication prompt.</p>
