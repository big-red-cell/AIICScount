<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>Issue: Chrome allows access to UNC network paths via file:// protocol from local HTML files
Steps to Reproduce:</p>
<p>Create local HTML file with video element
Use JavaScript to set video source to file://////[IP_ADDRESS]/[SHARE]/[FILE].mkv
Open HTML file in Chrome
Click to load video</p>
<p>Expected Result: Access blocked due to same-origin policy/CORS restrictions
Actual Result: Video loads and plays from network share without authentication prompts</p>

Author: za...@google.com
Thanks for reporting. When an HTML file is opened locally from your computer (file://), the browser is designed to function like any other local application. It correctly uses the OS&#39; existing permissions to access network locations that the user can already reach. This behavior doesn&#39;t bypass authentication. Policy like same-origin policy/CORS are not applicable here, as they govern interactions between web origins, not access between local resources. I am closing this bug as WAI.
