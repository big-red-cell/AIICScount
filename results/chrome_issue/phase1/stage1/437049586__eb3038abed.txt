<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>I have developed an iOS Shortcut that operates in the background to periodically take screenshots of the device screen. It uses optical character recognition (OCR) to analyze these screenshots for the presence of the word “password”, which commonly appears on password manager interfaces such as Google Chrome’s built-in password manager on iOS.</p>
<p>When the Shortcut detects the word “password” in a screenshot, it extracts the surrounding text data (including usernames, email addresses, and passwords if visible) and automatically sends this extracted information via iMessage to a specified recipient.</p>
<p>Notably, Google Chrome attempts to protect sensitive password data by briefly flashing the screen white immediately after the screenshot is taken. This flash seems intended as a visual mitigation against screenshot capturing. However, this visual flash occurs too late, meaning the screenshot already contains all the sensitive information before the flash starts.</p>
<p>As a result, this implementation by Chrome fails to prevent the capture of password data via screenshots, making the sensitive data vulnerable to extraction by automated tools such as my Shortcut. This exposes a significant security flaw in the way Chrome’s password manager handles screenshot protections on iOS.
