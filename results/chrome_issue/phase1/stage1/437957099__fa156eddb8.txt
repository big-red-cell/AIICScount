VULNERABILITY DETAILS<br>A vulnerability exists in Chrome’s local data protection that allows a local attacker to:<br><br>Retrieve all saved website credentials in plaintext.<br><br>Access and delete the full browsing history.<br><br>Both actions can be performed without requiring main administrator access or explicit user authentication.<br><br>By running a Python script that reads and manipulates Chrome’s local profile data, an attacker can exfiltrate sensitive credentials and remove key forensic evidence (history records) from the target system. This bypasses expected protections and can be used to cover tracks after data theft.<br><br>Impact:<br><br>Full compromise of saved website credentials.<br><br>Stealth removal of browsing history, erasing activity logs.<br><br>No admin rights or OS-level authentication required.<br><br>Exploitable by any local standard user account with access to the Chrome profile directory.<br><br>VERSION<br>Chrome Version: 139.0.7258.66 (Stable)<br>Operating System: Windows 11 Version 24H2 (Build 26100.4770) – Fully updated as of August 12, 2025<br><br>REPRODUCTION CASE<br><br>On a system with Chrome installed and containing saved passwords and browsing history, log in as a standard (non-admin) user.<br><br>Run a Python script that:<br><br>Locates Chrome’s local profile directory (%LOCALAPPDATA%\Google\Chrome\User Data\Default).<br><br>Reads the Login Data SQLite database and retrieves the encryption key from the Local State file.<br><br>Decrypts the password_value field for each saved login entry.<br><br>Accesses the History SQLite database and either reads or deletes all browsing records.<br><br>The script successfully outputs all saved usernames/passwords and can clear history records.<br><br>Observation:<br>No OS authentication prompt or admin privilege request occurs at any point during password retrieval or history deletion.<br><br><br>CREDIT INFORMATION<br>Reporter credit: Sanyam Jain<br><br>
