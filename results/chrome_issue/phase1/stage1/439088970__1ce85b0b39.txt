<h1>Steps to reproduce the problem</h1>
<p><strong>Steps to Reproduce:</strong></p>
<ol>
<li>Open the PoC: <a href="https://hackerbro.net/text-selection-overlap.html" data-b-widget="url" data-b-original-href="https://hackerbro.net/text-selection-overlap.html" data-b-redirected-href="https://www.google.com/url?q=https://hackerbro.net/text-selection-overlap.html&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1BSnkmWzQYKDcYcZZI8rPi">https://hackerbro.net/text-selection-overlap.html</a></li>
<li>Scroll so that selectable text is positioned directly beneath the Address/URL bar.</li>
<li>Tap and hold on the text near the top of the page.</li>
<li>Observe that the text selection menu overlaps the URL bar.</li>
</ol>
<p><strong>Observed Result:</strong></p>
<ul>
<li>The text selection menu overlaps the browser’s Address/URL bar.</li>
</ul>
<p><strong>Expected Result:</strong></p>
<ul>
<li>The text selection menu should be constrained to remain below security-critical browser UI elements, such as the Address/URL bar.</li>
</ul>
<p><strong>Impact:</strong></p>
<ul>
<li>This overlap can be abused to obscure the actual domain name or spoof the browser’s UI, misleading users and increasing the risk of phishing or social engineering attacks.</li>
</ul>

<ul>
<li><a href="https://issues.chromium.org/issues/329476341" data-b-widget="issue-reference" data-b-issue-id="329476341">Chromium Issue 329476341</a></li>

<h1>Problem Description</h1>
<ul>
<li>In <strong>Chrome Version: 139.0.7258.123 on Android</strong>, I found that the native text selection menu can appear <strong>over the browser’s Address/URL bar</strong>. This UI overlap can allow malicious actors to manipulate the user into interacting with the menu instead of the URL bar, increasing the risk of phishing or spoofing attacks.</li>
</ul>
<p><strong>Tested On:</strong></p>
<ul>
<li>Chrome Version: 139.0.7258.123 on Android</li>
</ul>

<p>Thanks for the report. While the selection UI overlaps the URL bar, I don&#39;t think there&#39;s a security issue here because the attacker can&#39;t control the contents of the menu.</p>
<p>Our security FAQ has a section on interesting UI spoofs:
<a href="https://chromium.googlesource.com/chromium/src/+/HEAD/docs/security/faq.md#what-makes-a-ui-spoof-interesting-to-report" data-b-widget="url" data-b-original-href="https://chromium.googlesource.com/chromium/src/+/HEAD/docs/security/faq.md#what-makes-a-ui-spoof-interesting-to-report" data-b-redirected-href="https://www.google.com/url?q=https://chromium.googlesource.com/chromium/src/%2B/HEAD/docs/security/faq.md%23what-makes-a-ui-spoof-interesting-to-report&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1iRurgJ5YL8OrJ3cPTRC0J">https://chromium.googlesource.com/chromium/src/+/HEAD/docs/security/faq.md#what-makes-a-ui-spoof-interesting-to-report</a></p>
<p>This bullet point is especially relevant:</p>
<blockquote>
<p>A spoof that convinces the user they are currently on origin A when in fact they are on origin B</p>
</blockquote>
<p>However, any interaction with the spoof page immediately closes the selection menu, so I don&#39;t see a realistic threat here.</p>
<p>I&#39;m closing this bug as such, but if you could demonstrate control over the text selection menu, we are of course happy to reconsider. Thanks!</p>
