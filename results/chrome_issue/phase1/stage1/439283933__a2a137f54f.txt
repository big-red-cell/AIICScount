<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>Summary:
In Google Chrome DevTools, when inspecting a web application that supports media sending and deletion (e.g., Messenger-like apps), the hover preview of a media element persists even after the element has been deleted in real time.</p>
<p>While the application removes the DOM element correctly and DevTools reflects the removal (element disappears from Elements panel), hovering over the previously inspected media link in DevTools still shows a cached preview thumbnail.</p>
<p>This creates a security/privacy flaw because sensitive media that was unsent or deleted can remain visible to anyone inspecting DevTools, contradicting the real-time deletion guarantees of the application.</p>
<p>Steps to Reproduce:</p>
<p>Open Chrome and log into a web app that supports sending and deleting media (e.g., Messenger-like chat app).</p>
<p>User A sends a media file (image/video) to User B.</p>
<p>In Chrome DevTools (Elements tab), locate the <span>&lt;img&gt;</span> or <span>&lt;video&gt;</span> element corresponding to the received media.</p>
<p>Hover over the src attribute of the element in DevTools — Chrome shows a live preview of the media.</p>
<p>User A deletes/unsends the media.</p>
<p>The element is removed from the DOM and from DevTools in real time.</p>
<p>❌ However, if you hover on the previously inspected element’s reference, the preview is still visible in DevTools, despite the element being removed.</p>
<p>Expected Behavior:
When an element is deleted/unsent in real time and removed from the DOM, Chrome DevTools should also invalidate and remove its hover preview immediately.</p>
<p>Actual Behavior:
Even after the element is gone, Chrome DevTools retains a persistent preview thumbnail, allowing deleted/unsent media to be visible after its intended removal.</p>
<p>Severity:
High (Privacy Impact) — Chrome is exposing cached previews of deleted media, breaking the real-time deletion model.</p>
<h4>Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>Privacy Violation: Deleted/unsent media remains accessible in Chrome DevTools hover previews.</p>
<p>Inconsistent Behavior: DOM removal is reflected, but cached preview persists.</p>
<p>Exploitable Risk: Sensitive media can be revealed post-deletion by anyone inspecting DevTools.</p>
<p>Trust Issue: Applications promise deletion (e.g., “unsend for everyone”), but Chrome caching bypasses this.</p>
