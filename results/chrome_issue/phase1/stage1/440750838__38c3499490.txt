<h2><strong>Technical Analysis</strong></h2>
<ul>
<li>
<p><code>chrome.devtools.inspectedWindow.reload()</code> includes the <code>injectedScript</code> field</p>
</li>
<li>
<p>This script is injected directly into the inspected page&#39;s main frame</p>
</li>
<li>
<p>This behavior allows execution of arbitrary JS on <strong>any domain</strong></p>
</li>
<li>
<p>Even Facebook and Instagram (which have strong CSPs and sandboxing) are vulnerable</p>
</li>
<li>
<p>This happens <strong>without warning</strong>, <strong>without host permissions</strong>, and <strong>without user approval beyond opening DevTools</strong>
This violates <strong>Chrome’s extension security model</strong>, which is based on:</p>
</li>
<li>
<p>Least privilege.</p>
</li>
<li>
<p>Explicit permission requests.</p>
</li>
<li>
<p>Isolation of extension logic from sensitive page content.</p>
</li>
</ul>
<h2><strong>Recommendations:</strong></h2>
<p><strong>Restrict <code>injectedScript</code> in <code>chrome.devtools.inspectedWindow.reload()</code></strong> to:</p>
<ul>
<li>Require declared host permissions.</li>
<li>If extension hasn&#39;t declared <code>&quot;https://*.facebook.com/*&quot;</code> in the manifest, <code>injectedScript</code> should <strong>not run</strong>.</li>
<li>Or block injections to sensitive domains    * E.g., <code>*.google.com</code>, <code>facebook.com</code>, <code>instagram.com</code>, <code>*.gov</code>, <code>banking</code> domains.
<strong>Limit script execution scope</strong>:</li>
<li>For example, allow it only on DevTools-controlled sandboxed environments (not production pages).
<strong>Add user confirmation</strong> or security prompts before injecting scripts.</li>
</ul>

<h1>Problem Description</h1>
<ul>
<li>This report details a <strong>Universal Cross-Site Scripting (UXSS)</strong> vulnerability in Chrome’s <strong>DevTools Extension API</strong>, specifically via <code>chrome.devtools.inspectedWindow.reload()</code>.</li>
</ul>
<p>A malicious DevTools extension can:</p>
<ul>
<li>Automatically execute arbitrary JavaScript in any inspected tab</li>
<li>Bypass Content Security Policy (CSP)</li>
<li>Run privileged scripts on secure domains like <strong>Facebook</strong>, <strong>Instagram</strong>, <strong>Gmail</strong>, etc.</li>
<li>Leak sensitive data (<code>document.cookie</code>, DOM data, CSRF tokens)</li>
<li>Do this without declaring host permissions in the manifest.</li>
</ul>
<h2><strong>Impact:</strong></h2>
<ul>
<li><strong>UXSS on any site</strong> (e.g., <code>https://www.facebook.com</code>, <code>https://www.instagram.com</code>)</li>
<li><strong>Bypasses CSP, Same-Origin Policy</strong></li>
<li>Does <strong>not require host permissions</strong></li>
<li><strong>No user interaction required</strong> beyond opening DevTools</li>
<li><strong>Triggers automatically</strong> as soon as DevTools is opened on a tab</li>
</ul>
<ul>
<li>This behavior allows malicious extensions to act as privileged agents within any webpage, violating core browser isolation guarantees.</li>
</ul>
