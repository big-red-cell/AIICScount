<h1>Problem Description</h1>
<p>The AndroidStreamReaderURLLoader class is allocated on the heap using <code>new</code>, but there is no corresponding <code>delete</code> or smart pointer managing its lifecycle. As a result, the memory allocated for the loader is never freed. Running a simple test under AddressSanitizer confirms this: the loader is created and started, but the destructor is never called, and LeakSanitizer reports a memory leak. This could lead to increased memory usage and potential instability when multiple loaders are created on Android, especially in long-running processes or heavy web content scenarios.</p>
<h1>Additional Comments</h1>
<ul>
<li>This leak occurs because <code>AndroidStreamReaderURLLoader</code> is allocated on the heap and never explicitly freed.</li>
<li>Although small, such leaks can accumulate over time, impacting memory usage in long-running processes, especially on Android devices.</li>
<li>The attached POC (<code>test_loader_real.cpp</code>) reproduces the issue with minimal setup using AddressSanitizer.</li>
</ul>
