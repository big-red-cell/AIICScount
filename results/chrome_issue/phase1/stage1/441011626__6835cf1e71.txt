<p>VULNERABILITY DETAILS</p>
<p>The Chrome Password Manager currently displays a prompt to update or save a password after a user resets or creates a new one. However, the &quot;Username&quot; field in the save prompt is left blank, even when the username/email is visibly present in the form or session.</p>
<p>This lack of automatic population may lead to:</p>
<p>Incomplete credential saving (i.e., password saved without username)</p>
<p>Autofill failures in future login attempts</p>
<p>Poor user experience</p>
<p>Potential phishing or account lockout risks due to users unknowingly saving incorrect or missing data</p>
<p>Given the increasing use of AI in autofill, this missing feature introduces a security concern due to credential mismanagement, especially for non-technical users.</p>
<p>The username field should be auto-populated using heuristic or AI-based analysis from the form data or session context.</p>
<p>VERSION</p>
<p>Chrome Version: 116.0.5845.97 (Stable)
Operating System: Windows 11, Version 23H2, Build 22631.3296</p>
<p>REPRODUCTION CASE</p>
<p>Go to any site with a password reset or account sign-up form.</p>
<p>Fill in new credentials (especially password and email/username).</p>
<p>Submit the form.</p>
<p>Observe the Chrome &quot;Update password?&quot; prompt.</p>
<p>Notice that while the password field is pre-filled, the username field remains blank, despite the username/email being present on the page.</p>
<p>Expected behavior: The prompt should auto-detect and suggest a likely username/email from the form.</p>
<p>FOR CRASHES</p>
<p>Not applicable – this is not a crash issue.</p>
