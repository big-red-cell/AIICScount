<h1>Steps to reproduce the problem</h1>
<ol>
<li>
<p>Developer Account Compromise (Most Common)
*How: The attacker phishes the original developer&#39;s credentials (for the Chrome Web Store/Google Developer account). Once they have access, they can push a malicious update to all existing users.
*Why it works:Users have automatic updates enabled, so they silently receive the malicious code. The extension&#39;s high user count and positive reviews remain, giving it a veil of legitimacy.</p>
</li>
<li>
<p>Malicious Purchase of a Legitimate Extension</p>
</li>
</ol>
<ul>
<li>How: A threat actor approaches a developer of a popular extension and offers to buy it for a significant sum of money. The developer, perhaps unaware of the buyer&#39;s intentions, sells it.</li>
<li>The Attacker&#39;s Goal: They now own the developer account and can push any update they want, turning a trusted tool into a spyware or adware platform to monetize the existing user base.</li>
</ul>
<ol start="3">
<li>Supply Chain Attack (Third-Party Code)
*How: The extension itself might be legitimate, but it depends on a third-party library or code for functionality (e.g., an analytics library, a utility module). If <em>that</em> third-party code gets compromised, the extension becomes malicious by association when it fetches the bad code.</li>
</ol>
<ul>
<li>Example:The extension might load a remote script from <code>some-analytics-service[.]com</code>. If that domain is hijacked, the script sent to the extension can be changed to malicious code.</li>
</ul>
<ol start="4">
<li>Unmaintained Extensions &amp; Policy Violations
*How: A developer abandons an extension. Later, a new &quot;maintainer&quot; offers to help. The original developer grants them access, and the new maintainer pushes a malicious update.
*Alternatively:The extension might have always had malicious code that evaded initial store review, or it might have introduced it later in an update that also slipped past the automated checks.</li>
</ol>

<li>Install a Browser: Install a fresh copy of Chrome or Firefox in the VM.</li>
<li>Disable Network (Temporarily): You can disable the VM&#39;s network adapter to be extra safe while building the malicious payload.</li>
</ol>
