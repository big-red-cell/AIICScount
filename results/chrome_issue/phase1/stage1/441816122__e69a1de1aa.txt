<h3><strong>Expected Behaviour:</strong></h3>
<ul>
<li>The popup or CCT opened by the sandboxed iframe should inherit the sandbox flags.</li>
<li>JavaScript execution should be blocked unless <code>allow-scripts</code>  <code> allow modals</code>  or <code>allow-popups-to-escape-sandbox</code> is explicitly set.</li>
</ul>
<h3><strong>Actual Behavior:</strong></h3>
<ul>
<li>The <code>intent://</code> link bypasses the iframe&#39;s sandbox restrictions.</li>
<li>Opens a new browser context (CCT) that runs untrusted JS (alert) with no sandbox.</li>
</ul>
<h3><strong>Recommendation:</strong></h3>
<ul>
<li>Prevent Chrome (including CCT) from launching via <code>intent://</code> when the source is a sandboxed iframe <strong>without</strong> <code>allow-popups-to-escape-sandbox</code>.</li>
</ul>
<h1>Problem Description</h1>
<ul>
<li>A sandboxed iframe (<code>sandbox=&quot;allow-popups&quot;</code>) in Chrome Canary version 141.0.7380.0 on Android can launch a <code>Custom Chrome Tab (CCT)</code> via an <code>intent://</code> URL. This allows JavaScript execution in a context that <strong>should be sandboxed</strong>, effectively bypassing iframe sandbox restrictions.</li>
<li>This constitutes a <strong>sandbox escape</strong> that leads to <strong>arbitrary script execution (XSS-like behavior)</strong> — violating Chrome&#39;s security model for iframe sandboxing.</li>
</ul>
<h3><strong>Affected Platform</strong></h3>
<ul>
<li><strong>Browser</strong>: Chrome Canary</li>
<li><strong>Version</strong>: <code>141.0.7380.0</code></li>
<li><strong>OS</strong>: Android 13</li>
</ul>

<h3><strong>Security Impact:</strong></h3>
<ul>
<li><strong>Sandbox escape → arbitrary JS execution.</strong></li>
<li>Bypasses trusted browser security controls and same origin policy.</li>
<li>Privilege escalation in sandbox or isolated environments.</li>
</ul>
