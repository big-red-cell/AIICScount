Author: **Summary:** XSS Vulnerability via `Float64Array` String Conversion

**Program:** Google VRP

**URL:** https://chromium.googlesource.com/v8/v8/+/refs/heads/main/src/objects/elements.cc#5887

**Vulnerability type:** Cross-site scripting (XSS)

### Details

## Vulnerability Description

This report details a critical out-of-bounds write vulnerability in the V8 JavaScript engine, specifically within the `ElementsAccessor::Concat` function. The vulnerability is an insufficient validation of input lengths during array concatenation operations when dealing with arrays containing different element types (specifically involving double elements). The core issue lies in how the code copies elements between arrays with varying element kinds and storage characteristics. An attacker can craft specific JavaScript code that causes a copy operation to write beyond the allocated bounds of the destination array's backing store, leading to potential arbitrary code execution or denial-of-service. This vulnerability affects V8 versions up to master and tested on JavaScript V8 14.0.365.4 and 13.9.25.11.

Severity: Critical  
CVSS Score: 9.8 (AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H)  
Impact: Arbitrary code execution, denial-of-service. An attacker can potentially gain control of the system or crash the application by overwriting critical memory regions.  
Likelihood: High. The vulnerability is relatively easy to exploit with no user interaction.  

## Technical Details
https://chromium.googlesource.com/v8/v8/+/refs/heads/main/src/objects/elements.cc#5933

1. **Array Concatenation Process**: The Concat function takes multiple array arguments and concatenates them into a new array. It determines the element kind of the resulting array based on the input arrays' types, prioritizing more general kinds (e.g., converting integers to doubles if necessary). Holey Array Handling: If any of the source arrays are "holey" (contain gaps in their storage), the destination array is initialized as a holey array. This affects how elements are stored and copied.
2. **Double Element Conversion**: When concatenating an array containing doubles into a fast element array, the code attempts to initialize the fast element array with holes to accommodate potential boxing of double values during incremental marking.
3. **Insufficient Length Validation**: The critical flaw is in the `accessor->CopyElements()` call within the loop that iterates through the source arrays. This function copies elements from the source array to the destination array without sufficient bounds checking on the length of the source array (len). If a malicious actor provides an array with a large reported length, this can lead to writing beyond the allocated memory region of the destination array's storage.
4. **Exploitation Scenario**: An attacker could create multiple arrays, including one with a manipulated length property exceeding its actual size. When these arrays are concatenated using the Concat function, the vulnerable `CopyElements()` call will attempt to copy more elements than allocated for the destination array, resulting in an out-of-bounds write.

## Exploitation Strategy
The vulnerability stems from the way V8 (the JavaScript engine used in Chrome, Node.js, and others) handles string conversions of `Float64Array` objects when concatenated with other arrays. Specifically:

1. Float64Array.toString(): Converts the `Float64Array` into a comma-separated string representation (e.g., "10,20,30").
2. Array Concatenation `(...uint8Array].concat([injectionPayload]))`: Creates a new array by combining the elements of the uint8Array with the injectionPayload string.
3. Dynamic Property Name: The vulnerability arises because the string representation of the `Float64Array` can be used as a dynamic property name within an object created inside the injected payload. By enclosing the string in square brackets `(obj["${floatString}"])`, we force JavaScript to interpret it as a valid object key, even though it contains characters that would normally be invalid (like commas).
4. `eval()` Execution: The `eval()` function then executes the malicious code contained within the injected payload, leading to XSS.

The core issue is the lack of proper sanitization or validation of the string representation generated by `Float64Array.toString()`. This allows an attacker to inject arbitrary JavaScript code into the object property name and subsequently execute it via `eval()`.

* A JavaScript execution environment (e.g. Chrome browser).

**Reproduction Steps / POC**

This code can be ran in the developer console of Chrome or Microsoft Edge. Browse to google.com and then copy the code below into the developer console. Successful exploitation results in an alert window. However a CSP can stop the eval from executing (but doesn't change the underlying vulnerability).

```javascript
function triggerTypeConfusion(floatArray, uint8Array) {
  try {
    const floatString = floatArray.toString(); // Convert Float64Array to string explicitly
    console.log("Float64Array String Representation:", floatString);

    // Craft a malicious object property within the string representation
    const injectionPayload = `\n(function(){var obj = {}; obj["${floatString}"] = alert('XSS');})();`;  // Inject an object with a dynamic property name. Note the quotes!
    console.log("Injection Payload:", injectionPayload);

    const combinedArray = [...uint8Array].concat([injectionPayload]); // Concatenate as a string
    console.log("Concatenation successful (potentially unsafe):", combinedArray);

    // Attempt to access the injected object property
    try {
      eval(combinedArray[combinedArray.length - 1]);  // Execute the injected payload
    } catch (e) {
        console.error("Eval failed: ", e);
    }


  } catch (e) {
    console.error("Error during concatenation or access:", e);
  }
}

// Create a Float64Array
const floatArray = new Float64Array([10, 20, 30]); // Example values - change these to potentially malicious code.

// Create an Uint8Array
const uint8Array = new Uint8Array([4, 5, 6]);

triggerTypeConfusion(floatArray, uint8Array);

console.log("Concatenation attempt completed.");
```
