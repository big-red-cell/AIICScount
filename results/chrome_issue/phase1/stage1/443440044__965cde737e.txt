<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>Description
While testing the Chrome browser - Windows, I discovered that local files (file://) are able to access and read other files on the user’s system without any explicit permission or configuration. Even though allowFileAccessFromFileUrls is not enabled or modified, the browser permits unrestricted access to local resources via file:// URLs. This leads to Local File Inclusion (LFI) and information disclosure.</p>
<p>Steps to Reproduce:</p>
<ol>
<li>Create a test file (e.g file:///C:/Users/severus/Documents/imp.txt)</li>
<li>Download the malicious.html and replace the local file path.</li>
<li>Open the malicious.html file on the system using the Chrome browser.</li>
<li>Observe that it reads the contents of file:///C:/Users/severus/Documents/imp.txt or other files without any prompts or permissions.</li>
</ol>
<p>Actual Behavior
The browser allows local files to access and read arbitrary files on the filesystem via file:// requests without any user consent, warning, or configuration.
This occurs even when allowFileAccessFromFileUrls is not explicitly set to true.</p>
<p>Expected Behavior
Browser should block local files from reading other files to prevent information leakage.
File access should require explicit permission or should not be allowed at all in user-facing environments.</p>
<h4>Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>Impact
Attackers can exploit this flaw to steal sensitive data like configuration files, private keys, passwords, or other user information stored locally.
This flaw is especially critical in applications that handle sensitive data, such as crypto wallets, secure browsers.
Users are unaware that opening a local file can expose their data without consent or warning.</p>
<p>Real-World Attack Scenario
An attacker tricks a user into downloading and opening a local HTML file (via email, messaging apps, or social engineering). The file silently reads sensitive local files and sends them to the attacker’s server. The victim’s private information, such as credentials or keys, can be stolen without any indication that a security breach is occurring.</p>
