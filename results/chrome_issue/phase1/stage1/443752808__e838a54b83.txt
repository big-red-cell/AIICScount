<h1>Chrome Extension API Vulnerability Report</h1>
<p><strong>Chrome Version:</strong> 139.0.7258.155 (Official Build) (64-bit)<br>
<strong>OS:</strong> Windows 11 Pro, 24H2<br>
<strong>Lacros Version:</strong> <em>(not applicable or not provided)</em><br>
<strong>Severity:</strong> Critical<br>
<strong>Reported by:</strong> Pedro Correia</p>
<hr>
<h2>Executive Summary</h2>
<p>A Chrome extension with <strong>no declared permissions</strong> is able to <strong>inject and execute code within the context of a webpage</strong>, <strong>access the DOM</strong>, and <strong>exfiltrate sensitive data</strong> — all <strong>without user interaction</strong>. This constitutes a <strong>zero-click vulnerability</strong> that violates Chrome&#39;s extension security model and poses a significant risk to user privacy and data integrity.</p>
<hr>
<h2>Expected Behavior</h2>
<p>Extensions that declare <strong>no permissions</strong> in their manifest should <strong>not</strong> be able to:</p>
<ul>
<li>Inject scripts into webpages.</li>
<li>Communicate with the main window.</li>
<li>Access or manipulate the DOM.</li>
<li>Exfiltrate data from the page context.</li>
</ul>
<hr>
<h2>Actual Behavior</h2>
<p>Despite declaring no permissions, the extension:</p>
<ul>
<li>Automatically triggers a chain of execution when the popup opens.</li>
<li>Injects code into the webpage and gains access to the DOM.</li>
<li>Reads sensitive data from the page and sends it back to the popup.</li>
<li>Exfiltrates the data by embedding it in the query parameters of an image URL, which is then sent to an attacker-controlled server.</li>
</ul>
<p>This entire process occurs <strong>without any user interaction</strong>.</p>
<hr>
<h2>Steps to Reproduce</h2>
<ol>
<li>Unzip the provided <code>.zip</code> file (contains the vulnerable extension).</li>
<li>Load the unpacked extension in Chrome via <code>chrome://extensions</code>.</li>
<li>Open any webpage (target page).</li>
<li>Trigger the extension popup (or let it open automatically).</li>
<li>Observe:
<ul>
<li>Code injection into the webpage.</li>
<li>DOM access and data extraction.</li>
<li>Creation of an image element with sensitive data in the URL.</li>
</ul>
</li>
</ol>
<hr>
<h2>Technical Summary</h2>
<ul>
<li><strong>Trigger:</strong> Automatic popup execution.</li>
<li><strong>Vector:</strong> Popup script injects code into the main page.</li>
<li><strong>Payload:</strong> Extracted data is sent via image URL query parameters.</li>
<li><strong>Permissions:</strong> None declared in <code>manifest.json</code>.</li>
<li><strong>Exploit Type:</strong> Zero-click, DOM access, data exfiltration.</li>
</ul>
<hr>
<h2>Impact Assessment</h2>
<ul>
<li><strong>Privacy Violation:</strong> Sensitive user data can be silently stolen.</li>
<li><strong>Security Breach:</strong> Bypasses Chrome’s extension permission model.</li>
<li><strong>Zero-Click Exploit:</strong> No user interaction required.</li>
<li><strong>Potential Abuse:</strong> Could be used for phishing, session hijacking, or surveillance.</li>
</ul>
<hr>
<h2>Recommendations</h2>
<ul>
<li>Review and patch the extension API to prevent popup-based DOM access without permissions.</li>
<li>Enforce stricter isolation between extension popups and webpage contexts.</li>
<li>Audit other extensions for similar abuse patterns.</li>
<li>Improve documentation and developer guidance on popup behavior and security boundaries.</li>
<li>Prevent contentScripts with manifest &quot;world&quot;: &quot;main&quot; from communicating indirectly with the extension.</li>
</ul>
<hr>
<h2>Additional Notes</h2>
<p><strong>Note:</strong> Chrome is not responsible for bugs or behavior of individual extensions. However, this vulnerability highlights a <strong>systemic issue</strong> in how popup execution flows can be abused even without declared permissions.</p>
