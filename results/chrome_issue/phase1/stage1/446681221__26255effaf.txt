<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>The vulnerability allows reading plaintext input values (including password inputs!) directly from memory at address <strong>7FF85CAC6890</strong> in the <em>chrome.exe</em> process.
The address is used by <em>textinputframework.dll</em>.</p>
<p>These values reside in memory temporarily while being typed and are not encrypted or obfuscated, allowing any process running under the same user context to access them in real-time.</p>
<p>Ideally, password inputs(from a form inside a website) should be encrypted or masked in memory instead of appearing in plaintext.</p>
<h4>Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>This vulnerability allows reading password-type input values from web forms in the browser directly from RAM. What distinguishes it from other local attacks described in the bug hunters FAQ (e.g., hooking, DLL injection, modifying the browser) is that:</p>
<ul>
<li>
<p>A malicious program exploiting this vulnerability <strong>does not require administrator privileges</strong> and is not detected by antivirus software as malicious.</p>
</li>
<li>
<p>It does <strong>not read stored passwords</strong>. it only captures values as they are typed in <strong>real-time</strong>.</p>
</li>
<li>
<p>Other browsers, such as Firefox, mask the password inputs in memory, preventing this type of attack.</p>
</li>
</ul>
