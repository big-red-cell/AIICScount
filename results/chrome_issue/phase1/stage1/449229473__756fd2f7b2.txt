# Problem Description

## bug threat model

Note: this vuln requires a compromised renderer.
https://chromium.googlesource.com/chromium/src/+/main/docs/security/compromised-renderers.md

Specifically, 
```
// third_party/blink/renderer/platform/widget/compositing/android_webview/synchronous_layer_tree_frame_sink.cc
  frame_sink_manager_ = std::make_unique<viz::FrameSinkManagerImpl>(
      viz::FrameSinkManagerImpl::InitParams());
```
blink provide a `frame_sink_manager_` that is under attacker's control (with a compromised renderer).

Ideally I should patch the code there, but I dont have a android debugging device, so 
I use unittest to simulate. Specifically, the attacker with a compromised renderer 
can construct the call in the unittest and trigger a container oob in gpu process. 
So its a renderer->gpu sandbox escape.

## bug RCA
