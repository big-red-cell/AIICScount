<h2>VULNERABILITY DETAILS</h2>
<p>A heap buffer overflow vulnerability exists in Chromium&#39;s Blink rendering engine during HTML serialization of DOM elements containing malformed UTF-8 sequences.</p>
<p>When serializing 513 or more DOM elements with attributes containing specific invalid UTF-8 byte patterns (0xF5, 0xF9, 0xEB, 0xFE), an integer overflow occurs in the string buffer size calculation within <code>blink::Vector&lt;char16_t&gt;::ReallocateBuffer()</code>. This results in undersized heap allocation followed by out-of-bounds memory writes, triggering security assertions (int3/ud2 instructions) and process termination.</p>
<h3>Technical Analysis</h3>
<p>When <code>innerHTML</code> is accessed on a DOM tree containing 513+ elements with attributes holding invalid UTF-8 data (0xF5, 0xF9 bytes), the <code>MarkupFormatter::AppendAttributeValue()</code> function miscalculates the required buffer size for UTF-16 conversion. The accumulated size overflows, causing <code>Vector&lt;char16_t&gt;::ReallocateBuffer()</code> to allocate insufficient memory. Subsequent append operations write beyond buffer bounds, corrupting heap metadata.</p>
<h3>Security Impact</h3>
<ul>
<li><strong>Heap Corruption:</strong> Controlled overflow in UTF-16 string buffer</li>
<li><strong>Proximity to Executable Memory:</strong> V8 JIT region adjacent to corrupted heap</li>
<li><strong>Exploitability:</strong> Attacker controls invalid UTF-8 byte sequences and element count</li>
<li><strong>Crash Consistency:</strong> 100% reproducible with exact conditions</li>
</ul>
<h3>Exploitation Scenario</h3>
<p>A malicious webpage can craft DOM elements with carefully chosen invalid UTF-8 sequences to trigger integer overflow in string buffer allocation. While the current PoC demonstrates a crash (caught by security checks), sophisticated exploitation could potentially bypass checks or leverage the memory corruption before detection.</p>
