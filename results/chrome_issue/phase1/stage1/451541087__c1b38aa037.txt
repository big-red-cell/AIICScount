<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p><strong>summary</strong>
When a webpage opens an existing window/tab using the same window.open(url, &#39;x&#39;) target name and the new URL triggers a download (e.g. an .apk file), Chrome on Android displays the download UI (download prompt/overlay) visually on top of the previously opened site (the reused tab). This makes it appear as if the previously opened site (for example <a href="https://google.com" data-b-widget="url" data-b-original-href="https://google.com" data-b-redirected-href="https://www.google.com/url?q=https://google.com&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0VT8wnjtPCJ_ZzcGf2doE0">https://google.com</a>) is the source of the download, which may confuse users or be abused for spoofing/phishing.</p>
<h4>Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<ol>
<li>Who can exploit it: Any web attacker who can control a web page (malicious site, compromised legitimate page, or an attacker able to inject script into a page) and host or link to a downloadable resource (e.g., an APK). Exploit requires only the ability to open windows/tabs via JavaScript (window.open) and to serve a downloadable payload; no special privileges or user gestures beyond a normal click are needed in the tested reproduction.</li>
<li>What they gain: The attacker can make a download prompt appear visually over a different, trusted-looking page (for example, google.com) that is still visible in the reused tab. This creates an opportunity for UI spoofing / social-engineering attacks: users may mistakenly believe the visible trusted site is the source of the download, increasing the likelihood they accept or run the downloaded file.</li>
<li>Impact on users and service trust: Leads to user confusion, elevated risk of malware installation, and erosion of user trust in browser UI provenance signals. While the vulnerability does not bypass platform-level install prompts or permissions, it materially increases the effectiveness of phishing campaigns and could facilitate distribution of malicious payloads.</li>
</ol>
