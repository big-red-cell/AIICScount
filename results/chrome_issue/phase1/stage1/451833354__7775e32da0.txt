<h1>Problem Description</h1>
<p>This vulnerability occurs when file downloads are triggered through reuse window.open(name) so that downloads run without permission dialogs and the download UI does not display the origin of the file source. This condition can mislead users because it appears as if the download comes from a trusted site that was opened previously, when in fact the file is taken from a different origin. The download window/dialog should display the correct origin of the file (or request confirmation) so that users can evaluate the trustworthiness of the file.</p>
<p>For the context of related issue classes, you can refer to <a href="https://crbug.com/40055527" target="_blank">crbug.com/40055527</a> (Android). Unlike that report, which falsifies the origin in the dialog, this case on macOS desktop does not display a dialog and removes the origin attribution from the download UI.</p>
