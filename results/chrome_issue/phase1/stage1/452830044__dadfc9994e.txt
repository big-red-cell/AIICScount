<h2>VULNERABILITY DETAILS</h2>
<ul>
<li>A heap-buffer-overflow occurs inside <code>rx::PackPixels()</code> when calling <code>glReadPixels()</code> with a read area larger than the framebuffer.
The issue arises because the buffer provided by the user is smaller than the internally computed copy size, and ANGLE continues to copy based on the unclipped width and outputPitch, causing a write past the end of the destination buffer.</li>
</ul>

<h2>Vulnerability Analysis</h2>
<p><code>glReadPixels()</code> should:</p>
<ul>
<li>Respect the clipped framebuffer region (256×256 in this case), Or validate that the destination buffer is large enough for the requested region and produce a GL_INVALID_OPERATION error instead of writing out of bounds.</li>
</ul>
<p>Root Cause Analysis</p>
<ol>
<li>glReadPixels(-150, -150, 1024, 1024) requests a region partially outside a 256×256 framebuffer.</li>
<li>ANGLE correctly clips the source read region to (0,0,256,256) but does not adjust the outputPitch or offset calculations.</li>
<li><a href="#b452830044-c1-https://source.chromium.org/chromium/chromium/src/+/main:third_party/angle/src/libANGLE/renderer/renderer_utils.cpp;drc=cede29f31bd9922c8ee621658ba59f8e1c299245;l=514">PackPixels()</a> then computes:</li>
</ol>
<pre><code>    uint8_t *destWithOffset = destWithoutOffset + params.offset;
    ...
    memcpy(destWithOffset + y * params.outputPitch, source + y * inputPitch,
           params.area.width * sourceFormat.pixelBytes);
</code></pre>
<p>where:</p>
<ul>
<li>params.offset ≈ 615000 bytes</li>
<li>params.outputPitch = 4096</li>
<li>destination buffer = 1,048,576 bytes (1 MB)</li>
</ul>
<ol start="4">
<li>The final memcpy writes beyond pixels + 1,048,576 → Heap Buffer Overflow.</li>
</ol>
<ul>
<li>By changing (x, y) or (width, height) in glReadPixels, the attacker can shift outputSkipBytes by predictable multiples of pixelBytes or outputPitch.</li>
<li>The resulting write location (e.g., +400 bytes, +600 bytes past buffer) is therefore partially controllable.</li>
</ul>
