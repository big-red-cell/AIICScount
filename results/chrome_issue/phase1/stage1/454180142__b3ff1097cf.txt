<h1>Problem Description</h1>
<p>When installing a Progressive Web App (PWA) or website shortcut through Chrome’s <strong>Add to Home screen</strong> feature, Chrome allows domains with extremely long subdomain names to be installed as standalone applications.</p>
<p>During the installation flow, the <strong>Install app</strong> prompt correctly displays the full domain name, including the top-level domain (e.g., <code>.badssl.com</code>).</p>
<p>However, after the installation is complete, Chrome displays <strong>Download PWA</strong> and <strong>Install PWA</strong> notifications where the domain is <strong>truncated</strong> to a shortened version such as:</p>
<p>long-extended-subdomain-name-containing-...</p>
<p>The actual domain suffix (e.g., <code>.com</code>, <code>.net</code>, <code>.org</code>) is no longer visible, which hides the true origin of the installed app.</p>
<p>This behavior could allow a malicious actor to exploit Chrome’s display truncation by registering a long subdomain designed to mimic a trusted brand or service.</p>
<p>For example:</p>
<p>long-extended-subdomain-name-looking-like-google-...</p>
<p>This can mislead users into believing the app is an official Google application or update.</p>
<p>Because PWAs installed from Chrome can run in <strong>standalone mode</strong> without an address bar, users cannot easily verify the real origin once opened. Combined with the misleading truncated domain, this creates a <strong>UI spoofing / phishing risk</strong>.</p>
<h1>Summary</h1>
<p>Long subdomain name in installed PWA gets truncated, hiding real domain (URL spoofing)</p>
