Author: # Steps to reproduce the problem
## Steps to reproduce
1. Open Google Chrome with Google Lens enabled.  
2. Scan a QR code containing a URL with a long subdomain or userinfo trick (`https://gmail.com@evil.com`) or else.  
3. Observe the URL displayed in Lens preview. The truncation hides the real domain.  
4. The user sees both the truncated URL and the QR code, which reinforces the false trust.

# Problem Description
Google Chrome’s **Google Lens feature** in the browser dashboard allows real-time QR code scanning. When a QR code contains a **long subdomain** or a URL with a misleading format (e.g., `https://mail.google.com@evil.com`), the displayed URL in the Lens preview **truncates the subdomain or main domain**, misleading the user about the true origin.

**Examples:**

1. QR code URL:  

https://long-extended-subdomain-name-containing-many-letters-and-dashes.badssl.com/

Lens preview displays:  

https://long-extended.....

The QR code itself is shown along with the truncated URL, which **gives the user a false impression** that the code originates from the legitimate `badssl.com` subdomain.  

2. QR code URL (malicious-looking):  

https://mail.google.com@evil.com

Lens preview displays:  
https://mail.google.....

## Impact
- Users may **trust the displayed URL**, believing it originates from a legitimate domain.  
- This enables **origin UI spoofing**, making phishing attacks or social engineering more convincing.  

## Expected behavior
The full **registrable domain** (eTLD+1) should be displayed clearly in Lens preview to prevent spoofing.  

## Observed behavior
Lens preview truncates long subdomains or misleading userinfo parts, displaying a partial URL that **misrepresents the origin**, convincing the user of legitimacy.

## Conclusion
This is a **security-relevant UI/Origin spoofing bug**. The truncation plus QR code display can mislead users into trusting malicious URLs, fitting Chrome’s scope for UI spoofing reports.
