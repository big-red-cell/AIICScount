<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>This report discloses a novel origin confusion and permission bypass vulnerability in Chromium&#39;s DownloadRequestLimiter::TabDownloadState class. By exploiting a shared callback queue for pending download requests, a malicious page can trigger a single multi-download prompt for its origin (e.g., attacker.com:8787) while queuing unauthorized downloads from a different origin (e.g., victim.com:8001) via an iframe. User approval of the attacker&#39;s prompt inadvertently authorizes all queued downloads, bypassing per-origin consent. This enables deceptive phishing or malware delivery, posing significant risks to user trust and security.</p>
<p>The issue is reproducible in the latest Chromium builds (as of October 24, 2025) across all platforms. A complete proof-of-concept (PoC) is included, using local servers to simulate the attack. No matching CVE or bug report was found on bugs.chromium.org or public vulnerability databases, suggesting novelty. This report is submitted for responsible disclosure under the Chromium Vulnerability Rewards Program.</p>
<p>#he DownloadRequestLimiter::TabDownloadState class in chrome/browser/download/download_request_limiter.h manages download requests exceeding Chrome&#39;s multi-download threshold by queuing them in a single std::vector<a href="javascript:void(0);" data-b-widget="url" data-b-original-href="about:invalid#zCSafez" data-b-redirected-href="about:invalid#zCSafez">DownloadRequestLimiter::Callback</a> callbacks_ (line 210). When a malicious page (e.g., localhost:8787) initiates multiple downloads to trigger a permission prompt, a simultaneous download from a different origin (e.g., localhost:8001 via iframe) is added to the same queue. The Accept method (line 146 in download_request_limiter.cc) sets a content setting only for the triggering origin but calls NotifyCallbacks(true) (line 176), approving all queued callbacks regardless of origin.</p>
<p>This design flaw allows cross-origin downloads to proceed without user consent for their specific origins, violating Chrome&#39;s same-origin security model for downloads.</p>
<p>Affected Code Locations</p>
<p>Header: chrome/browser/download/download_request_limiter.h</p>
<p>TabDownloadState class, specifically std::vector<span>&lt;Callback&gt;</span> callbacks_ (line 210).</p>
<p>Implementation: chrome/browser/download/download_request_limiter.cc</p>
<p>Accept method (line ~146): Sets CONTENT_SETTING_ALLOW for the triggering origin.</p>
<p>NotifyCallbacks (line ~176): Broadcasts approval to all callbacks without origin validation.</p>

<h4>Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<p>Impact</p>
<p>Primary Impact</p>
<p>Origin Confusion/Permission Bypass: User approval for one origin (localhost:8787) authorizes downloads from another (localhost:8001) without consent, undermining Chrome&#39;s per-origin permission model.</p>
<p>Phishing and Malware Delivery: Attackers can deliver malicious files (e.g., disguised executables) appearing to originate from trusted domains, increasing phishing success rates.</p>
<p>Attack Scenarios</p>
<p>Phishing Campaigns: A malicious site (attacker.com) triggers a prompt for benign files while an iframe from a typosquatted domain (e.g., paypa1.com) downloads a trojan. Users open the file, trusting its apparent origin.</p>
<p>Enterprise Policy Bypass: In managed environments, attackers bypass per-origin download restrictions by queuing blocked origins during an allowed prompt.</p>
<p>Chained Exploits:</p>
<p>XSS: On a trusted site, inject code to queue sensitive file downloads (e.g., user data exports) during the attacker&#39;s prompt.</p>
<p>Clickjacking: Overlay the prompt to force approval, automating the attack.</p>
<p>Ad Networks: Malicious ads in iframes exploit high-traffic sites for mass payload delivery.</p>
<p>Data Exfiltration: Queue downloads of user-generated files (e.g., financial reports) from legitimate origins without additional prompts.</p>
<p>Scope and Severity</p>
<p>Attack Complexity: Low (JavaScript on two origins; no authentication required).</p>
<p>User Interaction: Required (prompt approval), but deceptive (single prompt masks multi-origin downloads).</p>
<p>Mitigations: Safe Browsing and user action to open files limit execution risk, but not download or privacy risks.</p>
<p>Affected Users: All Chrome users (desktop/mobile); high exploitability in phishing campaigns.</p>
