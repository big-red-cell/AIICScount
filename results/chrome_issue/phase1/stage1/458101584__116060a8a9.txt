<h1>Steps to reproduce the problem</h1>
<ol>
<li>Open Google Chrome on Android.</li>
<li>Highlight/select any text on a webpage (example-markdown.txt).</li>
<li>Observe the “Tap to Search” / bottom preview panel appear automatically.</li>
<li>Compare the same behavior on Firefox — the feature is not present.</li>
</ol>
<h1>Problem Description</h1>
<p>When selecting text in Chrome on Android, Chrome automatically triggers the &quot;Tap to Search&quot; feature, showing a bottom information panel and partially overlaying the page. This behavior is unique to Chrome and not available in Firefox, leading to different user experience and potential confusion for users expecting consistent behavior across browsers. The feature may also distract or interrupt the normal reading flow.</p>
<p><strong>Actual behavior:</strong><br>
When Tap-to-Search displays very long domains, Chrome truncates the string from the right. This causes the <em>real</em> registrable domain (eTLD+1) to be hidden, while the visible part may misleadingly show a well-known brand substring at the front.</p>
<p><strong>Expected behavior:</strong><br>
The UI should always prioritize showing the registrable domain (eTLD+1). Truncation should keep the end of the domain (e.g., <code>...attacker-example.com</code>) so users can correctly identify the true origin.</p>
