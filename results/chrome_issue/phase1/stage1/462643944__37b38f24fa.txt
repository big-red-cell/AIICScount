<h1>Steps to reproduce the problem</h1>
<ol>
<li>Host an HTML page locally</li>
<li>Open this page in Chrome Beta Incognito</li>
<li>Click the button labeled: &quot;HERE&quot; and new tab</li>
<li>The page opens <a href="https://accounts.google.com/" data-b-widget="url" data-b-original-href="https://accounts.google.com/" data-b-redirected-href="https://www.google.com/url?q=https://accounts.google.com/&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2h5GDb7vJzQL1ZuySGCdEO">https://accounts.google.com/</a> in a new tab</li>
<li>Switch to the newly opened Google Account tab</li>
<li>Observe: A Save File dialog suddenly appears — while user is in the Google tab, not localhost tab</li>
</ol>
<h1>Problem Description</h1>
<p>A webpage opened on localhost can trigger a file download, but the resulting Save File dialog appears on a different tab, specifically on a trusted domain tab (e.g., accounts.google.com).
This causes users to believe that the file originates from the trusted site, rather than the malicious site.
This leads to severe UI deception, enabling malware delivery using a browser-level trust illusion</p>
<h1>Summary</h1>
<p>Forced download appears on Google tab due to trigger from another tab (cross-tab download spoofing)</p>
