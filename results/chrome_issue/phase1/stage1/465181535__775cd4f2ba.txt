<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<h2>Summary</h2>
<p>A memory safety vulnerability was discovered in Chromium&#39;s Mojo IPC stack (<code>mojo/core/ipcz_driver</code>). During fuzzing, an <strong>invalid memory read (segmentation fault)</strong> was triggered by passing a forged <code>IpczDriverHandle</code> to the <code>Transport::DeserializeObject()</code> function. This leads to <strong>Crash via invalid memory read due to unchecked handle deserialization</strong>, and could potentially be exploited by a compromised renderer to <strong>escape the sandbox or crash the browser</strong>.</p>
<hr>
<h2>Affected Component</h2>
<ul>
<li><strong>Product:</strong> Chromium</li>
<li><strong>Component:</strong> Mojo IPC / Ipcz Driver</li>
<li><strong>Files:</strong>
<ul>
<li><code>mojo/core/ipcz_driver/transport.cc</code></li>
<li><code>mojo/core/ipcz_driver/object.h</code></li>
</ul>
</li>
</ul>
<hr>
<h2>Vulnerability Details</h2>
<ul>
<li><strong>Type:</strong> Invalid memory read / use of attacker-controlled handle</li>
<li><strong>Severity:</strong> High (potential sandbox escape / arbitrary read)</li>
<li><strong>Root Cause:</strong> No validation is performed on the deserialized handles.</li>
<li><strong>Faulting Instruction:</strong><pre><code><span class="stx-keyword">return</span> object-&gt;type();  <span class="stx-comment">// object is from a fake handle</span>
</code></pre>
</li>
</ul>
<hr>
<h3>Root Cause</h3>
<p>The function <code>Transport::DeserializeObject()</code> accepts serialized byte data and a span of <code>IpczDriverHandle</code>s. These handles are directly interpreted via <code>Object&lt;T&gt;::TakeFromHandle()</code>:</p>
<pre><code><span class="stx-class">scoped_refptr</span>&lt;<span class="stx-class">ObjectBase</span>&gt; <span>object</span>;
transport-&gt;DeserializeObject(base::span(data, size), base::span(handles), object);
</code></pre>
<p>When a forged handle like <code>0xdeadbeef</code> is passed, it results in the following call chain:</p>
<pre><code>Object::TakeFromHandle()
  → FromHandle()
    → reinterpret_cast&lt;ObjectBase*&gt;(handle)-&gt;type() ← 🔥 Crash here
</code></pre>
<p>Because the handle is not verified or sanitized, the code dereferences a bogus pointer, resulting in a segmentation fault on <code>0xdeadbeef</code>.</p>

<h2>Confirmed Findings</h2>
<h3>1. <strong>Sensitive Deserialization Logic in <code>Transport::DeserializeObject()</code></strong></h3>
<p>We identified the function:</p>
<pre><code><span class="stx-class">IpczResult</span> <span class="stx-qualifier">Transport</span>::DeserializeObject(
    <span class="stx-qualifier">base</span>::<span class="stx-class">span</span>&lt;<span class="stx-keyword">const</span> <span class="stx-class">uint8_t</span>&gt; <span>bytes</span>,
    <span class="stx-qualifier">base</span>::<span class="stx-class">span</span>&lt;<span class="stx-keyword">const</span> <span class="stx-class">IpczDriverHandle</span>&gt; <span>handles</span>,
    <span class="stx-class">scoped_refptr</span>&lt;<span class="stx-class">ObjectBase</span>&gt;* out)
</code></pre>
<ul>
<li>
<p>Located in <code>mojo/core/ipcz_driver/transport.cc</code></p>
</li>
<li>
<p>Called from <code>ipcz_driver::Deserialize()</code> and <code>MojoReadMessageIpcz()</code></p>
</li>
<li>
<p>Accepts <strong>arbitrary data + handles</strong> from Mojo messages and deserializes them into IPC objects like:</p>
<ul>
<li><code>SharedBuffer</code></li>
<li><code>WrappedPlatformHandle</code></li>
<li><code>DataPipe</code></li>
<li><code>Transport</code></li>
</ul>
</li>
</ul>
<p>This makes it <strong>critical attack surface</strong> if untrusted renderers can trigger it.</p>
<hr>
<h3>2. <strong>Renderer-Exposed Mojo Interface Accepts <code>handle&lt;platform&gt;</code></strong></h3>
<p>We identified this method in <code>userspace_swap.mojom</code>:</p>
<pre><code>TransferUserfaultFD(uint64 uffd_error, handle&lt;platform&gt; uffd_handle);
</code></pre>
<ul>
<li>Defined in:
<code>chromeos/ash/components/memory/userspace_swap/userspace_swap.mojom</code></li>
<li>Called from the <strong>renderer process</strong></li>
<li>Accepts a <code>handle&lt;platform&gt;</code> (platform file descriptor, Mach port, etc.)</li>
<li>This is <strong>highly dangerous</strong>, as it can allow renderer-controlled injection of OS handles into the browser.</li>
</ul>
<p>This means there is a <strong>reachable path from the renderer → Mojo → browser → DeserializeObject()</strong>.</p>
<hr>
<h3>3. <strong>Deserialization Chain is Reachable from Mojo IPC</strong></h3>
<p>We confirmed that:</p>
<ul>
<li><code>MojoReadMessage()</code> calls → <code>MojoReadMessageIpcz()</code></li>
<li>→ which calls <code>Deserialize()</code> in <code>ipcz_driver.cc</code></li>
<li>→ which calls <code>Transport::DeserializeObject(...)</code></li>
</ul>
<p>Thus, <strong>any Mojo-exposed interface that passes untrusted handles</strong> could result in deserialization of attacker-controlled data and memory.</p>

<ul>
<li><code>SharedBuffer::Deserialize(...)</code></li>
<li><code>TransmissiblePlatformHandle::Deserialize(...)</code></li>
<li><code>WrappedPlatformHandle::Deserialize(...)</code></li>

<p>Hi team,</p>
<p>Thank you for the previous clarifications. In response, I&#39;ve traced the full path of a <code>handle&lt;platform&gt;</code> passed via Mojo IPC from <code>.mojom</code> declaration to driver-level deserialization.</p>
<p>The key points are:</p>
<ol>
<li>
<p><strong>Mojo IPC serializes <code>handle&lt;platform&gt;</code> separately</strong> from the message body — it&#39;s passed as an out-of-band <code>IpczDriverHandle[]</code> array.</p>
</li>
<li>
<p><strong>The driver layer (e.g., <code>DeserializeObject()</code>) receives these handles with no deep validation</strong>, trusting the memory layout and type mapping.</p>
</li>
<li>
<p><strong>In <code>WrappedPlatformHandle::Deserialize()</code></strong>, the handle is blindly interpreted and dereferenced.</p>
</li>
</ol>
<p>This confirms that if an attacker can influence this out-of-band handle array (through a renderer compromise or fuzzing path), they could induce memory corruption or trigger unsafe object behavior.</p>
<h3>1. <strong>Mojom Definition</strong></h3>
<p>A <code>handle&lt;platform&gt;</code> declared in <code>.mojom</code> files indicates the IPC message may carry a raw OS handle (e.g., FD on Linux/macOS or HANDLE on Windows).</p>
<pre><code>chromeos/ash/components/memory/userspace_swap/userspace_swap.mojom:
  TransferUserfaultFD(uint64 uffd_error, handle&lt;platform&gt; uffd_handle,
</code></pre>
<hr>
<h3>2. <strong>Code Generation Layer</strong></h3>
<p>When <code>mojom</code> files are compiled, Mojo generates C++ code (in <code>gen/</code>) to handle message serialization and deserialization.
In particular:</p>
<ul>
<li>The handle is converted into a <code>MojoHandle</code> via <code>mojo::internal::Serialize&lt;mojom::WrappedPlatformHandle&gt;(input, buffer, context)</code>.</li>
<li>Platform handles use <code>MojoPlatformHandle</code> for cross-platform support.</li>
</ul>
<p>inspect <code>gen/chromeos/ash/components/memory/userspace_swap/userspace_swap.mojom.cc</code> to find:</p>
<pre><code><span class="stx-qualifier">mojo</span>::<span class="stx-qualifier">internal</span>::Serialize&lt;<span class="stx-qualifier">mojo</span>::<span class="stx-class">PlatformHandle</span>&gt;(
    in.handle, buffer, &amp;result-&gt;handle, context);
</code></pre>
<hr>
<h3>3. <strong>Handle Packing</strong></h3>
<p>In <code>mojo/public/cpp/bindings/lib/serialization.h</code> and <code>.../handle_serialization.h</code>:</p>
<ul>
<li><code>SerializePlatformHandle</code> wraps the OS handle into a Mojo handle.</li>
<li>It uses the <code>NodeController</code> to allocate a driver handle.</li>
</ul>
<hr>
<h3>4. <strong>Transfer Over IPC (Ipcz)</strong></h3>
<h4>➤ <code>core_ipcz.cc</code>:</h4>
<p>Contains:</p>
<pre><code><span class="stx-class">IpczDriverHandle</span> handles[] = { <span class="stx-keyword">reinterpret_cast</span>&lt;<span class="stx-class">IpczDriverHandle</span>&gt;(<span class="stx-number">0x12345678</span>) };
MojoWriteMessage(pipe_handle, <span class="stx-keyword">nullptr</span>, <span class="stx-number">0</span>, handles, <span class="stx-number">1</span>, MOJO_WRITE_MESSAGE_FLAG_NONE);
</code></pre>
<h4>➤ <code>transport.cc</code>:</h4>
<pre><code>transport-&gt;DeserializeObject(data, handles, object)
</code></pre>
<p>Calls object-specific deserialization like:</p>
<pre><code><span class="stx-qualifier">WrappedPlatformHandle</span>::Deserialize(<span class="stx-class">data</span>, <span class="stx-class">handles</span>)
</code></pre>
<hr>
<h3>5. <strong>Driver Assignment</strong></h3>
<p>In <code>wrapped_platform_handle.cc</code>:</p>
<pre><code><span class="stx-class">scoped_refptr</span>&lt;<span class="stx-class">WrappedPlatformHandle</span>&gt; <span class="stx-qualifier">WrappedPlatformHandle</span>::<span>Deserialize</span>(<span class="stx-qualifier">base</span>::<span class="stx-class">span</span>&lt;<span class="stx-keyword">const</span> <span class="stx-class">uint8_t</span>&gt; <span>data</span>, <span class="stx-qualifier">base</span>::<span class="stx-class">span</span>&lt;<span class="stx-keyword">const</span> <span class="stx-class">IpczDriverHandle</span>&gt; <span>handles</span>) {
  <span class="stx-keyword">if</span> (<span>handles</span>.empty()) <span class="stx-keyword">return</span> <span class="stx-keyword">nullptr</span>;
  <span class="stx-keyword">return</span> <span class="stx-qualifier">base</span>::MakeRefCounted&lt;<span class="stx-class">WrappedPlatformHandle</span>&gt;(<span class="stx-qualifier">PlatformHandle</span>::FromMojoHandle(<span>handles</span>[<span class="stx-number">0</span>]));
}
</code></pre>
<p>This wraps and takes ownership of the <code>IpczDriverHandle</code>.</p>
<p><strong>This is where the raw <code>handle&lt;platform&gt;</code> becomes a driver object.</strong></p>
<hr>
<h3>6. <strong>Validation (or Lack Thereof)</strong></h3>
<ul>
<li><code>DeserializeObject()</code> in <code>transport.cc</code> accepts <code>base::span&lt;IpczDriverHandle&gt;</code>.</li>
<li>These are <strong>not byte-streamed</strong>, but <strong>passed as a separate array</strong> (Mojo message + handles).</li>
<li>There is <strong>no integrity check that each handle refers to a valid type or source</strong>.</li>
</ul>
<p>My injection of <code>0xdeadbeef</code> worked because:</p>
<ul>
<li>The driver trusted the index into <code>handles[]</code>.</li>
<li>No deep validation (like type checking or mapping bounds check) occurred before dereferencing.</li>
</ul>
<hr>
<h2>Security Implication</h2>
<blockquote>
<p><code>IpczDriverHandle</code> is <strong>not a typed pointer</strong>. It&#39;s a number (e.g., index or raw pointer).</p>
<p>The driver <strong>does not validate</strong> the content unless extra logic is added by the object-specific deserializer (e.g., <code>WrappedPlatformHandle::Deserialize</code>).</p>
</blockquote>
<hr>
<h3>My Request</h3>
<p>Could you confirm whether this serialization behavior and lack of validation is considered safe, given that:</p>
<ul>
<li><code>IpczDriverHandle</code> may be user-controlled under certain sandboxed conditions (e.g., renderer).</li>
