<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>Component: V8 / Array Builtins / Interpreter
Status: Reproducible
Version: 143.0.7499.110
Javascript: V8 14.3.127.16</p>
<p>A specifically crafted JavaScript code pattern triggers an unexpected behavior in Array.prototype.slice(), where the method returns a single value (either a float or an object) instead of returning a valid JSArray.
This occurs regardless of the input contents—whether the source array contains floats ([3.3, 3.3, 3.3]), objects ([{}, {}, {}]), or mixed elements.</p>
<p>This abnormal behavior indicates that the crafted code sequence corrupts the internal state of the array. Returning a single primitive value from Array.prototype.slice() is never valid under any execution condition.</p>
<p>This strongly suggests an underlying internal error such as:</p>
<p>internal Map corruption</p>
<p>ElementsKind transition collapse</p>
<p>incorrect builtin selection or dispatch</p>
<p>corrupted array allocation or initialization path</p>
<p>invalid interpreter state transitions triggered by the crafted code</p>
<p>Because the incorrect return type directly violates the JavaScript specification and affects a core builtin, this behavior strongly suggests an underlying type confusion or memory corruption primitive.
Such primitives are frequently chainable with JIT-based exploitation, OOB write primitives, or arbitrary object fabrication</p>
<p>This is the root-cause payload:</p>
<p>let obj = {a:1};
(()=&gt;{
a = new Array(10000).fill(obj)
b = a.slice(0,10000)
[setTimeout(()=&gt;{a = {}; })]
console.log(b)   //Expected: is an array of objects.
// Actual : single object !
})();</p>
