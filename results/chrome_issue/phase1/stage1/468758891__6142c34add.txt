<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<h3>Hi Team,</h3>
<ul>
<li>A tapjacking vulnerability allows a malicious website to obtain sensitive permissions (Location, Camera, Microphone) from a victim using continuous triple taps on the same screen location.</li>
</ul>
<h3>Reproduction Steps:</h3>
<ol>
<li>Victim visits a malicious webpage <a href="https://attacker.hackerbro.net/Tapjack.html" data-b-widget="url" data-b-original-href="https://attacker.hackerbro.net/Tapjack.html" data-b-redirected-href="https://www.google.com/url?q=https://attacker.hackerbro.net/Tapjack.html&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1LOjKRJhL8HMQQ1l8XarWT">https://attacker.hackerbro.net/Tapjack.html</a>.</li>
<li>The page instructs the user to tap three times on the same visible button.</li>
<li>Due to overlapping permission prompts, Chrome grants security permissions without clear user intent.</li>
<li>Attacker gains access to sensitive device features.</li>
</ol>
<h4>Impact analysis</h4>
<ul>
<li>Unauthorized access to Location, Camera, or Microphone</li>
<li>User consent can be bypassed through UI manipulation</li>
</ul>
<h3>Recommended Fix:</h3>
<ul>
<li>The final permission prompt should <strong>not appear at the same screen position</strong> as previous UI elements.</li>
<li>Place the final permission dialog <strong>above or below the page content</strong>, ensuring repeated taps at the same location cannot automatically approve permissions.</li>
</ul>
