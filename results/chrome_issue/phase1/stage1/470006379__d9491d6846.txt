<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<h2>Hi Team,</h2>
<ul>
<li>
<p>A sandboxed, cross-origin iframe using <code>allow-top-navigation-by-user-activation</code> can perform <strong>top-level navigation without a direct user click</strong>, by reusing a previously granted user activation and triggering navigation on a <strong>mouse hover event</strong>.</p>
</li>
<li>
<p>This behavior allows an attacker-controlled iframe (e.g., malicious ads) to <strong>escape the sandbox</strong> and redirect the top-level page, violating iframe isolation guarantees.</p>
</li>
</ul>
<h2>Product &amp; Version:</h2>
<ul>
<li><strong>Browser:</strong> Google Chrome</li>
<li><strong>Version:</strong> 143.0.7499.147</li>
<li><strong>OS:</strong> macOS Tahoe 26.2</li>
</ul>

<h3>3. Exploitation</h3>
<ol>
<li>Victim clicks once inside the iframe (grants user activation).</li>
<li>Victim moves mouse (hover) over iframe content.</li>
<li><strong>Top-level navigation occurs</strong>.</li>
<li>The sandboxed iframe escapes and redirects the main page.</li>
</ol>
<h2>Expected Behavior:</h2>
<ul>
<li>Only a <strong>direct user-initiated click</strong> should allow top-level navigation.</li>
<li>Hover events should <strong>not</strong> reuse user activation.</li>
<li>Sandbox isolation should remain enforced.</li>
</ul>
<h2>Actual Behavior:</h2>
<ul>
<li>User activation persists beyond the click.</li>
<li>Hover event triggers top-level navigation.</li>
<li>Sandbox restriction is bypassed.</li>
</ul>
<h4>Impact analysis</h4>
<ul>
<li>Malicious advertisements can redirect the publisher’s page.</li>
<li>Sandbox isolation is bypassed.</li>
<li>Enables javscript execution, phishing, forced navigation, and ad fraud, malvertising.</li>
<li>Violates expected browser security model for sandboxed iframes.</li>
</ul>

<p>I would like to add additional information that this issue cannot be reproduced in the Safari browser. Although the mouse click event did not trigger top-level navigation, the mouse hover did. This indicates that user activation events such as <code>onclick</code> are blocked in the Chrome browser. However, the same approach fails when using <code>onhover</code>. But, hover is not considered a user activation because it does not represent an explicit user intent.</p>

This would only be a bug if it was reproducible after the 5 seconds have passed (which I have not been able to do here).
