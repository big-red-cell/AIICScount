<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>A webpage can enter fullscreen mode via a user interaction using the Fullscreen API, which removes the browser’s address bar and tabs. While in fullscreen, the page can render UI elements using only HTML/CSS that visually resemble Chrome permission dialogs (e.g., “Allow notifications”, “Block / Allow” buttons) and Chrome-like top bars.</p>
<p>Because these elements are purely webpage-rendered and Chrome does not present a sufficiently clear, unavoidable indicator distinguishing them from genuine browser UI, an average user may believe the prompt originates from Chrome rather than the webpage itself. No extensions, real permissions, or privileged APIs are used.</p>
<h4>Impact analysis</h4>
<p>This behavior enables user deception by allowing malicious websites to impersonate trusted Chrome UI. Users may be misled into interacting with fake permission dialogs or security messages, which can facilitate phishing, social engineering, or malware distribution.</p>
<p>The issue impacts user trust in browser-generated security indicators. Even without a traditional exploit, deceptive fullscreen UI can cause users to take unsafe actions under the false assumption that Chrome is requesting or enforcing them.</p>
