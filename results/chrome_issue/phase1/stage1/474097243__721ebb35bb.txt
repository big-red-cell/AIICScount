<h1>Problem Description</h1>
<p>Chromium Android download UI displays only the <code>eTLD+1</code> (registrable domain) rather than the full hostname, which can mislead users about the true origin of downloaded content and enable download origin spoofing via deceptive subdomains.</p>
<p>Chromium Android displays only the registrable domain (<code>eTLD+1</code>) in the download confirmation dialog instead of the full hostname from which the page is downloaded.</p>
<p>For example:
A page downloaded from
<code>thisexampledomainforbugbountycaseanddontuseforanysecurity.syarif07.my.id</code>
is shown as originating from <code>syarif07.my.id</code>.</p>
<p>A page downloaded from
<code>attacker.www.github.io</code>
is shown as originating from <code>www.github.io</code>.</p>
<p>This behavior appears to be caused by Chromium’s use of Public Suffix List (PSL)–based site attribution when rendering download UI, resulting in loss of subdomain-level context. While the internal security origin remains correct, the user-facing UI does not reflect the actual host serving the content.</p>
<p>As a result, attacker-controlled subdomains under trusted public suffixes may appear indistinguishable from legitimate sites in the download dialog.</p>
