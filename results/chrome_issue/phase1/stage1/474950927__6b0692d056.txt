<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<p>Summary
When a Picture-in-Picture (PiP) window is triggered from a video inside a cross-origin iframe, the browser incorrectly displays the parent page’s origin instead of the iframe’s actual origin. This results in misleading origin attribution and enables trusted-UI spoofing.</p>
<p>Steps to Reproduce</p>
<ol>
<li>Open the POC URL: <a href="https://barathstalin6.github.io/summa/domainspf.html" data-b-widget="url" data-b-original-href="https://barathstalin6.github.io/summa/domainspf.html" data-b-redirected-href="https://www.google.com/url?q=https://barathstalin6.github.io/summa/domainspf.html&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw0E2j1rPC76hhArPoy-9ojg">https://barathstalin6.github.io/summa/domainspf.html</a></li>
<li>Click the Picture-in-Picture button from the iframe</li>
<li>Observe the origin displayed in the PiP window.</li>
<li>Notice it shows barathstalin6.github.io but actully the origin of the file is <a href="https://bughunter-6.github.io" data-b-widget="url" data-b-original-href="https://bughunter-6.github.io" data-b-redirected-href="https://www.google.com/url?q=https://bughunter-6.github.io&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw2vj1SltXPfZ9XYW0ZoNZW-">https://bughunter-6.github.io</a></li>
</ol>
<p>Expected Behavior
The PiP window should always display the actual origin of the media content (iframe origin), not the embedding page’s origin.</p>
<p>Actual Behavior
The PiP UI displays the parent page’s origin, hiding the true iframe origin and misleading the user.</p>
<h4>Impact analysis</h4>
<p>An attacker can embed a malicious iframe on a benign or trusted site and serve deceptive video content. When PiP mode is enabled, the window shows the trusted parent domain instead of the attacker-controlled iframe origin. Since PiP is a persistent and trusted UI surface, users may believe the content originates from a legitimate site, enabling phishing, misinformation, or social-engineering attacks.</p>

Author: ct...@chromium.org
<p>Thank you. This appears to be using Video PIP, which I have a hard time seeing how this could be abused by an attacker. In the scenario laid out in your report, the user is on that top level origin and clicks a button and a video is shown in PIP -- from the user&#39;s mental model, that PIP <em>belongs</em> to that top-level origin tab. Popping back in the video PIP should and does return the user to that origin, so the origin attribution seems correct to me. In general, we don&#39;t think that users have any conception of iframe origins, and avoid surfacing them to users as much as possible (see also the motivation for permission delegation / permissions policy).</p>
