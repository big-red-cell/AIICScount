Steps to reproduce the problem
Edit src of iframe in poc.html with an unavailable file path in your computer.
Open poc.html in chrome (visit with file:///path/to/poc.html), open console, refresh and watch the output.
You will see when the src is unavailable, the embedding time is relatively fixed, now record that value (name it "time-no").
Change the src of iframe to an available file path.
Do 2. again and record the time naming "time-yes".
You will definitely notice that "time-no" is quite different from "time-yes", thus the attacker can know whether a file is present on victim's computer.

Problem Description
I recently noticed a vul that can map a victim's hard drive -> https://issues.chromium.org/issues/41492103 And I am thinking another way to get the same effect. I found no matter if the src of iframe is available, the onload event will be triggered. This makes the embedding time harmful. In my poc.html, I'm just giving a poc, attacker can change the code to calculate the time more accurately.

Summary
Security: iframe's load time reveals if a file exists
