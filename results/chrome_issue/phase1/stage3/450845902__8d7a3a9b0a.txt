<h1>Steps to reproduce the problem</h1>
<ol>
<li>Host or open the PoC page (example): <code>https://attacker.hackerbro.net/crossoriginsizeleak.html</code> (or open the attached HTML file locally / on a testing host you control).</li>
<li>On the PoC page enter the target origin URL (for example <code>https://academy.hackerbro.net</code>) into the input field.</li>
<li>Click <strong>Check</strong>. The page will perform a <code>HEAD</code> (no‑cors) cache put, measure <code>navigator.storage.estimate()</code>, then perform a <code>GET</code> (no‑cors) cache put and measure again.</li>
<li>The PoC computes the difference between the two cache usage readings and reports the approximate size difference for the targeted resource.</li>
<li>Repeat with other target origins as needed.</li>
</ol>
<p><strong>Example observed outputs (from testing):</strong></p>
<ul>
<li><code>Resource on https://academy.hackerbro.net has a size difference of 6,641,293 bytes or less.</code></li>
<li><code>Resource on https://auth.tesla.com has a size difference of 4,683,879 bytes or less.</code></li>
</ul>
<h1>Problem Description</h1>
<ul>
<li>A CacheStorage padding side‑channel allows a same‑origin attacker page to infer the size of opaque cross‑origin responses (coarse resolution) by comparing storage usage after caching the resource via different HTTP methods on Chrome 141.0.7390.77 (macOS Tahoe 26.0.1).</li>
</ul>
<p><strong>Impact:</strong></p>
<ul>
<li>An attacker can deduce approximate sizes of cross‑origin resources (e.g., body length) leading to fingerprinting or leakage of information about dynamic resources (auth payloads, uploaded assets). No direct content exfiltration, but sensitive metadata can be inferred.</li>
</ul>
