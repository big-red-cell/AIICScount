# Issue 375594906__cc64ce1591

**Bucket:** POTENTIAL

## Summary
The issue claims that uploading a directory on mrnoob790.github.io/os can disclose a username-bearing path through `webkitRelativePath` after the keyboard trigger.

## Environment
- OS/runtime: Linux Ubuntu (headless environment)
- Browser: Google Chrome 150.0.7871.124
- Automation path: Headless Chrome with remote debugging
- Required environment: Interactive file picker access (not available in headless mode)
- Attachments used: none

## Environment gap

The issue requires interactive Google Chrome on Windows and a user-driven
directory picker. This run used Ubuntu Linux with headless Chrome, so the
required Windows file-picker path was unavailable.

## Attack chain

1. Open the supplied page in desktop Chrome on Windows.
2. Trigger its keyboard handler and choose a directory through the file picker.
3. Read the displayed `webkitRelativePath` value and check whether it contains
   the username-bearing directory component.

The local run could not perform step 2 because no interactive Windows file picker
was available.

## Notes
The Chromium discussion and current browser behavior are not used as an
obsolescence decision; the required platform and interaction were unavailable.
