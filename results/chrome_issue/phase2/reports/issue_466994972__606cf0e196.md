# Issue 466994972__606cf0e196

**Bucket:** POTENTIAL

## Summary
Chrome displays downloads from Google redirect URLs as originating from "https://google.com" in the download UI, even when the actual file comes from a different domain, potentially enabling user deception through source spoofing.

## Environment
- OS: Linux (Ubuntu)
- Browser: Google Chrome 150.0.7871.124
- Automation path: Headless Chrome with CDP access
- Required environment: Chrome browser with GUI access to chrome://downloads page
- Attachments used: none

## Reproduction

### Environment gap
The reproduction requires verification of Chrome's download UI behavior in chrome://downloads, which displays the download source as "From: https://www.google.com" when initiated from a Google redirect page. However, the current environment runs Chrome in headless mode without GUI access, making it impossible to observe or verify the chrome://downloads page behavior described in the issue.

### Attack chain
1. Navigate to https://www.google.com/url?q=https://dist.torproject.org/tor-0.4.8.21.tar.gz — Chrome loads redirect notice page
2. Click on the link to https://dist.torproject.org/tor-0.4.8.21.tar.gz — Download is initiated
3. Open chrome://downloads — UI should display "From: https://www.google.com" instead of actual source
4. User is deceived into believing the file comes from Google rather than torproject.org

### PoC scaffold
Verified that:
- The Google redirect page loads correctly and contains the expected link to the target file
- The target file (tor-0.4.8.21.tar.gz) can be successfully downloaded from dist.torproject.org
- File size matches expected (10,663,112 bytes)

However, cannot verify the critical UI behavior in chrome://downloads due to headless environment limitations.

## Notes
The Chromium developer response indicates this behavior is "working as intended" - Chrome displays the origin of the page that initiated the download (Google redirect page) rather than the actual network origin that delivers the file. This confirms the behavior exists but is considered by design. Full reproduction would require a GUI-enabled Chrome instance to observe the chrome://downloads page behavior.
