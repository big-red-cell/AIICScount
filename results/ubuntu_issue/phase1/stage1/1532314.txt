Message 53 | Author: serge-hallyn | Subject: Re: Buffer overflow in cgmanager
Here is a patch for libnih to switch from select() to epoll() in its mainloop.  The motivation for this would be for it to not crash with >1024 fds.

With cgmanager with this patch, i can fire off 1100 clients who sleep after the dbus connect (which should result in > 3k fds), with no problems.

The patch to nih/tests/libtest_io.c is curious in two parts - I had to remove the TEST_ALLOC_FAIL.  What it does is run its block many times (8?) to test allocation failures.  Oddly, a tmpfile is created, then at the top of the block it is written to, then rewound, then checked for contents and eof.  On the second run, it is not rewound before again writing to the file.  This is resulting in "This is a test\nThis is a test\n...".  I don't understand how this works in the original code (but note that it does!), and don't understand how I'm breaking it.

Since any unprivileged user can easily fire off N clients which sleep, causing daemons linked to libnih-io to crash (in the assert of nfds < 1024), this seems like a crucial fix to trivial unprivileged DOS.  The DOS for cgmanager is local, but for other daemons presumably is remote.
