Bug #1979562: CVE-2022-21449 - Psychic signatures in Java

URL: https://bugs.launchpad.net/ubuntu/+source/openjdk-16/+bug/1979562

Metadata: security_related=true; information_type=Public Security; tags=["amd64", "apport-bug", "jammy", "jammy-security", "patch", "third-party-packages"]; targets=openjdk-16 (Ubuntu) (Won't Fix, High), openjdk-18 (Ubuntu) (Fix Released, High)

Description:
It was discovered OpenJDK did not properly check ECDSA signatures. JDK could generate a bad key with 0's and sign it anyways. The result would be JDK allowing for a bad invalid key/certificate anyways.

[Impact]

 * OpenJDK was found to accept invalid ECDSA signatures.

 * This could allow for attackers to bypass security/certificate
   checks

[Test Plan]

 * Here is a good PoC - https://github.com/khalednassar/CVE-2022-21449-TLS-PoC
 - this modifies some of the golang crypto libraries to make it work

 * After cloning the repo and installing dependencies, run ./build.sh

 * Run the go-server-test binary

 * Run the vulnclient jar file

 * Use curl to fetch www.google.com

 * In /etc/hosts, add 127.0.0.1 www.google.com

 * Rerun the vulnclient.jar - it will show the invalid signature

 * Trying to curl www.google.com will fail with a bad signature error

[Where problems could occur]

 * The patch itself is mostly harmless (except for potential integer issues with BigInteger if there were to be any) but a lot of what happens can be seen around the vulnerable server client and its library

 * Updates in other parts of OpenJDK, like the signum() and bitLength() functions can break the patch

 * To get a good PoC, very specific steps need to be followed. In this PoC, if Go files or whatever files the host server may be running is edited or changed this can cause an issue (say a change in the crypto library may cause an issue)

 * TLS updates may cause problems

[Other Info]

 * This has been dubbed "Psychic signatures" - https://neilmadden.blog/2022/04/19/psychic-signatures-in-java/
 * I do not plan to patch Impish as it is EOL in a few weeks
 * This bug impacts  OpenJDK 15 and later.
