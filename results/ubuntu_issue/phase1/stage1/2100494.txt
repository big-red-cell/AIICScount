Bug #2100494: Misuse of /tmp could result in root privilege escalation

URL: https://bugs.launchpad.net/ubuntu/+source/add-nvidia-repositories/+bug/2100494

Metadata: security_related=true; information_type=Public Security; tags=["regression-proposed"]; targets=cloud-images (New, Undecided), add-nvidia-repositories (Ubuntu) (Won't Fix, Undecided)

Description:
From https://bugs.launchpad.net/ubuntu/+source/add-nvidia-repositories/+bug/2089830/comments/5:

>  wget "$keyring_url" -O /tmp/cuda-keyring.deb
>  dpkg -i /tmp/cuda-keyring.deb
>  rm /tmp/cuda-keyring.deb
>
> That's a classic predictable-name-in-tmp security issue.

I think there's kernel protection in Ubuntu that stops a user from writing to a file in /tmp even if it has 666 permissions, so that might stop this being exploitable in practice. However, it's still unacceptable from a security perspective, and we must not rely on such kernel protections.

Discovery credit: Andreas Hasenack
