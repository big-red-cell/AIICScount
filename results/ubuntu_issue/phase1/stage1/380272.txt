Description:
When mounting CIFS share you can read all mount options from /etc/mtab. This is major security risk if you are using shared network resources. Here is example of mine cifs mount information:

//192.168.1.10/Te****t /home/<username>/Mount/Te****t cifs rw,username=<username>,password=<password>,iocharset=utf8,file_mode=0777,dir_mode=0777,uid=1000 0 0

I found this on Ubuntu 8.10 server and 9.10 desktop edition.

Could this one fix it :

Message 1 | Author: vladislav-kurz | Subject: mount -t cifs exposes password in /etc/mtab
Package: mount
Version: 2.12-10
Severity: important

When mounting a cifs share using command like this:

mount -t cifs -o username=user,password=pass //server/share /mnt/share

mount writes all the options, including password into /etc/mtab!
This file is readable to everyone and so are the passwords. Any user can
write "mount" or "cat /etc/mtab" to get them.

Passwords are not shown in /proc/mounts.

Also I have found out that this happens only if /sbin/mount.cifs
(from package smbfs) is not available. I wonder why it works this way.
I would expect one of these behaviors:

1. mount -t cifs should fail if /sbin/mount.cifs doesn't exist
2. mount -t cifs should do the job correctly without /sbin/mount.cifs
(thus rendering mount.cifs obsolete)

However current sitution is that users without mount.cifs (smbfs)
installed are exposing their passwords in /etc/mtab, while those who
installed smbfs are safe.

Message 3 | Author: ttx | Subject: Re: /etb/mtab shows cifs mount options usernames and password
Note that this is only if /sbin/mount.cifs isn't present (smbfs not installed).

For root CIFS mounts, mount.cifs helper is called when present, otherwise only "mount" and kernel magic is used to mount the filesystem... and they don't know about sensitive options  to scrub.
