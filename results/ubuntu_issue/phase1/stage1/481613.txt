Bug #481613: grub2 - cat - security - it becomes too easy without pwd-protected grub-shell

URL: https://bugs.launchpad.net/ubuntu/+source/grub2/+bug/481613

Metadata: security_related=true; information_type=Public Security; targets=grub2 (Ubuntu) (Won't Fix, Wishlist)

Description:
Using grub without a password-protected grub-shell was and is always a major security risk if you can't trust the people sitting in front of such a box.

But with grub2 it will become a major headache. Up to now people must have had at least some minor knowledge about the kernel-command-line to change it e.g. to init=/bin/bash to do some unwanted things.

With grub2, it just gets much more easier, just use cat. This is described in the help, and it even offers tab-completion!

So just anyone who can start a grub-shell can type cat /etc/shadow, or use it to display almost every other file he might not have the rights to see, after the OS is booted.

I haven't looked at how the password is stored in grub2, but in grub1 it was stored in plain in menu.lst (which is by default world-readable). A NoNo if there is a plain password stored inside which offers root-access.

My sugestion is to do 4 things:

- disable access to the grub-shell through enforcing a password (maybe through using a password stored in shadow)
- make grub.cfg readable only by root
- encrypt the password in grub.cfg
- describe the problems with grub-shell LOUD AND CLEAR on every admin and security-page of every handbook, faq and such.

I'm sure many people are assuming that when they disable booting from USB or such, they have secured their systems (at least to some level) against people sitting in front of the hardware, which just is not true.

Message 5 | Author: holler | Subject: Re: grub2 - cat - security - it becomes too easy without pwd-protected grub-shell
Sure, but as I've written above there is subtle difference between adding init=/bin/bash to the menu entry and the cat command. The cat command is so easy to use (and with online-help), that even a person without any linux-knowledge (e.g. childs) won't have a problem to find and use it.

That means it is much more dangerous not to use a password to protect a linux-box with grub2 than it was with legacy grub.

And I've seen e.g. tons of messages where it is explained how to enable the grub-menu (in ubuntu 9.10), all were without any remark that this should be done only in conjunction with enabling a password for grub.

So there is imho clearly a requirement to warn users about that (preferable at least in the grub-documentation from where it will spread to other documentations), otherwise it doesn't needs long until classrooms or such are equiped with dangerous grub2-installations.
