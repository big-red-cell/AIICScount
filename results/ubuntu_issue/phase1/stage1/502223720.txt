<h3>The problem</h3>
<h4>Please describe the technical details of the vulnerability</h4>
<h2>Summary</h2>
<p>An attacker-controlled page can present a normal name/email form while adding invisible but focusable address fields hidden with <code>opacity:0</code>. When the user selects an address Autofill suggestion on the visible field, Chrome also fills the hidden fields, and page JavaScript can read the values immediately.</p>
<h2>Reproduction</h2>
<p>Attached files:</p>
<ul>
<li><code>index.html</code></li>
<li><code>poc.py</code></li>
<li><code>chrome-firefox-comparison.mp4</code></li>
</ul>
<p>Steps:</p>
<ol>
<li>Run <code>python3 poc.py</code></li>
<li>Open <code>http://127.0.0.1:8080/index.html</code></li>
<li>Click <code>Full name</code> in the <code>opacity:0</code> panel</li>
<li>Choose an address Autofill suggestion</li>
</ol>
<h2>Observed result</h2>
<ul>
<li>The <code>opacity:0</code> panel captures Autofill values in hidden <code>street-address</code>, <code>postal-code</code>, and <code>tel</code> inputs.</li>
<li>The <code>display:none</code> control remains empty.</li>
<li>The values are readable from page script through normal DOM events.</li>
<li>For comparison, Firefox did not autofill either hidden-field variant in the same PoC; both result tables remained empty.</li>
</ul>
<h2>Expected result</h2>
<p>Inputs that are not human-visible should not be eligible for Autofill, even if they remain focusable.</p>
<h2>Root cause</h2>
<p><code>IsWebElementVisible()</code> in <a href="https://chromium.googlesource.com/chromium/src.git/+/refs/heads/main/components/autofill/content/renderer/form_autofill_util.cc" data-b-widget="url" data-b-original-href="https://chromium.googlesource.com/chromium/src.git/+/refs/heads/main/components/autofill/content/renderer/form_autofill_util.cc" data-b-redirected-href="https://www.google.com/url?q=https://chromium.googlesource.com/chromium/src.git/%2B/refs/heads/main/components/autofill/content/renderer/form_autofill_util.cc&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3frTtvqUSnwx2ZevEQOS5M">https://chromium.googlesource.com/chromium/src.git/+/refs/heads/main/components/autofill/content/renderer/form_autofill_util.cc</a> uses focusability plus a minimum-size heuristic as its visibility signal.</p>
<p>The same weak signal is still used when deciding whether a field may be filled:</p>
<ul>
<li><code>ShouldSkipFillField()</code> in <a href="https://chromium.googlesource.com/chromium/src.git/+/refs/heads/main/components/autofill/content/renderer/form_autofill_util.cc" data-b-widget="url" data-b-original-href="https://chromium.googlesource.com/chromium/src.git/+/refs/heads/main/components/autofill/content/renderer/form_autofill_util.cc" data-b-redirected-href="https://www.google.com/url?q=https://chromium.googlesource.com/chromium/src.git/%2B/refs/heads/main/components/autofill/content/renderer/form_autofill_util.cc&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw3frTtvqUSnwx2ZevEQOS5M">https://chromium.googlesource.com/chromium/src.git/+/refs/heads/main/components/autofill/content/renderer/form_autofill_util.cc</a></li>
<li><code>FormFiller::GetFillingSkipReasonsForField()</code> in <a href="https://chromium.googlesource.com/chromium/src.git/+/refs/heads/main/components/autofill/core/browser/filling/form_filler.cc" data-b-widget="url" data-b-original-href="https://chromium.googlesource.com/chromium/src.git/+/refs/heads/main/components/autofill/core/browser/filling/form_filler.cc" data-b-redirected-href="https://www.google.com/url?q=https://chromium.googlesource.com/chromium/src.git/%2B/refs/heads/main/components/autofill/core/browser/filling/form_filler.cc&amp;sa=D&amp;source=buganizer&amp;usg=AOvVaw1pgzO2IbkqSqohbkOHhNPw">https://chromium.googlesource.com/chromium/src.git/+/refs/heads/main/components/autofill/core/browser/filling/form_filler.cc</a></li>
</ul>
<p>Both paths reject unfocusable fields, but they do not require human-visible presence. As a result, invisible address fields remain eligible for Autofill when a visible address-triggering field is used.</p>
<h2>Suggested fix</h2>
<p>Use an Autofill-specific visibility predicate for both parsing and fill-time gating, and treat <code>opacity:0</code>, zero-area clipping, and clearly offscreen fields as non-fillable.</p>

<p>When a user chooses to share their address information with a site, Chrome will indeed provide address details to that site. That is true whether the user can see the fields or not -- immediately upon filling, the information would be available to the website.</p>
<p>As discussed in the duplicate issue <a href="https://issues.chromium.org/issues/490430923" data-b-widget="issue-reference" data-b-issue-id="490430923">490430923</a>, the attempts to not fill fields that are hidden by some of the mentioned CSS hiding techniques could be described as best-effort at best, and is not a hard security boundary.</p>
<p>Additionally, there are valid use cases across the web where fields are styled with opacity: 0 and blocking autofill on them would break legitimate website functionality.</p>
