Author: # Steps to reproduce the problem
1. Save the attached file lookalike_userinfo_poc.html. 
2. Serve it locally, for example: python3 -m http.server 8000 
3. Open http://127.0.0.1:8000/lookalike_userinfo_poc.html in Chrome. 
4. Click "Control: dot-separated lookalike". 
5. Observe that Chrome shows a lookalike URL warning for: https://google.com.abcdefj.evil.com/ 
6. Go back to the PoC page. 
7. Click "Bypass: userinfo". 
8. Observe that Chrome navigates directly to: https://google.com@abcdefj.evil.com/. The actual host is abcdefj.evil.com, and the same lookalike warning is not shown. 

# Problem Description
Chrome's lookalike URL warning is meant to stop users from visiting malicious sites that look like a trusted domain. The warning correctly appears for the control URL https://google.com.abcdefj.evil.com/.

However, placing the trusted-looking domain before "@" bypasses this protection. For https://google.com@abcdefj.evil.com/, no warning is shown, even though the URL still begins with "google.com". Here "google.com" is only userinfo and the real host is abcdefj.evil.com.

Because Chrome does not apply lookalike detection to the userinfo portion, an attacker can prepend a trusted domain via "@" to make a malicious link look legitimate while evading the warning, defeating the purpose of the lookalike protection.
