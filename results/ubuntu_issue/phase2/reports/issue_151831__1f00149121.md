# Issue 151831__1f00149121

**Bucket:** POTENTIAL

## Summary
The issue describes a vulnerability where a compromised user account can modify `.bashrc` to alias `sudo` to a malicious script that captures passwords. The core mechanism is verified to work as described, but full interactive testing requires a graphical desktop session which is unavailable in the current environment.

## Environment
- OS/runtime: Ubuntu 26.04 LTS (resolute)
- Automation path: terminal fallback (no active graphical session - DISPLAY and WAYLAND_DISPLAY empty)
- Prerequisites: bash shell, sudo command available at /usr/bin/sudo

## Reproduction
1. Verified that .bashrc is user-writable and sudo is available at /usr/bin/sudo
   - cmd: `ls -la ~/.bashrc && which sudo`
   - verify: File permissions show `-rw-r--r-- 1 znh znh` and `which sudo` returns `/usr/bin/sudo`

2. Demonstrated that malicious aliases can be defined in .bashrc
   - cmd: Created test .bashrc with sudo alias and sourced it
   - verify: `alias sudo='echo "FAKE SUDO..."'` was successfully defined when sourced

3. Verified that absolute path bypasses aliases as security mitigation
   - cmd: `bash -c "source malicious_bashrc; type /usr/bin/sudo"`
   - verify: Returns `/usr/bin/sudo is /usr/bin/sudo` showing absolute path is not affected by alias

4. Confirmed that aliasing absolute paths fails as described
   - cmd: `bash -c "alias /usr/bin/sudo='echo gotcha'"`
   - verify: Returns `bash: line 1: alias: '/usr/bin/sudo': invalid alias name` with exit code 1

## Notes
The vulnerability logic is coherent and the core mechanism works as described. However, full reproduction would require an interactive desktop session to demonstrate the complete attack flow (user typing 'sudo', being prompted by fake sudo, entering password, etc.). Without a graphical session, we can only verify the underlying alias mechanism. The issue remains POTENTIAL because the prerequisite (interactive desktop session) is unavailable, but the security-relevant effect is verified to be technically feasible.
